## 總評

正文的技術內容沒有發現錯誤。抽查的關鍵主張——工具往返與 `stop_reason`、hub-and-spoke 編排、Pre／Post hook 的時序限制、MCP user scope 存於 `~/.claude.json`、batch 的 24 小時窗口與 50% 折扣、required 與 nullable 的差異——與現行官方文件一致，且書中已用大量限定語把「考綱記載」「產品現況」「本書設計」分開，這是這本書最強的地方，不要在後續修改中稀釋。

**缺口全部集中在同一條軸線上：這本書教「考什麼」教得很完整，但幾乎不教「怎麼考」。** 讀者照著四週計畫讀完、做完 Lab、寫完 18 題之後，仍然不知道自己有沒有資格報名、要去哪個平臺排程、考不過要等多久、證書多久過期。對一位在臺灣、多半不在 Claude Partner Network 內的讀者而言，資格問題是最先該知道、卻被放在最後的事。

## 發現與行動（按優先序）

### P1-1｜資格門檻缺席，讀者可能讀完才發現無法報名

- **位置：** `README.md` 結尾段、`00-exam-map.md`「確認你準備的是哪個考試」表。
- **證據：** 書中僅寫「報名、費用與政策仍以官方認證入口為準」，並連到 Partner Certifications 頁。多份公開指南一致指出 CCAR-F 不對一般大眾開放，報名限 Claude Partner Network 成員企業的員工，且註冊信箱網域必須符合合格企業，個人信箱無法報名；另有以企業身分申請需自「Registered」層級進入的門檻描述。同時 Anthropic Academy 存在一個 CCAR-F 的 access request 頁面，代表可能另有申請途徑。
- **讀者影響：** 最高。這是唯一會讓四週準備完全白費的資訊，而它目前不在書裡。
- **行動：** 在 `00-exam-map.md`「確認你準備的是哪個考試」之前新增一節「先確認你報得了名」，說明合作夥伴資格限制、企業信箱要求，以及 access request 這條可能的申請路徑；`README.md` 的閱讀路線表之前加一句指向該節。**資格條款以官方頁面與政策 PDF 為準，第三方指南只作為「需要去查」的線索，不可直接當事實寫入。**
- **驗收：** 該節每項限制都有對應的官方連結；沒有取得官方依據的部分明確標「未確認，需自行向官方入口查覈」，不使用第三方轉述當結論。

### P1-2｜報考平臺已移轉，書中只指向 Skilljar

- **位置：** `README.md` 的官方認證入口連結、`appendix-sources.md` S01。
- **證據：** Pearson VUE 已有 Anthropic 認證專頁，明列四張證照（CCAO-F、CCAR-F、CCAR-P、CCDV-F），並說明流程是先在 Anthropic Partner Academy 註冊，觸發排程流程後收到 Pearson 帳號密碼，再到 Pearson 帳號預約；考試可選實體考場或 OnVUE 線上監考。多份指南記載交付平臺於 2026-06-30 移至 Pearson VUE。
- **讀者影響：** 高。書中的單一連結不算錯（Partner Academy 仍是第一步），但讀者不會知道還有第二個平臺、第二組帳號、以及線上監考的環境要求。
- **行動：** 在 P1-1 新增的同一節內補「報名到坐上考位」的兩段式流程：Partner Academy 註冊／購買 → Pearson 帳號 → 選 OnVUE 或考場預約，並註明改期／取消須於 48 小時前於 Pearson 帳號操作。`appendix-sources.md` 新增 Pearson VUE 專頁為來源條目。
- **驗收：** 流程敘述與 Pearson VUE 專頁一致；OnVUE 的網域與環境需求不逐條抄錄，只提示線上監考有環境檢查，細節連回官方。

### P2-1｜考試政策整體缺席：費用、閉卷、重考等待期、效期

- **位置：** `00-exam-map.md` 的考試資訊表。
- **證據：** 目前該表只有認證名稱、代碼、題數時間、題型、情境結構、通過標準六列。公開資訊另有：費用 US$125（部分合作夥伴層級首次報考五折）、閉卷且不得使用 AI 協助、重考等待期 14／30／90 天且滾動 12 個月內最多 4 次（此項見於 Pearson VUE 官方頁）、證書效期 12 個月且有續證機制。
- **讀者影響：** 高。「閉卷、不得使用 AI」會直接改變讀法——這本書的自測與 Lab 設計本來就是為了內化而非查閱，但書裡從沒說明為什麼要這樣練。重考等待期則決定要不要冒險早考。
- **行動：** 擴充該表為兩張：一張「考試形式」（沿用現有六列，加閉卷／不得使用 AI），一張「報考與證書政策」（費用、重考等待期與次數上限、效期與續證）。重考政策標明取自 Pearson VUE 官方頁；費用與效期標「待查」，直到取得官方政策 PDF。同時在 `README.md`「如何使用這本書」補一句：因為是閉卷，各章自測要能不看書作答。
- **驗收：** 每一列標出來源與查覈狀態；「待查」欄位不得寫成肯定句。

### P2-2｜缺少官方 prep 課程與本書章節的對照

- **位置：** `00-exam-map.md` 的「原創四週安排」、`appendix-sources.md`。
- **證據：** Partner Academy 的 CCAR-F prep courses 頁列出七門課：AI Fluency: Framework & Foundations、Building with the Claude API、Claude Code in Action、Claude 101、Introduction to Model Context Protocol、Claude on Google Cloud、Claude with Amazon Bedrock。
- **讀者影響：** 中高。有 Partner Academy 權限的讀者會同時面對官方課程與這本書，卻沒有對照表可以判斷哪些能互相取代、哪些只有官方課程有。
- **行動：** 在四週安排之後新增一張「官方 prep 課程 ↔ 本書章節」對照表，逐門標出對應章節，以及本書**沒有**覆蓋的部分（雲端平臺課程、AI Fluency 的協作框架）。明確寫出本書不是官方課程的替代品。
- **驗收：** 七門課全部出現在表中；本書未覆蓋的部分老實標為未覆蓋，不用相近章節硬湊。

### P2-3｜缺少配速指南與整組情境練習

- **位置：** `12-practice.md` 的開場說明。
- **證據：** 考試為 60 題／120 分鐘，四個情境自六個情境庫抽出，每個情境框住一組題目；情境敘述本身就要花閱讀時間。本書 18 題採六情境各三題，適合概念定位，但沒有任何時間壓力訓練，也沒有「一個情境連續作答十餘題」的形態。`README.md` 的「考前總複習」路線承諾用 12 章排除干擾項，這部分是達成的；缺的是節奏。
- **讀者影響：** 中。不影響觀念正確性，但影響考場表現。
- **行動：** 兩件事，可分開做。（a）在 `12-practice.md` 開頭補一段配速說明：平均每題約兩分鐘，情境敘述的閱讀成本集中在每組開頭，複選題要先數清楚要選幾項。（b）新增一組「情境包」練習：單一情境敘述 + 連續 10–12 題 + 建議作答時限，形態貼近實際考試。**（b）為新增章節，需先確認使用者是否要做**；只做（a）也有價值。
- **驗收：** 配速說明不宣稱是官方建議，寫明是由題數與時間推得的算術。新增情境包若執行，須維持既有原創原則，不引用任何回憶題或第三方題庫。

### P3-1｜Claude 認證家族缺席，讀者無法確認自己選對考試

- **位置：** `00-exam-map.md`「確認你準備的是哪個考試」。
- **證據：** Pearson VUE 專頁列出四張證照：CCAO-F（Associate）、CCDV-F（Developer）、CCAR-F（Architect Foundations）、CCAR-P（Architect Professional）。書中目前只處理 CCAF／CCA-F／CCAR-F 的別名混淆，沒有處理跨證照的選擇。
- **讀者影響：** 中低。README 的別名說明已經擋掉最常見的誤會。
- **行動：** 在既有表格下方加一張四證照對照表（代碼、定位、與本書的關係），並註明 CCAR-P 是進階路線、不在本書範圍。
- **驗收：** 只列代碼與定位，不臆測各證照的題數與費用。

### P3-2｜雲端主題的範圍界定可能與官方 prep 路徑不一致【待查】

- **位置：** `00-exam-map.md`「哪些主題不深挖」。
- **證據：** 該節依考綱 Appendix 把「雲端配置」列為不深挖，但官方 prep 課程清單包含 Claude on Google Cloud 與 Claude with Amazon Bedrock，且有指南描述應「加選一門對應自身雲端的部署課程」。
- **讀者影響：** 中低，且**尚未確認為缺陷**。兩者可能並不矛盾：排除的是雲端部署細節的出題，prep 課程則提供背景。
- **行動：** 重新下載 Exam Guide PDF，核對 pp.36–39 的排除清單原文，再決定是否在該節補一句「排除的是雲端配置細節的出題，不代表不必知道 Bedrock／Vertex 的定位」。**核對前不修改正文。**
- **驗收：** 修改後的敘述能直接引到 PDF 的頁碼與原文用語。

### P3-3｜README 承諾的「弱項清單」沒有對應範本

- **位置：** `README.md` 閱讀路線表、`00-exam-map.md` 四週安排第四週產出、`12-practice.md`「訂正方法」。
- **證據：** 三處都要求讀者產出弱項清單，`12-practice.md` 的訂正方法已寫出應記錄的五個欄位（選項、漏看的限制、錯誤假設、回讀章節、可驗證實驗），但沒有可直接抄用的表格骨架。
- **讀者影響：** 低。文字說明已足夠，只是抄用成本高一點。
- **行動：** 在「訂正方法」補一張五欄空表當範本，附一列填好的示例（沿用既有的 Q03 例子）。
- **驗收：** 欄位與現有文字敘述一致，不新增未說明的欄位。

## 不列為缺陷的項目

以下在審閱中檢查過，判定為符合設計意圖，記錄下來避免下一輪重複討論：

- **書名與 slug 用 CCAF 而非官方代碼 CCAR-F。** README 已明確說明別名與正式代碼的關係，且 CCAF 是讀者實際的搜尋用語。維持現狀。
- **18 題遠少於 60 題。** 書中已明說「不是等值模擬考」，並禁止換算 scaled score。這是誠實的限制聲明，不是缺頁；P2-3 是加值而非補救。
- **未實際呼叫 Claude API／MCP／CI。** 成書計畫已將此列為明示的驗證範圍限制，正文也逐處區分離線模擬與需讀者自備環境的整合任務。
- **六張 Mermaid 圖、nav、書庫登記（`js/books-data.js` 第 14 行）與頁尾回連。** 成書計畫的最終驗收已逐項通過，本輪未見需要重驗的變更。

## 執行紀錄（2026-09-07）

### 來源突破

原計畫假設政策資訊需要另外兩份未取得的 PDF。實際重新下載 Exam Guide 並以 pypdf 抽取全文後發現，**§11–16（pp.33–36）本來就涵蓋報考流程、身分證件、重考、缺考、閉卷規則、保密協定、效期與續證、申訴**——這些頁面在成書時已列入「本書讀取範圍」，只是沒有寫進正文。因此除資格門檻外，本輪所有政策敘述都改以第一手考綱為據，不使用第三方轉述。

第三方指南與考綱的核對結果：費用 125 美元、效期 12 個月、重考 14／30／90 天與滾動 12 個月 4 次，均與考綱一致。**唯獨「限合作夥伴企業員工」在考綱中找不到依據**，維持待查。

### 順帶修正的兩件事

- **out-of-scope 清單原本缺三項。** 核對 pp.38–39 原文後補上「Claude API 的認證／計費／帳號管理」「特定程式語言與框架的詳細實作」「效能基準與模型比較指標」，並改寫成完整 16 項。
- **六個情境原本只有一句話帶過。** 考綱 §5 公開全部六個情境的設定與主要領域，已改寫為對照表，並串到本書 18 題的六組情境與相關章節。情境一的四個官方 MCP 工具名稱一併列出。

### 新發現並修正的缺陷：中文標題的錨點不穩定

寫入頁內連結時建置回報錨點不存在。查證後確認 `configs/claude-ccaf.yml` 的 `toc` 使用 python-markdown 預設 slugify，會把中文標題全部丟棄、產生 `_1`、`_2` 這類流水號 id——**任何人新增一個標題就會讓既有錨點指向別的章節**。已在該 config 的 `toc` 加上 `slugify: !!python/object/apply:pymdownx.slugs.slugify {kwds: {case: lower}}`（pymdownx 10.21.3 已安裝，非新增依賴），中文標題現在產生可讀且穩定的錨點。

此問題同樣存在於本書庫其他 20 本書的 config。經使用者同意後一併修正：21 個 config 全部加上同一行 slugify 設定。

修改前先確認風險：全書庫僅 `mas531-computational-photography` 使用頁內錨點，且都是 glossary 的 ASCII 單字母標題（`#c`、`#d`、`#l` 等），不受 slugify 變更影響。建置後已驗證這八個字母錨點全數存在。

修正後抽查，中文標題的 id 已由 `_1`、`_2` 變成可讀值（例：cs336 的「這本書的讀法」「目前進度」、semi-jobs 的「產業範圍」「怎麼讀」「數字怎麼用」）。**副作用：這些頁面的 ToC permalink URL 已改變**；書庫為本機閱讀用途，未對外發布過舊連結，判定可接受。

**重出全部 50 題**（使用者指示舊的不留），設計規則三條：

1. 四個選項都是實務上真的有人會選的做法；多數題目的判別點落在兩個都說得通的選項之間。

3. 字母位置打散。
