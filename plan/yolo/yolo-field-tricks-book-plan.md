# YOLO 現場招式：那些有點土，卻能解決問題的工程技巧

狀態：2026-09-21 已完成第一輪中英文網路研究並修訂大綱，尚未撰寫正文、建立新書網站或執行模型實驗。研究先存於 [data/yolo-field-tricks](../../data/yolo-field-tricks/README.md)，該目錄依 repo 設定不納入 Git。

## 定位

讀者能跑 YOLO，但遇到漏檢、誤報、資料不足或部署差異時，還不知道除了重新訓練以外能做什麼。本書從工程師的取巧與小實驗切入，學會控制輸入、拆解流程、快速驗證假設。

以工業瑕疵檢測為貫穿案例；影片技巧另用連續影像示範。這是獨立的書籍規劃，不覆寫既有《YOLO 工程：從任務到上線》。既有書提供原理，本書提供遇到問題時的動作。

「好用」指能在指定條件下省時間或改善交付結果，不表示所有技巧都是業界通則。區分診斷手段、可交付策略與只能製造漂亮數字的錯誤做法。先固定使用的 YOLO 實作、版本、權重及匯出方式；涉及 NMS 的內容只適用於具有該後處理步驟的管線。

## 六部二十二章

| 部分 | 章節／招式 | 現場實驗 | 有效前提與代價 |
|---|---|---|---|
| 一、先讓問題現形 | 1. 故意讓模型背熟十張圖 | 在少量已核對標註的圖片上訓練，直接檢查訓練圖預測 | 用來排查資料、類別與流程；背得起來不代表泛化，背不起來也不唯一指向程式 bug |
| | 2. 把 conf 降低，看看框到底有沒有出來 | 保留較低分候選，掃描門檻並比較漏檢與誤報 | 找候選被過濾的問題；降門檻不能救回模型根本沒定位的物體 |
| | 3. 存下模型真正吃到的圖 | 對照原圖、裁切、letterbox 圖與 tensor 統計 | 抓 RGB/BGR、縮放、padding、正規化差異；顯示圖不能替代 tensor 比對 |
| | 4. 留一包「每次都跑」的壞圖 | 保存誤報、漏檢、邊界案例與完整設定，建立重播腳本 | 這包是回歸集；反覆拿來改模型後不能再冒充獨立測試集 |
| 二、不重訓也能動的地方 | 5. 只看該看的地方：固定 ROI | 以整圖為基線，比較裁切、遮黑、推論後 ROI 過濾 | 三種機制不同；遮黑不必然減少運算，ROI 外目標會被排除 |
| | 6. 大圖切小塊，小缺陷變大 | 重疊切片推論，還原座標後合併框 | 適合小目標；增加延遲，處理切邊、重複框與尺度差異 |
| | 7. 每種類別有自己的門檻 | 在驗證集調不同門檻，比較每類漏檢與誤報 | 推論入口須先保留足夠低分候選；後端不能復活前面刪掉的框 |
| | 8. 模型後面接幾條土規則 | 依位置、尺寸、長寬比過濾，並記錄每條規則刪掉哪些框 | 要有穩定的場景知識；解析度、相機位置或新品種可能讓規則失效 |
| 三、資料不夠時的省工招式 | 9. 誤報什麼，就餵它看什麼 | 收集易誤報的正常紋理作為負樣本，重新訓練 | 必須確認沒有漏標的目標；正常紋理不是一律加成新類別 |
| | 10. 反而把資料增強關掉 | 檢查數字／方向語義，對照關閉無效翻轉或後期關 Mosaic | 先看增強後圖；關太多也可能更易過擬合 |
| | 11. 大模型先標，人類用三鍵修 | 大模型預標、小模型訓練；用裁切＋全景、快捷鍵與同類聯絡表修標註 | 加上補框與調框流程；刪壞框不能把有物體的圖變成負樣本 |
| | 12. 把缺陷貼到正常圖上 | 在合理背景合成缺陷並處理標註 | 檢查尺寸、邊界與光照；只用真實且隔離的資料驗證成效 |
| 四、用系統替模型補位 | 13. 先找得到，再分得清 | 先偵測 defect，再裁切做細分類，對照單一多類模型 | 適合定位相近但細分類困難的情境；第一段漏檢仍無法補救 |
| | 14. 連續看到才報警 | 對同一追蹤目標設計多幀確認與解除條件 | 降低閃爍誤報但增加延遲，短暫目標可能消失；獨立影像不適用 |
| | 15. 永遠只剩 300 個框，先查上限 | 查推論 max_det、圖內 top-k 與評估 maxDets，製造密集合成案例 | 不同層的上限不同；改評估設定要標示新的 metric 定義 |
| 五、部署現場的救命入口 | 16. 不接設備，直接重播一次推論 | 實作檔案與 tensor 入口，保存影像、參數、模型與輸出 | 要與正式入口共用核心流程；CLI 選項是新增實作，不是 YOLO 自帶功能 |
| | 17. Python 正常，C++ 卻跑歪 | 固定一張圖，逐段比對輸入 tensor、原始輸出、解碼、座標與後處理 | 容許合理浮點差異；不要只比最終畫框圖，也不要先猜是權重問題 |
| | 18. 慢的時候，先查排隊 | 分開量解碼、前處理、搬移、推論、後處理與等待時間；對照最新幀策略 | 丟舊幀適合重視即時性的串流；不可套用到要求每件必檢的產線 |
| 六、更有現場味的選讀與整合 | 19. 慢的可能是畫中文字 | 關閉渲染、快取標籤貼圖、比較各段時間 | 渲染改善不是模型加速；先量瓶頸再改 |
| | 20. 只讓互斥類別互相打架 | 同一批候選對照 class-aware、class-agnostic 與群組 NMS | 需要明確類別語義；不可讓人與其拿的物品互相抑制 |
| | 21. 故意多問一個不想要的類別 | YOLO-World 比較單一目標提示與加入混淆物提示 | 特定開放詞彙模型的案例，不是固定類別 YOLO 的通用技巧 |
| | 22. 做一套自己的 YOLO 實驗台 | 整合重播、階段輸出、ROI／切片／門檻切換與結果報告 | 保留 baseline、原始輸入及每次改動；品質與時間一起比較 |

第 12、20、21 章可按需選讀。原本的少數類別重複抽樣與傳統影像候選區移至延伸題，目前來源不足以把它們當主線的固定配方。

## 每章固定格式

1. 現場卡住的症狀與可重播案例。
2. 工程師先做的小動作，附最小操作或程式。
3. 為什麼可能有用：只補理解這招必要的原理。
4. 一次只改一件事，與原流程對照。
5. 看什麼數字：每類召回、每張或每件誤報、端到端延遲、人工複判量等。
6. 何時失效：提供一個反例，而不只展示成功畫面。
7. 如何撤回，以及哪些設定與紀錄值得保留。

每章標示「設定即可試」「需要改程式」「需要重訓」，並附適用版本。診斷用設定不能直接當正式效能測試設定。

## 貫穿實驗與驗收

主線案例：正常紋理容易誤報、微小缺陷容易漏檢的工業影像。尚未取得實際影像或程式，因此不宣稱任何招式已在 GPMDLCore 或使用者設備上驗證。

先依 lot、wafer、拍攝批次或相機等來源單位決定隔離方式，再產生裁切與擴增版本。固定一份原始 baseline、驗證集及獨立測試集，門檻和規則只在驗證集調整。

最終成品是可重播的推論實驗台：可切換 ROI、切片、分類門檻及規則，保存各階段輸出，對照品質與時間。合格條件由實際任務訂定，不預先承諾改善百分比。

## 不該拿來冒充成果的招式

- 用測試集反覆挑門檻，仍宣稱是獨立測試成績。
- 先切片再隨機切資料集，讓同張原圖的近似內容出現在兩邊。
- 複製少數樣本後，讓副本跨資料集。
- 刪掉難例或漏標，藉此讓分數上升。
- 只報 GPU 推論時間，卻對外聲稱是整套系統速度。

這些可作為識破假改善的反例，不作為建議操作。
