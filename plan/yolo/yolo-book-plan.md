## 定位與架構決策

讀者假設：會基本 Python，尚未完整做過視覺模型專案；數學與 PyTorch 先備另設補充頁。硬體未指定，規劃 CPU 入門、NVIDIA 部署及 Apple Silicon 支線，不假設有付費雲端。
讀完能從需求定義、資料、訓練、評估走到部署，解釋主要機制，並知道哪些結論需要現場驗證。
主線：需求與驗收 → 最小推論 → 資料與訓練 → 評估與排錯 → 任務選型 → 部署與維運 → 專案驗收。原理為工程判斷打底，08–12 為按需選讀，從排錯與選型頁回連；不要求先修完學術內容。
以物件偵測作共同基礎，其他任務說明相對於偵測新增的資料、輸出、損失、指標及部署限制。YOLO 家族不當成單一團隊的連續版本。
穩定概念與易變版本資料分離；不逐版重講 backbone、neck、head，不抄完整 API 參數表。外部好解釋保留導讀連結，但核心推導與可執行步驟仍須自足。

## Claude CLI 寫作交接

使用者指定：正文由 Claude CLI 執行；主 agent 管架構、資料評比與驗收，subagent 是 CLI 操作者，不自行代寫正文。
使用者已追加「繼續直到完成，commit push」，依上述 create 流程持續寫作與驗收。路徑預定 docs/yolo/、configs/yolo.yml、book/yolo/html/，成書後依 repo 規範更新 js/books-data.js。

1. 先補當批來源全文與版本定位；固定示範環境、資料及權重，不預先捏造測量結果。
2. 試寫 06 評估基礎：最小手算例子、圖、可執行核對及常見誤解，驗证全書深度；再回修模板。
3. 每批 2–3 個相關章，由主 agent 給章節 ID、目標、先備、來源與已讀範圍、術語、允許修改路徑、驗收條件。
4. subagent 用已確認的 claude 非互動 CLI，提示由檔案 stdin 輸入，保留 stdout/stderr、退出碼與產物路徑。不開 bypass permissions，不默認安裝環境或執行昂貴訓練。若 CLI 失敗，回報實際錯誤，不冒稱 Claude 已交付。
5. Claude 僅寫指定正文與章內資產；主 agent 維護 plan/nav/共用術語與整合決策。同一檔案不平行寫入。
6. 每批回傳來源版本/已讀段落、正文、操作證據、圖狀態、依賴變更與待補缺口；主 agent 查核來源與概念銜接後派下一批。
7. 正文穩定後製圖、交叉連結、同步資產、MkDocs 建置與視覺驗收；沒有執行的 GPU/部署測試清楚列待驗證。

## 原始驗收規格

架構：每章有目標、先備、來源映射、路徑、視覺需求；暫缺來源已標記。下一步依批次續寫、驗收與出版，不另等待逐批確認。

當代能力：每項能力分架構、已釋出權重、框架支援、匯出、硬體實測；未知留白並列待查。不存在跨情境保證的統一 FPS 或「準確率」。
專案：測試集隔離，部署前後精度比對，端到端延遲/記憶體/失效場景有紀錄；無硬體實測不能宣稱可達。
出版要求：相對連結、nav、Mermaid、圖文一致性、MkDocs build、入口卡片均列入驗收；最終結果見完成紀錄。
