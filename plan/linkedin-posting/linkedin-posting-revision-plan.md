# LinkedIn 書籍修訂計畫：從作者歷程學習發文

日期：2026-10-03｜狀態：已獲使用者同意，首輪可取得性試點完成，M1 未達標；已完成第一輪外部來源擴充與六章整合，見[批次進度](linkedin-scale-status.md)。

本計畫更新研究需求，取代舊計畫對「研究充分性」與案例規模的判定。既有正文保留作初稿；先完成研究試點，再依證據改寫。舊版完成建置，不代表已滿足本次新需求。

## 1. 書要幫讀者做什麼

讀者能根據自己的角色、經驗、目標受眾與可公開材料，選擇發文模式，寫出貼文，並理解別人的成效哪些能借鏡、哪些依賴當時的身分與環境。

核心問題：**某位作者在某段職涯，對哪些人說什麼、如何說、得到什麼反應；其中哪些做法適合我現在或未來的位置？**

「位置」先涵蓋三層：工作角色與資歷、領域可信度、帳號發展階段。受眾角色另記，例如工程師寫給同行、主管或潛在雇主，不能混成同一分類。

主要情境：

- 現在：設備／視覺 AI 工程師，累積工程可信度與同行交流。
- 鄰近發展：設備軟體 RD、一般軟體 RD、工業 AI，展示除錯、測試、整合與維護能力。
- 未來探索：LLM 應用與 Agent 工程，以實作和評測證據建立可信度。
- 資深工程師、主管、顧問、創業者作比較組，說明資歷與商業目標如何改變寫法。

## 2. 現有版本的缺口

| 現有內容 | 缺口 | 修訂方式 |
|---|---|---|
| 七篇短貼文拆解 | 孤立案例，沒有作者基準 | 加入同作者連續時窗與普通／低互動貼文 |
| 六類編輯模式 | 未充分連到職位、受眾、成效 | 經實際樣本修正分類，建立角色選擇表 |
| 通用發文教學 | 不清楚工程領域是否適用 | 用領域案例支持、限縮或反駁建議 |
| 自有成效記錄 | 缺乏他人貼文反應比較 | 加入有時間戳的公開反應數與比較限制 |
| 當前作者身分 | 可能把今日聲望套到早期貼文 | 建立職涯與發文並行時間軸 |
| 合成寫作示範 | 無法證明真實讀者反應 | 保留作練習，與真實案例研究分開呈現 |

## 3. 兩條研究線共同支撐全書

### A. 既有洞察、書籍與研究

先建立 12–20 項候選來源，篩出約 6–10 項可深入讀取、有方法或可操作建議的核心來源。這是工作量預算，不是已完成數量。

涵蓋平台官方說明、原始數據報告、作者本人對長期寫作的復盤、書籍／課程合法可讀章節，以及工程作者的實務分享。每項記錄：版本、研究期間、個人帳號或公司專頁、樣本來源、原始指標定義、主要主張、限制、適用角色及可驗證方式。

建立「主張對照表」：例如教學文是否容易累積專業信任、敘事是否較容易引出留言；逐項對照來源與本書案例。不同來源轉述同一份報告，只算一條證據鏈。付費書籍尚未讀到的章節列為待取得，不以書介或評論代替已讀正文。

本輪查到的研究入口（尚未完整審讀，不採用其成效結論）：

- [Metricool 2026 研究介紹](https://metricool.com/press-release-linkedin-study-2026/)：供尋找原報告與方法，檢查個人帳號、格式、帳號規模如何區分。
- [Richard van der Blom 研究方法自述](https://www.linkedin.com/posts/richardvanderblom_55-from-3500-posts-to-7-million-the-full-activity-7454084514089340928-frSX)：列為方法查核入口；作者自述仍須與可讀報告核對。
- [The Revenue Engine Playbook](https://richardvanderblom.com/the-revenue-engine-playbook/)：書籍候選入口，須判斷商業開發導向與工程職涯寫作的差異；目前不是已讀教材。

### B. 作者縱向研究與貼文比較

不要先指定名人就當代表。先建立約 24 位候選作者，按角色、領域、語言、可讀歷史、帳號階段與商業目的篩選。

建議正式範圍：12 位作者，每位約 20–30 篇可分析貼文，共約 240–360 篇；其中 4 位深讀約 40–60 篇，合計預估 320–480 篇（深讀包含原有樣本，不重複計數）。此數量用於編輯規劃，不代表統計代表性。

作者配置目標：設備／半導體與工業視覺 4 位、軟體 RD／工程實務 4 位、LLM／Agent 4 位。交叉領域指定主要組別，保留多重標籤。至少一半優先尋找接近讀者或只領先一至兩個職涯階段的作者；繁中作者以至少 4 位為招募目標，若不足，明列缺口，不用名人補滿後宣稱適合台灣工程師。

每位作者先探索最早可讀資料，再選擇三個有明確日期的時窗：早期、中期、近期；有轉職、升任、產品發布等可驗證事件時，另作事件前後比較。歷史能追溯三至五年則優先，但不硬湊年份。最早可讀貼文不等於第一篇貼文。

每個時窗固定起訖日，優先讀取窗內全部可見貼文；太多時使用事先記錄的系統抽樣規則。不可先看到讚數再決定研究樣本。另選的熱門教學案例標為目的取樣，不放入模式成效統計。

## 4. 先做可行性試點

選 3 位作者，分別代表設備／半導體、軟體 RD、LLM／Agent，每位 12–20 篇，涵蓋至少兩個時期。

試點須交付：

1. 三份作者時間軸，區分當時職位、今日職位與未知區間。
2. 36–60 筆貼文資料，含一般互動案例與缺失欄位。
3. 一份資料可取得性報告：正文、日期、反應數、歷史職位各能取得多少。
4. 一張角色與模式對照表，附證據強弱。
5. 一組「作者歷程＋模式比較＋讀者改寫」試寫章節。

試點驗收後才確定正式樣本規模。若深層歷史只能找到零散搜尋結果，該作者可作個案，不能作完整縱向分析；優先更換作者或縮短有證據的時窗。正文與數據無法讀取的連結只列線索，不填入已分析樣本。

## 5. 資料欄位與比較方法

### 作者資料

作者 ID、公開個人頁、主要領域、職位有效期間、職涯事件及來源、目標受眾、可確認的外部知名度／商業活動、追蹤數及觀察日期、歷史覆蓋與缺口。

目前追蹤數不能代替發文當時的追蹤數。職位期間來自可查證資料；不能由語氣猜測資歷。私人背景只用於讀者適配，不存入公開作者資料。

### 貼文資料

永久連結、作者 ID、發表時間及精度、資料擷取時間、當時角色及證據、主題、主要／次要發文模式、媒介、開頭、論證順序、證據類型、結尾邀請、語言、外部連結、反應數、留言數、轉發數、數值是否約略、可讀範圍及缺漏原因。

讚數明確區分「Like 類反應」與「全部 reactions」。介面只顯示總反應數就如實記錄，不將總數改名為純按讚數。缺失不是零；只有相對日期或縮寫數字時保留原始顯示及不確定性。

### 如何回答「哪種效果好」

- 每篇展示實際可見的反應、留言、轉發與觀察日期，讓讀者能看見量級。
- 優先比較同作者、同一時窗的不同模式，再比較角色相近的作者；報告樣本數、中位數與分布，不只列最大值。
- 同作者時窗內可顯示互動名次／百分位作描述，樣本少時只列排序，不能把相對排名當因果效果。
- 跨作者分析先逐作者摘要，避免高頻大帳號支配整體結論；保留語言、主題、媒介與特殊事件差異。
- 舊貼文今日累積反應不能還原當年七天成效。歷史樣本以當下快照描述；未來新追蹤樣本才可建立一致的 7／30 天觀察窗，兩者分開。
- 未取得曝光就不計曝光互動率；未取得歷史追蹤數就不計歷史追蹤者互動率。
- 公開互動不能證明錄取、升職或成交。目標受眾的實質回覆可作質性線索，不能冒稱轉換。

## 6. 模式分類與角色適配

現有六類模式作起點，加入作品展示、資源整理、職涯／里程碑公告等候選類型，由試點決定拆分或合併。主題、模式、媒介、目的分欄；一篇可以多標籤，但主要模式需有判定理由。

先讓兩位分析者獨立標註同一批 10–15 篇，整理分歧與反例，再批次處理。資料不足的模式只提供寫作示例，不宣稱成效較好。

每個模式章固定回答：

1. 原文如何組織，讀者為何可能願意看？
2. 作者當時是誰，已有什麼可信度與受眾？
3. 這篇反應如何，相對同作者同時期屬什麼位置？
4. 同模式的一般／低互動案例有何差異？有哪些替代解釋？
5. 適合什麼角色、目標與材料？不適合時改用什麼？
6. 讀者可如何改寫為設備、軟體 RD、LLM 或 Agent 題目？

角色適配分成「案例支持」「跨來源支持」「編輯推論」。高讚不自動等於適合讀者；結論需同時考慮可提供的證據、受眾與寫作目的。

## 7. 書籍新架構

| 部分 | 內容 | 讀者成果 |
|---|---|---|
| 一：先找到自己的位置 | 現職／未來角色、受眾、目標；如何讀互動數與研究 | 個人定位與模式選擇起點 |
| 二：看懂作者如何走到今天 | 4 位作者深度歷程；其餘作者比較卡；職位與發文時間軸 | 分辨可模仿的寫法與依賴聲望的條件 |
| 三：逐種學會發文模式 | 各模式的真實高／中／低互動案例、角色適配、既有洞察對照 | 有理由地選擇模式 |
| 四：從案例寫出自己的貼文 | 設備／視覺、軟體、LLM、Agent 同題改寫；開頭、證據、媒介、系列 | 完整草稿與可公開作品 |
| 五：持續修正 | 可維持的工作流、發文紀錄、回應與系列、自己的比較 | 個人寫作迴圈 |
| 附錄 | 樣本與方法、資料缺口、來源書目、分類規則、案例索引 | 能追溯每個結論 |

保留 C01 定位、C05 編修、C06 媒介、C07 互動與 C08 工作流中的可用內容；大幅重寫 C03／C04／C09，新增作者歷程與既有洞察比較。C02 改成簡明的方法導讀，詳細方法移附錄。研究資料的規模不等於正文篇幅：正文精選約 30–40 篇深入拆解，其餘進案例索引與分析摘要。

## 8. 資料與派工

延用 `data/linkedin-posting/` 作本機研究區，新增 `v2/`。預計以簡單 CSV 與 Markdown 保存 `authors.csv`、`posts.csv`、`claims.md`、`coding-guide.md`、`author-studies/` 與 `synthesis/`，不先建立資料庫或爬蟲平台。

研究檔依現有規則不進 Git。支持書中結論的精簡證據表、方法、來源連結與必要數據快照，須另整理進 `docs/linkedin-posting/`，讓版本庫中的書能獨立追溯。保存摘要與必要短引，不搬運整篇著作。

沿用使用者允許的 Luna max 子代理：

- 第一批：三名代理分別做三個領域的作者候選與可取得性試點；主代理統一抽樣、欄位、去重與判讀。
- 第二批：各代理在固定作者清單內讀歷史貼文，按作者分工，避免時間軸被切碎。
- 第三批：分工審讀既有來源與模式分析；主代理整合角色適配、反例和教學章節。
- 數字、職位時間線及強結論逐項回查；抽樣交叉複核至少 20% 資料。錯誤集中時擴大複核相應批次。

## 9. 里程碑與完成標準

| 階段 | 交付 | 通過條件 |
|---|---|---|
| M0 需求修訂 | 本計畫 | 研究單位、角色、數據與章節方向明確 |
| M1 試點 | 3 作者、36–60 貼文、試寫 | 能取得跨期正文與足夠互動快照；缺口可明確描述 |
| M2 正式研究 | 作者檔案、貼文表、核心來源筆記 | 抽樣規則一致、去重、每項有來源；覆蓋不足如實縮減主張 |
| M3 綜合分析 | 作者歷程、模式比較、角色適配、主張對照 | 每項主要建議能追到案例／研究，且有反例或邊界 |
| M4 正文重寫 | 新章節與精選案例 | 每種正式教授的模式至少 3 篇跨至少 2 位作者的真實拆解，含一般或低互動對照；否則標為探索性 |
| M5 出版驗收 | 建置與桌面／手機閱讀檢查 | 來源、數字、時間軸和連結核對；既有書庫檢查通過 |

研究完成不能只靠達到篇數。至少回答：目前的我先練哪幾種模式、未來角色需要哪些材料、同一作者的寫法如何隨位置變化、哪些高讚做法不適合直接照抄，以及有哪些尚無資料的問題。

M1 試點未取得足夠跨期資料。2026-10-03 使用者進一步授權大規模研究；改先擴大外部來源線及質性整理，並補入書稿。作者跨期、互動比較仍按原驗收條件保留未完成，詳見[批次進度](linkedin-scale-status.md)。


## 10. 使用者補充：低頻研究與分批派工（2026-10-03）

使用者允許十名以上代理，但要求避免過度爬取。代理數不等於網路請求並行度。此環境含主代理最多四個同時運行名額，因此以三名 Luna max 子代理分批執行，不為湊代理數增加請求。

- LinkedIn 同一時間只有一名指定研究者定點閱讀，其他人讀不同原站或處理本機資料。
- 不建爬蟲、不遍歷帳號、不自動翻頁、不平行抓取、不繞登入、驗證或限流。
- 首批每人最多四次搜尋、六個原始頁面；先評估可讀性，再調整下一批，這不是平台認可的速率保證。
- 已讀資料共用，必要查核才重開；遭遇阻擋即停止該來源，不能改派其他代理重試同一限制。
- 有登入提示但正文仍可公開閱讀時可記錄可見部分，不操作登入；若正文不可讀，標記缺口。
- 第一批採設備貼文、作者原站背景、既有研究三種分工，先避免三組同時請求 LinkedIn。
- 若無法在此方式下取得原定 36–60 篇，先交付可取得性結果及調整方案，M1 保留未達標，不以搜尋摘要或原站文章補算。

首輪結果見 [試點報告](linkedin-pilot-status.md) 與 [教學試寫](linkedin-pilot-sample.md)。LinkedIn 遭遇 HTTP 999，已停止本輪全站讀取；實際只取得兩篇正文，不能啟動原定模式成效比較。
