# LinkedIn 擴大研究：批次與交付

2026-10-03｜第一輪完成，縱向研究仍未完成。使用者已授權擴大研究，保留低頻、非爬蟲限制。

## 本輪範圍

擴大既有研究、第一人稱復盤、合法書籍節選、工程作者背景與寫作案例的覆蓋，再整理成能閱讀的書稿。LinkedIn 先前發生 HTTP 999，本輪不請求其網域，也不以其他代理或工具重試。直接貼文縱向資料仍是獨立缺口；不把外部文章算成 LinkedIn 貼文。

既有 M1 未通過。此次先推進 M2 的外部來源線與 M3 的質性整理，不將它們標成 M1 或全部正式研究完成。原定 320–480 篇是規劃上限範圍，不是本輪抓取指令。

## 批次安排

| 批次 | 分工 | 網路範圍 | 交付 |
|---|---|---|---|
| A | 原始報告、作者復盤、領域作者 | 不同非 LinkedIn 原站，定點讀取 | 三份來源卡與請求紀錄 |
| B | 書籍合法節選、繁中作者、補充工程寫作 | 依 A 的缺口再分配，避免重複網站 | 補充來源卡、未讀候選清單 |
| C | 主張對照、角色適配、作者時間軸 | 本機資料，不新增請求 | 綜合分析與書稿 |
| D | 數字與歸因檢查、來源與章節檢查 | 優先本機，必要查核才定點讀取 | 修正與驗收紀錄 |

每位外部資料研究者最多四次搜尋、六次逐頁開啟；這是本輪工作預算，不代表網站認可的安全速率。遇到阻擋停止該來源，搜尋摘要僅作線索。代理名額最多同時三位；擴大分工不等於提高同站請求並行度。

## 交付判準

- 來源卡記錄已讀範圍、發布日期、資料期間、職位證據、指標與缺口。
- 相同研究的報告／新聞稿／轉述合併為一條證據鏈；來源頁數、證據鏈、作者數、貼文數分開計算。
- 角色與模式建議須標明來源支持或編輯推論；沒有互動快照，不作高低讚排名。
- 作者時間軸保留當時職位未知，區分原站文章、團隊文章與 LinkedIn 個人貼文。
- 本機研究放 `data/linkedin-posting/v2/`；書中必要證據與引用整理進正文，確保不依賴 Git 忽略的研究檔也能閱讀。
- 書稿建置、相對連結與證據檢查完成後，記錄剩餘缺口。
