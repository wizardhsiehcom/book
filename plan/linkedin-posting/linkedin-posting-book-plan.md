建立／查核日期：2026-09-30｜slug：`linkedin-posting`｜目前範圍：研究完成後，接續正文實作與本機出版驗收。

## 讀者與成果

本書以使用者的機械／動機與 AI 背景、設備業影像 AI 研發經驗為起點，規劃適合本人目前身分與未來可能角色的 LinkedIn 內容。主要受眾是設備／視覺 AI 同行、軟體 RD、LLM／Agent 應用工程師，以及能評估技術能力的主管。

核心定位：**從設備與視覺 AI 出發，展示把 AI 做成可維護軟體的能力，再以公開作品探索 LLM／Agent 應用。** 完整的角色矩陣、12 個候選題目與材料要求見 [個人定位](../../data/linkedin-posting/positioning.md)。這是依本人背景提出的編輯建議，未假設已具備未來職位的資歷。

讀完應能：選定服務的讀者與問題、從真實工作材料產生題目、選擇發文模式與媒介、完成一篇有證據的貼文、回應留言，並用自己的資料修正下一輪內容。求職、建立同行關係與商務詢問採不同成果指標。

主線：**目前能力／未來角色 → 領域作者與案例 → 可公開的技術材料 → 發文與作品 → 同行對話與修訂**。

半導體是產業範圍；設備軟體 RD、工業 AI 是鄰近角色；LLM 應用與 Agent 工程是可透過作品探索的方向。優先蒐集這些領域實際工程內容的寫法，既有通用發文教學用於支援編輯。

本書以個人帳號的自然觸及內容為主。公司專頁用作比較與證據邊界；廣告投放、私訊外展、自動發文系統與全套個人檔案優化不在主線。沒有保證觸及、固定爆文公式或演算法權重表。

### 內容模式（編輯分類）

1. **教學拆解**：問題 → 步驟 → 範例 → 適用限制。
2. **案例復盤**：情境 → 決策 → 結果 → 可移用的教訓。
3. **觀點論證**：主張 → 理由與證據 → 反例／邊界 → 意涵。
4. **經驗敘事**：具體事件 → 認知轉折 → 對讀者的用途。
5. **資料解讀**：來源與樣本 → 發現 → 不能推論的事 → 實務意義。
6. **專業提問**：情境與自己的初步答案 → 明確問題 → 邀請有經驗者補充。

這六類可重疊，用來幫讀者選擇表達方式，並非 LinkedIn 官方分類或成效排名。里程碑公告歸入案例／敘事；清單是組織形式；文件輪播、影片與純文字是媒介；newsletter 是連載與訂閱載體。避免把這些放在同一張互斥分類表。

## 試寫與後續批次

1. **先補領域案例，再試寫 C04**：用公開／合成資料的小型影像 AI 錯誤分析，示範教學與復盤兩種寫法；搭配一個公開文件 LLM／Agent 小實驗的候選題，並以能公開讀取的領域貼文做結構分析。實驗尚未執行前只寫設計，不預填結果。不得捏造發布成效。驗收讀者能說明選擇模式的理由，並自己產出草稿。
2. **批次一 C01–C03**：補齊定位、證據判準與素材庫，使 C04 不依賴尚未定義的概念。
3. **批次二 C05–C07**：完成改寫、媒介選擇、回應與再利用；重新核對當時官方功能。
4. **批次三 C08–C09、A01**：完成可維持的排程與記錄表，檢查數據定義一致；小型比較是練習設計，不冒稱已執行實驗。
5. **出版整合**：正文穩定後建立 `configs/linkedin-posting.yml`、`docs/linkedin-posting/README.md`，登錄 `js/books-data.js`；同步資產、建置與視覺驗收。

每批回修來源映射、概念依賴與缺口。未讀的案例不能填成正式教材；若真實樣本不足，保留合成示例標記並縮減跨族群結論。
