# 產物：原始碼不是正在執行的程式

你把待判條件改了，畫面卻沒變。先不要改第二次：編輯器裡的檔案、編譯器的輸入、最後執行的檔案，是三個位置。

## 從文字到程序

C++ 原始碼經前處理與編譯，形成可供連結的物件檔；linker 將定義接起來形成執行檔。執行時系統載入產物，開始程序。實作可以合併部分階段，但你的診斷仍要分辨是語法／型別錯、定義找不到，還是啟動後結果錯。

C00 G06 的 `checker.h` 只提供宣告。`main.cpp` 看見宣告，因此知道如何呼叫 `load`；真正定義在 `checker.cpp`。只交 main.cpp 編譯，可能通過前面的型別檢查，卻在連結找不到定義。

```sh
c++ -std=c++17 -O0 -g lessons/06-modules/main.cpp lessons/06-modules/checker.cpp -o build/g06
```

這條命令在 C00 根目錄、build 已建立時使用。Windows 的旗標不同，請用課程建置入口；不要直接把此命令貼給 cl。

## 你要留下什麼證據

C00 的 `course.py run` 先重建、成功後才啟動。它不讓一次 build 失敗後接著跑舊檔。不過手動雙擊別處的 exe 仍可能跑錯；所以核對執行檔路徑、編譯來源與輸入，而不只看螢幕上有沒有 `PASS`。

Debug 通常保留較易讀的除錯資訊並降低最佳化；Release 可能重排或消除程式，單步位置不再和每一行直覺對齊。本書用 `-O0 -g` 學流程，另用 `-O2 -DNDEBUG` 驗行為。不是說 Release 一定更正確或 Debug 不必測。

## 做一次差異實驗

在練習副本把 G01 的待判資料改掉。先不建置，直接跑 build/g01；再使用課程入口重建並跑。記錄兩次數字差在哪。這個實驗只動自己的副本，不把沒建好的產物當交付。
