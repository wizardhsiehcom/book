# 從讀懂程式到能修改系統

<p class="lead">你能讓 AI 寫出程式，下一步是自己掌握它的資料、資源、失敗與修改邊界。這本書以 C++17 為主，把一個離線圖片檢查器背後的工程判斷拆開說清楚。</p>

假設你接到一份缺陷清單，準備送去判圖。你需要知道：哪些列待判？圖片找不到還是空的？重複身分應怎麼處理？改一項規則後，舊行為有沒有被破壞？問題很小，已經用得到值、容器、資源、契約、測試與工具。

**B01 是原理與判斷的書；C00 是一版版做出工具的課。** 讀一頁原理，再做一個相關實驗，比等整本讀完才動手更容易確認缺口。

## 從哪裡開始

- 還不確定先備能力：先到 C00 的免修診斷，或讀[全書地圖](00-map.md)。
- 能看懂語法但不知道修改會影響誰：從[值與參照](02-values.md)、[生命週期](03-lifetime.md)開始。
- 程式有跑卻不確定正確：讀[輸入契約](06-contracts.md)、[測試證據](09-tests.md)。
- 改碼沒有反應或只會猜問題：讀[產物](01-build.md)、[除錯](10-debugging.md)、[Git](12-git.md)。

每頁先從具體問題開始，解釋機制，再比較方案與反例。文末先作答，解答在[獨立答案頁](answers.md)，不要求背術語。
