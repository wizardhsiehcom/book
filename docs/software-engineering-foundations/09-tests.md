# 測試證據：要能抓到一個真的錯誤

測試輸出 PASS 很容易。重要的是，如果你把 `bytes < minimum` 錯改成 `bytes <= minimum`，測試是否會發現剛好等於門檻的檔案被拒絕？

## 從契約選案例

先找一個正常值、邊界值與違反前提的值。MIN_BYTES 接受 1..1000000，至少測負數、0、上限外與字尾垃圾；檔案大小規則則測 N 和 N+1。前者是輸入驗證，後者是比較規則，不要用同一個籠統「錯誤案例」代替。

工具有多種輸出，測試也要檢查相應證據：exit code、id、狀態和總數。只斷言程式沒 crash，會漏掉「查錯列但有輸出」。只斷言含 PASS，也可能只是在印固定字串。

## 兩個尺度

書附 `concepts.cpp` 用直接呼叫驗小原理；C00 `tools/check.py` 則啟動真實執行檔，用暫存清單／圖片目錄核對外部契約。前者精準但不能代表 CLI，後者包含解析與檔案系統，但也沒有測影像解碼或網路。

一個合成 PNG 可證明 ready 路徑，不能證明原機台的全部圖片品質。測試替身簡化的部分，必須在結論中留下來。

## 檢查本身是否有效

C++ assert 在 NDEBUG 下可能消失，Python assert 在 -O 下也可能省略。因此配套檢查用條件失敗時拋例外，並故意觸發一次確認會被抓到。這不是建議所有程式都禁用 assert；它只是確保本教材驗收不依賴可被關閉的機制。

如果改了某行，卻沒有任何測試能失敗，回去問是否缺案例，或該行根本不影響契約。不要為提高測試數字逐個私有 helper 寫鏡像測試。
