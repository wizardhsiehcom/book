# 自我檢查解答

先保留自己的答案，再核對。可以有不同實作，但不能略過題目中的契約。

## Q01

可能編譯時出現宣告不匹配，也可能呼叫端仍能編譯但連結找不到相應定義；依實際改法判斷。保留來源與建置旗標、產物路徑、輸入與執行結果，比只說跑過更有用。

## Q02

auto row 是副本，修改不回到 vector。改 auto& 才借用原元素，但也改變副作用契約；報告原本只讀，不應隨意修改 judge。

## Q03

line 每輪可能覆寫內容或改變緩衝區，存其地址不等於保存當時文字；生命週期結束後更不能使用。Row 值把需要的數字保存到自己的儲存，不借用 line 的地址。

## Q04

set 的身分等價與順序不同於原始列；unordered_set 不提供原清單排序。分開 rows 與 seen，保留順序與完整內容，另做 id 查重。

## Q05

不行。要說明雜湊平均行為、字串長度、檔案呼叫成本、I/O 與輸入規模。較少比較不代表整個工具在任何環境必然更快。

## Q06

使用者或腳本可能忽略後續錯誤，把前面視為完整報告。若允許部分結果，需明確標示 partial、失敗列與退出語意，不能沿用全部成功的契約。

## Q07

空批與無法讀取變得無法區分；可能印一份正常空結果。保留例外或明確錯誤結果，讓入口決定退出。

## Q08

副檔名需求只影響路徑選擇；放寬身分會改另一項安全與資料契約。由 main 驗證副檔名後傳給產生路徑的 report 或獨立命名函式，不讓 parser 接收任意路徑。

## Q09

在練習副本把 < 改成 <=，剛好等於檔案大小的測試應由成功變失敗。若仍全綠，查案例是否真的走過比較與是否只測了兩端以外的值。修回後才保留有效實作。

## Q10

固定清單內容／版本、程式產物與配置、圖片根目錄與檔案快照。若 load 得到的 Row 完全相同，再往選取與路徑查；不能只因檔名同名就排除輸入差異。

## Q11

不行。I/O 路徑與最佳化不同會混入額外變因。先用同環境同資料核對正確性，再在同一量測範圍比較。

## Q12

移出暫存用 restore --staged；普通 restore 會依來源恢復工作區，可能丟棄修改。先用 status、diff 與 diff --cached 確認內容。

## Q13

應說明 macOS 實測及 Windows 操作路徑未驗，不能把語言跨平台設計當作平台驗證。遠端 CI 未執行也要分開記錄。

## Q14

list(a) 只複製外層，內層 dict 仍共用。先決定要修改原資料還是產生獨立結果，再選逐列複製或建立新輸出；含巢狀可變值時需要更明確的複製政策。
