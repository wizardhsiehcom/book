# CI 與交付：讓另一個環境也能重現

「我電腦能跑」還少了來源、工具鏈、依賴、輸入與命令。另一個人如果拿不到相同條件，成功經驗就無法重現。

## 一個共同入口

C00 的本地驗證入口是 `python3 tools/course.py test`。CI 可以執行同一入口，不另寫一套只有雲端懂的判準。倉庫附一份 GitHub Actions 工作流程，檢出來源後在 Linux runner 執行；在遠端真正跑過之前，狀態仍是「設定就緒，遠端未驗」。

CI 不是品質證明書。它只能按配置檢查所涵蓋的行為。沒有測到的 Unicode 路徑、Windows filesystem 權限、真圖片解碼，不會因為綠勾自動成為已驗證能力。

## 交付要說哪些話

記錄工具版本、建置旗標、輸入來源、已測的正常與失敗案例、如何停止與重跑。exit 1 是資料問題還是程式崩潰，也要說清楚。若交付的是讀者工具，應能從乾淨 build 目錄重新建置；不是靠自己遺留的二進位檔才能成功。

一般部署可能需要固定依賴版本與包裝產物，本課沒有第三方 C++ 依賴，因此先用標準編譯器與來源就足夠。不要在還沒有部署需求時順手加 Docker、套件倉庫與發布平台。

## 驗證出版也是交付的一部分

程式跑得動，正文命令卻指錯檔案，讀者仍然會卡住。所以本書建置時核對連結和範例，並抽查表格、圖、程式碼在閱讀畫面是否溢出。工程驗收與閱讀驗收各記自己的證據。

**Q13：** 本機通過而 Windows 沒跑過，交付說明應該寫「跨平台驗證完成」嗎？你能合理承諾哪些事？
