# 模組邊界：哪一段可以獨立改，哪一段不能

需求從「只查待判 PNG」變成「所有列都查 JPG」。最先要做的不是加幾個 class，而是定位選取規則、命名規則與報告統計在哪裡。

## 沿變動原因切開

C00 有四個明確責任：number 將文字變整數；load 將輸入變成可信 Row；inspect 將路徑與門檻變成檔案狀態；report 選列並輸出。main 組合參數、開檔與最外層錯誤處理。

這不代表每個函式都要一個檔案。G05 保留單檔，有利初學者看完整流程；G06 才把可讀的核心定義移到 checker.cpp，讓入口剩下組合。拆分理由是閱讀、測試與規則變更已經有具體邊界，不是行數超過某個神奇數字。

## 介面要讓依賴看得見

`inspect(path, minimum)` 直接呈現會影響結果的輸入。如果它偷偷去讀全域設定，測試固定 path 也不等於固定條件。把真正需要的參數傳入，比先蓋一套配置框架更容易推理。

load 接受 istream 是因為檔案和字串都能用相同讀取契約，便於做解析反例。這是標準函式庫已有的介面，沒有必要為唯一 parser 再造 factory 或 repository layer。

## 重構先凍結行為

移動定義前記下正常、空批、錯欄、重複與缺圖的報告及結束碼。移動後重跑，出現差異就查明原因。測試只能保護已覆蓋行為，不能因為全綠就順手混入選取規則改動，否則 reviewer 很難知道差異是移動還是新需求。
