# 輸入契約：拒絕錯誤，比默默猜測可靠

清單寫 `1oops -1`。如果解析器只讀前綴 1，程式依然會去查 1.png，甚至印 ready。每一步都沒有 crash，整份結果卻指向了不該接受的資料。

## 三層檢查

第一層是形狀：標頭必須符合約定，每筆恰好兩欄。第二層是型別：整欄都要能轉成整數，不能只成功讀取前綴。第三層是領域：id 必須在 1..999999，judge 在 -1..99，同一份清單 id 不重複。

C00 選 `from_chars`，同時檢查 ec 與 ptr。只看 ec 可能留下未消耗字尾；只看 ptr 也忽略超出整數範圍。先驗證有號數再轉成檔案大小使用的無號型別，避免負值被轉成很大的正值。

```cpp
const auto parsed = std::from_chars(first, last, value);
if (parsed.ec != std::errc{} || parsed.ptr != last)
    throw std::runtime_error("invalid integer");
```

這是解析重點片段；可跑例子在書附 `concepts.cpp` 與 C00 `number`。

## 契約也要選擇失敗策略

本課選擇整份清單讀完且驗證成功才產生報告。因為格式壞掉時，部分摘要容易被當成完整結果。空白行略過，只有標頭則表示合法空批；空檔沒有標頭，回 2。這些都是明確的產品政策，不是語言自動決定。

若真實需求是盡量檢查可用列，可以改成收集 rejected rows，但要讓報告清楚標「部分完成」。不能一邊跳過錯誤，一邊用全部成功的退出碼。

## 簡化必須可辨識

此處不是完整 CSV parser，不處理引號、逗號或嵌入換行。檔名從驗證過的整數導出，沒有從清單接受任意路徑。接產線時先寫轉接契約，不把此 parser 直接套到未核對格式。

**Q06：** 有一筆合法資料後接壞資料，為什麼先印第一筆成功再 return 2 可能誤導？如果想保留部分成果，要改哪個契約？
