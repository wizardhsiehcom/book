# 容器：選的是資料語意，不只是效能

清單今天三筆，明天三千筆。固定陣列的筆數被寫進程式，因此 C00 G02 改用 vector。但下一階查重選 set，不代表要把整份清單也換成 set。

## 兩份不同用途的資料

`vector<Row> rows` 保存每一列及原順序。`unordered_set<int> seen` 只回答「這個身分是否出現過」。報告沿 rows 走，查重沿 seen 做；兩者擔任不同角色。若直接遍歷 unordered_set 印報告，順序就不是原清單順序，甚至沒有 judge 可用。

| 結構 | 你真正需要的性質 | 常見代價 |
|---|---|---|
| vector | 連續資料、依序掃描、索引 | 中間插刪搬移元素；成長可能換儲存位置 |
| unordered_set | 身分唯一、平均快速查找 | 額外記憶體、無承諾的排序、最壞查找仍可很慢 |
| map | key 對 value、排序遍歷 | 樹結構成本；不是每個 key 查找都需要排序 |

選容器之前先問資料是否要保留順序、重複值、關聯內容，以及數量如何變化。沒有需求就不引入另一份索引。

## 成長會影響借用

vector 重新配置儲存時，指向舊元素的參照、指標與 iterator 會失效。`reserve` 可以減少重新配置，但不能拿「我大概留夠了」當生命週期保證。C00 的做法是先完整載入，再唯讀遍歷；遍歷期間不 push_back，因此更容易分析。

本書例子先存副本，再讓 vector 成長，最後仍可安全讀副本。刻意不讀已失效參照，因為一次看起來能跑不證明合法。
