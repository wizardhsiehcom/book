# 09　全自動檢測整機，究竟整合了什麼？

如果只需要一張照片，相機與鏡頭似乎就夠了。產線需要的卻是：正確的工件被安全送進來，在指定區域取得可靠影像，完成判定，結果送到正確位置，工件再被安全送出。全自動整機的難度，存在於這些工作必須長時間一致完成。

先備：[成像](05-optics-and-imaging.md)、[recipe](06-aoi-and-recipes.md)與[量測](07-metrology-and-3d.md)。本章使用一般整機模型，不是倍利機構設計圖。

## 工件從進站到出站

進站先確認工件身分、載具與允許的 recipe。搬送與定位要讓工件進入可檢查姿態，同時避免碰傷、污染與誤放。接著依檢查區域安排運動、對焦、取像及資料處理；檢查完成後，系統輸出狀態、結果與追溯資訊，再交還工件。

```mermaid

    A["身分與載具確認"] --> B["搬送與定位"]
    B --> C["對焦、運動與取像"]
    C --> D["檢出或量測"]
    D --> E["結果與完整性檢查"]
    E --> F["出站與資料交接"]
```

## 為什麼整機不是零件規格相加？

運動平台標示很小的位置重複偏差，不代表取像座標同樣準確。熱漂移、光學畸變、工件定位和座標轉換都可能加入變動。相機能快速輸出影像，也不代表工件能以同樣速度對焦與移動。

整機性能由共同配置決定。例如一組高倍率光學可提供較細取樣，但若需要大量停走與對焦，總節拍可能下降；若改成運動中取像，就要驗證拖影、照明與同步。單獨引用各子系統在不同條件下的最大值，可能拼出實際不存在的性能組合。

## 哪些故障一定要被保留？

假設搬送成功、影像取得 99 個區域，但第 100 個區域失焦。若系統仍輸出普通「完成」，下游就可能誤以為整片符合檢查範圍。完成狀態應區分有效全檢、部分完成、無效量測與待重跑。

另一種情境是分析完成但網路中斷。工件能否出站、結果是否稍後補傳、如何避免同一工件被重複記錄，必須有明確流程。這些細節直接影響追溯與停機，並非只是 IT 附加功能。

停電或緊急停止後，還要確認工件實際位置、未完成作業與資料狀態。不能單純重新啟動軟體就假設世界回到初始狀態；復歸應從可核對的現場狀態接續。

## 從展示到量產驗收

展示可證明一個場景可運行；驗收則要覆蓋約定的工件、缺陷、節拍與異常。測試集合應包含代表性材料、邊緣區、翹曲、不同載具與合理的批次變化，再用共同方法確認品質。

| 驗收面向 | 要看到的資料 | 常見遺漏 |
|---|---|---|
| 工件與搬送 | 適用範圍、損傷與異常紀錄 | 只用一種理想載具 |
| 影像與品質 | 覆蓋、漏檢、假警報、無效區域 | 未把缺拍算進整體結果 |
| 量測 | 參考比較與條件變化 | 只報重複性 |
| 產能 | 同 recipe 下端到端時間 | 只報拍照或演算速度 |
| 整合與復歸 | 錯工件、斷線、重啟與補傳 | 只驗正常路徑 |

工廠端驗收與出廠端驗收可能面對不同環境和接口。測試在供應商現場通過，仍需確認客戶的搬送、網路、流程和工件變化不超出條件。

## 與倍利的連結

**已確認：** 倍利公開晶圓級自動檢量測整機，具名型號與通用功能的對照見[第 14 章](14-v5-product-evidence.md)。

**推論：** 整機交付通常需要承擔較完整的工件到結果鏈，適合用本章責任表追問；實際契約可能另有選配與客戶責任。

**待查：** 特定配置的有效全檢節拍、異常復歸、量測研究與具名客戶共同驗收。不能由「全自動」一詞推出無人值守範圍。

## 理解檢查

1. 相機很快，為何整機仍可能很慢？
2. 部分區域失焦時，什麼資訊不能被「完成」狀態遮掉？
3. 供應商現場驗收通過後，客戶現場還要驗什麼？

??? note "參考推理"
    1. 搬送、定位、對焦、分析或輸出可能主導總時間。
    2. 未完成區域、原因、受影響工件與重跑需求。
    3. 真實工件、接口、環境、流程及異常處置的共同運作。
