# 12　缺陷座標如何變成產線可用的資料？

檢測設備找到一個缺陷，如果下一站找不到同一位置，這份結果就無法支持複判與分選。資料整合的核心不是「有沒有輸出檔案」，而是另一個系統能否把結果正確對回工件、理解狀態並完成動作。

先備：[ADC](08-adc-and-human-review.md)與[三種硬體部署](09-standalone-inspection.md)。本章不教未取得正式規格的 KLARF 或 SINF 欄位；以下欄位表是本書自建的資訊需求模型。

## 身分、位置、結果、版本

| 資訊群 | 教學欄位例 | 為什麼需要 |
|---|---|---|
| 身分 | 批次、工件、站點、作業識別 | 避免結果套到另一片晶圓 |
| 位置 | 原點、軸向、單位、正背面、晶粒與局部座標 | 讓接收端找回同一實體位置 |
| 結果 | 候選、類別、量測值、有效／待查狀態 | 區分已判定與未完成 |
| 影像 | 可追溯影像位置與取像條件 | 重現判讀依據 |
| 版本 | recipe、模型、軟體、校正與格式版本 | 解釋重跑和歷史結果差異 |
| 時序 | 取像、分析、完成與傳送時間 | 分析等待與異常復原 |

這些資訊可能分散在多個檔案、訊息和資料庫中，不要求全部塞進單一格式；但要有穩定的關聯方式。

## 地圖、結果檔與通訊是不同層

Wafer map 是把工件上的單位或位置連到狀態的表示方式。檢測結果檔可能保留候選位置、類別與影像索引；分選端可能使用另一種較聚合的晶粒狀態。多個缺陷落在同一晶粒時，如何合併為最終 bin，需要明確規則。

KLARF 與 SINF 是倍利公開列出的結果輸出選項。本輪沒有取得兩者可直接作為互通保證的完整第一方 schema，因此不把它們寫成欄位固定、所有設備都能直接交換的通用格式。實作前需要版本、樣本檔與接收端規格。[倍利整機產品頁](https://www.v5.com.tw/tw/service/product/5/6)

SECS/GEM 則屬設備與工廠主機的通訊、資料及控制行為脈絡。SEMI 的官方導覽區分 SECS-II 訊息與 GEM 設備行為，以及承載訊息的相關標準；它不等於缺陷圖片或結果檔格式。設備列出支援 SECS/GEM，也還要核對實作的事件、警報、命令和狀態。[SEMI 通訊標準導覽](https://www.semi.org/en/standards-watch-2022-Sept/intro-to-semi-communication-standards)

## 座標轉換不是改兩個欄位名稱

一套系統可能以晶圓中心為原點，另一套以某個參考角或晶粒為原點；軸向、單位與正背面觀察方向也可能不同。轉換可能包含平移、旋轉與鏡射，具體形式依兩端定義而定。

**教學例：** 假設兩端共用中心與尺度，但接收端 X 軸方向相反，原位置 (2, 3) 應變成 (−2, 3)。如果只把欄位複製，畫面上的座標仍是合法數字，卻代表另一個位置。真實背面轉正面不能直接套這個簡例，還需要晶圓方向、基準標記和實際機台定義。

要測轉換，最好選分布在不同象限、接近邊緣且不完全對稱的已知位置。只測中心點會漏掉鏡射和旋轉錯誤；只測一個點也無法充分辨識比例與方向。將結果送到接收端，再實際找回原位置，才形成有用的往返測試。

## 斷線與重跑會製造什麼資料？

設備送出結果後沒收到確認，可能需要重送。接收端若把每次重送都當新檢測，缺陷數與產量就會被重複計算；如果只按晶圓 ID 去重，又可能誤刪真正的不同站點或重測結果。因此需要能區分工件、作業與版本的識別策略。

重測也不能不留痕跡地覆蓋舊結果。第一次可能缺拍，第二次才完整；後端應知道哪份是目前有效結果，以及前一次失敗原因。跨系統時間不同步時，僅按時間戳排序還可能出錯，需要結合作業識別與狀態轉移。

## 接口驗收要走完整圈

用代表性工件產生結果，傳給接收端，檢查位置、單位、類別與影像，再讓下游完成預定動作。另測空結果、未知類別、缺圖、版本不合、斷線、重送與重跑。空結果尤其要區分「檢查成功且無候選」和「根本沒有完成檢查」。

接口通過後，仍需保存版本相容範圍。廠商軟體升級、客戶 bin 規則變更或模型類別增加，都可能使舊接收端無法正確解讀，應在更新前跑共同樣本。

## 與倍利的連結

**已確認：** 官網有結果檔、正背面座標與工廠自動化相關功能描述，完整條件集中在[第 14 章](14-v5-product-evidence.md)。

**推論：** 這些入口值得分成「檔案內容」「座標語義」「設備通訊」三張驗收表，以免只驗證其中一層。

**待查：** 實際 schema、訊息清單、座標規則、斷線復原和跨系統共同測試。功能名稱存在不代表客戶整線已互通。

## 理解檢查

1. 為何測中心點不足以驗證正背面座標轉換？
2. 收到空結果檔，可以直接認定沒有缺陷嗎？
3. 為何不能只按晶圓 ID 刪除重複資料？
4. 有 SECS/GEM，能否推定 KLARF 可被對方讀取？

??? note "參考推理"
    1. 中心在多種旋轉或鏡射下不變，無法揭露方向錯誤。
    2. 不能；需確認作業完成、範圍有效且資料完整。
    3. 同一晶圓可有多站、重測與不同版本的合法紀錄。
    4. 不能；設備通訊與檔案內容是不同接口層。
