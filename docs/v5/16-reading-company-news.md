# 16　如何讀懂認證、AI 效益、新產品與擴產消息？

看到一則公司消息時，最有用的能力是把它翻成可確認的句子：誰在什麼時間，對哪個工件與任務，提供了什麼證據，還缺什麼才支持下一步結論。前 15 章的原理就是為了完成這個轉換。

以下六例依[第 14 章](14-v5-product-evidence.md)的官方來源與公開缺口設計。案例一至三、六取自公司公開敘述；案例四、五是**明示假設練習**，沒有暗示倍利發生了相應客戶事件。分析表是本書自建，不是投資評等。

## 案例一：取得多家 OSAT 認證

**原始主張與來源：** 官網有 V5 系統獲多家先進封裝 OSAT 認證的公司敘述，見[整機產品入口](https://www.v5.com.tw/tw/service/product/5)。

**支持到哪裡：** 公司公開宣稱系統有客戶資格進展。**缺失條件：** 客戶、型號、配置、站點、日期與驗收項目對照。因此可保留「公司稱系統取得相關認證」，不能自行換成具名客戶或某一產品性能。

**會改變判斷的觀察：** 客戶或雙方提供直接的型號與驗收對照，可讓結論收斂到那個範圍。若後續文件顯示僅供應商資格，則要改寫為資格層級；資格不等於每一款設備皆已量產採用。

## 案例二：檢出規格小到 0.18 μm

**原始主張與來源：** V5300 PRO 的簡報列有特定倍率、長寬與灰階條件，詳見[第 14 章檢出表的來源定位](14-v5-product-evidence.md)。

**支持到哪裡：** 這是一項帶條件的公司微觀檢出規格。**缺失條件：** 代表性缺陷、材料、照明、召回／假警報分母、掃描速度與量測方法。因此不能改寫成量測 accuracy，也不能直接判定比另一個產品的像素數字更強。

**會改變判斷的觀察：** 取得同工件與同品質要求的共同測試，可以比較該任務；若文件說明數字只對特定高對比樣本成立，就應把適用範圍縮回那些樣本。原理回顧：[光學](05-optics-and-imaging.md)與[計量](07-metrology-and-3d.md)。

## 案例三：ADC 節省大部分人力

**原始主張與來源：** 公司 4 月簡報提供 ADC 用戶端效益例，原數字與日期保留在[產品證據章](14-v5-product-evidence.md)。

**支持到哪裡：** 公司報告了案例效益，不能自動推廣到所有客戶。**缺失條件：** 原工作量、每類人工時間、抽查維護、低信心比例、觀測期間，以及最終品質。

**可保留結論：** 值得把 ADC 放進複判瓶頸的改善候選，再要求完整前後資料。**會改變判斷的觀察：** 若節省只計逐張看圖，總工時效益就需要扣回新增工作；若同時增加高風險漏放，便不能只以人力改善宣稱導入成功。重算方法見[第 08 章](08-adc-and-human-review.md)。

## 案例四：舊機升級成功，準備全面複製

**假設消息：** 某工廠一台既有光學設備改造後，自動找點比原先更快，因此計畫擴至其他同型號機台。這不是倍利已公告事件。

**已給證據：** 只有單台的找點時間改善。**缺失條件：** 原機差異、影像可用率、量測一致性、有效完成率、改造停機與維護責任。

**可保留結論：** 已有一個局部流程改善示例，可進入多機差異評估。不能直接認定全廠同效。**會改變判斷的觀察：** 代表性不同機況通過共同測試，可擴大適用範圍；若舊相機或平台造成失敗，則需要分組改造或另評估新機。原理回顧：[OM 升級](10-om-upgrade.md)。

## 案例五：Inline 導入，不增加節拍

**假設消息：** 某檢測模組可放入宿主原有等待窗口，供應商稱不影響產能。這不是倍利已公告的性能。

**已給證據：** 只知道有可用窗口與一個演示時序。**缺失條件：** 代表性工件、結果期限、最忙負載、長尾延遲、異常與維護停機。

**可保留結論：** 存在讓作業重疊的設計可能性；還不能證明持續運作的零節拍代價。**會改變判斷的觀察：** 在真實負載與例外條件下仍守住時序，才能提高信心；若偶爾逾時引發停機，就需按分布與可用率重算。原理回顧：[Inline](11-inline-aoi.md)與[驗收](13-throughput-and-acceptance.md)。

## 案例六：新 3D 方向，是否已成為成長產品？

**原始主張與來源：** 2026-08-19 簡報在未來產品發展中列出 3D，來源與定位見[產品證據章](14-v5-product-evidence.md)。

**支持到哪裡：** 公司公開發展方向。**缺失條件：** 具名產品、原理、Z 性能、工件窗口、可採購時間、出貨與驗收。不能把方向直接轉成現售能力或收入。

**會改變判斷的觀察：** 具名型錄能支持產品化進展；出貨文件能支持交付；客戶共同驗收能支持限定場景採用。不同證據更新不同欄位，不需一次跳到最終商業結論。若只有願景頁改版，仍維持方向層級。

## 擴產消息再加一條容量鏈

若日後有擴產公告，可沿「投資計畫 → 場地與人員 → 製造與測試瓶頸 → 可交付設備 → 客戶訂單與驗收」追問。新增面積不必然按比例增加產能：關鍵人員、關鍵零件、校正與出廠驗證都可能限制交付；有交付能力也不等於已有需求。

這是未來消息的教學框架，本書未以未查核的擴產數字推算倍利營收。若缺乏正式資料，就將每個箭頭列為假設，再指定需要什麼觀察來確認。

## 可以反覆填寫的消息分析表

| 欄位 | 填寫方式 |
|---|---|
| 原始消息 | 原始 URL、發布日、查閱日與版本，保留一句有限主張 |
| 主體與產品 | 公司、型號、配置；不知道就明寫未具名 |
| 工件與任務 | 材料、站點、檢出／量測／分類／交付 |
| 指標與分母 | 數值、單位、比較基線、樣本與期間 |
| 商業階段 | 方向、產品、驗證、交付、驗收等分開記 |
| 證據來源關係 | 公司自述、客戶資料、共同測試；轉載不另算獨立證據 |
| 可保留結論 | 只寫現有證據足以支持的範圍 |
| 替代解釋 | 版本差異、測試較容易、口徑改變或其他原因 |
| 更新觸發 | 哪份新資料會擴大、縮小或推翻目前結論 |

## 與倍利的連結

**已確認：** 本書保留產品、簡報版本與公開來源，讓讀者能自行返回檢查。

**推論：** 光學、AI、接口與整合是理解不同交付路線的共同語言；應用到消息時，重點是把缺的條件顯性化。

**待查：** [待查表](appendix-open-questions.md)列出的型號、驗收與商業口徑。沒有資料的地方保留具體問題，不以樂觀或悲觀故事填空。

## 理解檢查

1. 新聞轉載官網，同一主張出現兩次，為何不等於兩份獨立證據？
2. 若只取得新 3D 型錄，可以更新哪些結論、哪些仍不能更新？
3. 請用分析表重寫一句「有 AI 所以競爭力強」：至少指出工件、任務、品質與交付條件。

??? note "參考推理"
    1. 兩篇文字可能來自同一發布方，沒有新增測試或外部確認。
    2. 可更新具名產品與公開規格；出貨、客戶採用與收入仍需相應證據。
    3. 可改為「在某工件與候選集合上，模型在指定品質門檻下減少多少待判工作，且接口和維護已達要求」；未取得數據時維持待驗證假設。
