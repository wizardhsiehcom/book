# 04　聯盟合作，到底由誰交付？

## 開場問題：一站式服務，是否等於一家公司負責到底？

客戶面對一條先進封裝設備線，通常只想知道何時能運轉、何時能驗收；聯盟因此以「單一窗口、一站式服務」溝通很自然。然而窗口是對客溝通安排，不會自動回答誰設計、誰製造、誰簽約、誰到場安裝，也不會把多家法人變成單一法人。尤其在故障、變更或保固發生時，若無法指出責任與證據，所謂整合交付只是一句行銷語。

本章建立一張可供查核的責任地圖。它是交付分析框架，不是東捷或 G2C+ 已簽署的合約分工；實際 FAT、SAT 與接口控制可先回看[第 03 章](03-integration-acceptance.md)。

## 先看結構：把「合作」拆回七個可驗證的動詞

交付不是從聯盟標誌直接跳到出貨，而是依序追問：研發定義了什麼、製造了什麼、由誰報價簽約、誰把設備安裝到現場、誰接受驗收、誰在保固後維護。銷售與簽約須拆開，因為參展、介紹或擔任窗口，不當然是契約相對人；驗收也須與出貨拆開，因為送抵現場不等於客戶已接受。

| 階段 | 必須釐清的交付物 | 最小可查證問題 |
|---|---|---|
| 研發 | 規格、設計版次、接口與測試範圍 | 哪一法人對哪個模組的設計與變更負責？ |
| 製造 | 組裝紀錄、校正、序號與出廠測試 | 誰製造，誰保有品質紀錄？ |
| 銷售／簽約 | 報價範圍、PO、保固與責任條款 | 誰報價、誰簽字、誰認列收入？ |
| 安裝 | 現場條件、施工紀錄、啟動限制 | 誰進場、誰協調廠務與上下游？ |
| 驗收／出貨 | FAT、SAT、未結項與放行紀錄 | 何種條件下由誰接受何種範圍？ |
| 售後 | 保固、備品、服務紀錄與升版 | 故障第一響應與最終履約主體是誰？ |

## 輸入／操作／輸出：把宣傳語轉成責任鏈

**輸入**是設備範圍、各法人名稱、客戶需求、接口文件與可定位的公開聲明。**操作**不是猜測聯盟內部分工，而是把每項聲明放入上表，保留聲明的主體與階段；再要求每個交接點有可追溯文件。**輸出**是一份「已知責任、待確認責任、不得推定事項」清單，使專案可在未知道所有商業條款時先避免錯誤歸責。

例如，東捷稱參與先進封裝設備協作，並以自動化整合、模組化製造與快速量產支援協助設備導入及客戶驗證。[E3](appendix-sources.md#E3) 這可放入研發協作、製造支援與導入／驗證的**階段主張**；它沒有指出機型、客戶、合約或驗收結果，故不能輸出為「東捷交付某整線」。同理，盟友頁面所稱單一窗口，只支持聯盟的對外服務定位，不支持窗口法人、收入主體或連帶責任。[E1](appendix-sources.md#E1)

## 缺陷會長什麼樣子：責任空白會在異常時浮現

| 缺陷表象 | 常見混淆 | 應補的紀錄 |
|---|---|---|
| 模組已到廠卻無法串線 | 把出貨當作系統可驗收 | 供應範圍、現場接口、安裝與 SAT 邊界 |
| 改配方後品質漂移 | 不清楚設計變更與現場調機誰批准 | 版次、變更單、重測與放行人 |
| 客戶向窗口申訴卻久未排除 | 把窗口誤認為每一故障的履約人 | 服務 SLA、升級路徑、保固與備品責任 |
| 宣傳出現夥伴標誌 | 把聯展名單當作產品供應名單 | 型號、供應法人、製造地與契約附件 |

技術上的跨機台失效可依第 03 章以工件、控制、資料及放行追查；商務與 IP 問題則不可用工程推論補齊。誰擁有設計、背景 IP、共同開發成果與使用權，必須由合約或權利文件確認，本章不替任何聯盟成員分配。

## 如何檢查與控制：責任與證據要能逐列對上

下表故意把「未公開」保留為未公開。它不是否定合作，而是防止把各自的自述拼接成不存在的共同承諾。

| 項目 | 可定位的公開主張 | 可支持的保守結論 | 尚缺的責任／證據 |
|---|---|---|---|
| 研發 | 東捷稱有研發自主能力並參與設備協作。[E3](appendix-sources.md#E3) | 東捷自述參與協作。 | 模組 RACI、設計審查、IP 與成果歸屬。 |
| 製造 | 東捷稱具模組化製造與快速量產支援能力。[E3](appendix-sources.md#E3) | 是能力與支援定位。 | 實際製造機型、工廠、品質紀錄、產量。 |
| 銷售 | E2 為共同聯展預告；E1 稱一站式窗口。[E2](appendix-sources.md#E2) [E1](appendix-sources.md#E1) | 有公開活動與服務定位。 | 報價者、代理權、客戶、訂單與區域。 |
| 簽約 | 未見可核讀公開契約。 | 不可判定。 | 契約相對人、付款、保固、收入歸屬。 |
| 安裝 | 東捷稱協助加速設備導入。[E3](appendix-sources.md#E3) | 導入支援是其公開目標。 | 現場施工者、廠務責任、裝機紀錄。 |
| 驗收／出貨 | 未找到具名客戶、FAT／SAT 或出貨紀錄。 | 不可宣稱已驗收或出貨。 | 型號、接受準則、日期、結果及簽核。 |
| 售後 | 東捷提及自研發至維護的一站式優勢；盟友稱服務體系。[E3](appendix-sources.md#E3) [E1](appendix-sources.md#E1) | 有服務涵蓋性的對外主張。 | 保固法人、SLA、備品、實際履約紀錄。 |

控制方法是讓每一列都對應一位責任人、一份文件、一個版本與一個例外處理者。採購前應先確認「窗口」是否有權代表各供應商承諾；驗收前應以附件列出各模組範圍、缺陷歸因程序與未結項關閉權限。沒有這些資料時，分析結論必須停在公開主張，不能用聯盟品牌補足。

## 理解檢查

??? question "「單一窗口」能否直接寫成東捷是唯一簽約與收款法人？"
    不能。E1 只支持聯盟的服務定位，沒有列出窗口法人、授權範圍、契約相對人或收入歸屬；須以報價、合約或公司揭露另行確認。

??? question "夥伴與東捷共同出現在聯展，是否能把夥伴產品列為東捷自有產品？"
    不行。聯展僅能支持公開活動與共同展示／交流。自有產品必須有東捷的型號、產品文件或明確權利主張，不能憑標誌歸屬。

??? question "東捷稱協助客戶驗證，為何仍不能寫成已完成驗收？"
    驗證時程的協助是階段主張，不含客戶、機型、接受條件、結果與簽核。取得 FAT／SAT 或客戶確認前，兩者不可互換。

??? question "若整線缺陷源於接口，誰一定要負責？"
    公開資料不足以指定法人。應依合約供應範圍、ICD、變更紀錄與異常處置條款判定，而非依聯盟名稱或窗口稱號猜定。
