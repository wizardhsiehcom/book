# 程式如何在機器與網路上運作

<p class="lead">一批合成 AOI 圖片從來源交到接收端。程式還活著，畫面卻沒有進度；傳送函式回傳了，接收端仍不能說這張圖已經交付。</p>

你已經能追蹤一個程序裡的函式、輸入與輸出。這本書從那裡往下看：程序與執行緒誰在等誰、同一份圖在記憶體與檔案裡有幾份、位元組流要怎樣才算一筆訊息，以及逾時、取消和停止之後，哪些結果其實仍未知。

《從讀懂程式到能修改系統》負責語言層的值、生命週期與測試。《資料庫與資料正確性》負責交易、操作去重與未知提交。本書負責執行、通訊與資源模型。Linux 現場招式與 Docker 現場招式仍是症狀排查；Binary Hacks 是選讀。

## 從哪裡開始

- 不確定自己會不會看程序：從[全書地圖](00-map.md)與[程序](01-process.md)開始。第一個能帶走的東西是程序辨識紀錄：找到自己啟動的 worker、取得退出狀態、確認它已被回收。
- 檔案在，內容卻只寫了一半：讀[檔案](05-files-io.md)與[完成的層次](06-completion-durability.md)。
- 連線成功但圖沒到：讀[名稱與 port](07-address-port-dns.md)、[位元組流](08-tcp-stream.md)、[訊息契約](09-message-contract.md)。
- 要停機，帳上還有在途工作：讀[取消](15-cancellation-unknown.md)與[停止](17-shutdown.md)。

每頁先預測，再看模型與反例，最後才跑小實驗。題目的提示與解答分開，放在[提示](hints.md)與[解答](answers.md)。

## 實驗界線

實驗使用合成工作編號、自建暫存目錄，以及你自己啟動的程序。預設只走 loopback，不需要管理者權限。斷電、真跨機掉線、netem 與產線權限不在這次通過的範圍。環境、命令與未測項目寫在[驗證紀錄](verification.md)。

完整的影像交付與補傳工具不在這本書裡做完。讀完應能交出資料流圖、通訊契約、工作帳與一份依證據分類的故障說明。終點題在[練習](exercises.md)。
