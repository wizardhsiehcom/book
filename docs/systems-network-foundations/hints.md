# 提示

提示只標邊界，不給完整答案。

- **Q01.** 把標準輸出的一行，和父程序觀察到的退出狀態，排成兩欄。
- **Q02.** 分開「程序仍可被觀察」與「這段時間的 CPU 時間有沒有增加」。
- **Q03.** `id` 的文件定義是物件壽命內的身分。再問這兩個程序是否共享 heap。
- **Q04.** 看兩個函式是不是都讀過每一個 byte，以及計時裡包含了什麼。
- **Q05.** 讀者的接受條件裡有沒有「正式名稱存在」以外的檢查。
- **Q06.** 列出這次呼叫過的動作：flush、fsync、程序結束。再看有沒有斷電這一步。
- **Q07.** 名稱解析的輸出是一組位址。listener 是後來的另一個檢查。
- **Q08.** 先問定界規則在哪裡。11 這個數字要跟那條規則比，不跟 send 的回傳值比。
- **Q09.** 長度欄是契約的一部分。正文短於宣告長度就遇到結尾時，緩衝區裡還算完整嗎？
- **Q10.** 404 出現在回應列。連線錯誤發生時，通常還沒有這一行。
- **Q11.** 確認這次是預設建置，以及事件迴圈一次推進幾個 CPU 密集的 Task。
- **Q12.** 把兩次讀取的 snapshot 寫下來，再看寫回時有沒有用到最新的 value。
- **Q13.** 用提交、接受、拒絕、完成四個數對一次。佇列長度只是其中一個瞬間。
- **Q14.** 把三段的 0.15 加總，再和 0.20 比。剩餘預算是扣過的。
- **Q15.** 客戶端要有自己的收件證據。worker 的完成不會自動複製過去。
- **Q16.** 兩個檢查的名字不同。接工作前要看哪一個。
- **Q17.** 成功的停止要能把已接受的工作收成完成或明確未完成。強制終止後的 marker 另計。
- **Q18.** 總等待把 I/O、佇列與鎖加在一起。分段欄位不在時，分類器缺少輸入。
- **Q19.** 畫出容器的 network namespace，以及客戶端程序跑在邊界的哪一側。

## 終點題

先跑 `examples/station_skeleton.py`，對照 `fixtures/station-jobs.json` 裡每一筆的 `file`、`drop_reply` 與 `arrive`。半檔不要進入完成數。回覆遺失只改客戶端那一欄。停止之後才到的編號不要標成已接受。
