# 終點題：量測檔接收站

離開各章之後，用同一組規則看一個新情境。不要重建完整的交付產品。下面的開關都是合成的。

## 現場

兩個來源各交三筆工作，編號 `M-1` 到 `M-6`。接收端一次只能持有兩筆已接受但未完成的工作，滿了就拒絕。其中 `M-3` 的檔案只有標頭和前半段。`M-4` 的 worker 已經寫完結果，客戶端把回覆丟了。停止訊號到達時，`M-5` 已接受且尚未完成，`M-6` 還在來源端、接收端沒有接受。

起點是 [examples/station_skeleton.py](examples/station_skeleton.py)。開關在 [fixtures/station-jobs.json](fixtures/station-jobs.json)，半檔樣本是 [fixtures/measurements/M-3.bin](fixtures/measurements/M-3.bin)，其餘完整檔放在同一目錄。`drop_reply` 與 `arrive: during-stop` 分別打開回覆遺失和停止期間的在途工作。容量、半檔是否拒收、丟掉回覆時計入哪一格，是程式上方的三個常數。先跑通這組開關，再改一項契約，讓錯誤的實作在同一份輸入上失敗。

## 要交出來的東西

1. 一張資料與資源圖：程序、檔案路徑、socket、佇列各屬於誰。
2. 訊息契約：長度欄、編碼、上限、不完整時的錯誤。
3. 容量、總預算、停止三條政策，各用一句話寫死。
4. 六筆工作的帳。帳上的狀態要互斥：接受數等於完成、取消、未完成之和；提交數等於接受加拒絕。
5. 把 `M-3` 與 `M-4` 的故障分開說明，並各給一個會打穿錯誤實作的檢查。

## 判準

能解釋界線，並用程式把界線跑出來。整個腳本結束碼是 0，仍可能把半檔收進來，或把丟掉的回覆記成成功。那種 PASS 不算這題通過。
