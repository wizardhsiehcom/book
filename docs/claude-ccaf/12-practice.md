# 12｜18 題原創情境練習

題目由本書自行設計，**不是官方題庫、回憶題或等值模擬考**。六組情境各三題；每題標明單選或複選數量。建議先寫「限制 → 選擇 → 排除原因」，再展開解析。全對也不能換算成官方 scaled score。

## 情境一：活動訂位客服

助理可查票券與申請改期，實際改期前必須確認票券所有權。政策只寫同城市活動可改期。

### Q01｜單選；1.4、1.5

測試發現助理偶爾跳過所有權確認就呼叫改期。哪個修正最直接處理失敗原因？

- A. 在 prompt 加入三次「一定要先確認」。
- B. 改期工具執行前檢查可信驗證狀態與票券所有權。
- C. 改期完成後由另一個模型檢查。
- D. 所有客服問題都改成只准執行一次工具。

??? note "答案與逐項解析"
    **B。** 規則放在真正執行邊界，纔可阻擋不符條件的動作。A 仍是機率性的指引；C 發生在副作用之後；D 既沒有核實身分，也破壞需要多步調查的正常流程。回讀[執行約束](03-enforcement.md)。

### Q02｜複選，選兩項；5.2

哪兩種情況應直接進入人工判斷或接手流程？

- A. 使用者明確要求現在交人工。
- B. 使用者說「有點煩」，但只需補寄收據。
- C. 使用者要跨城市改期，而政策未涵蓋。
- D. 助理剛完成第一個查詢，還有第二個可用查詢。

??? note "答案與逐項解析"
    **A、C。** A 是明確偏好，C 是政策缺口。B 應先承認困擾並提供可做的解法，除非使用者要求人工；D 本身不代表無法取得進展。回讀[升級條件](09-context-reliability.md)。

### Q03｜單選；2.2、5.3

票券查詢逾時，程式卻回傳成功與空清單，助理告訴使用者「你沒有票券」。應先改哪裡？

- A. 換成更長的回覆模板。
- B. 把所有空清單都自動查十次。
- C. 要求模型沒有百分之百信心就拒答。
- D. 區分查詢失敗與成功但無資料，回傳可重試狀態。

??? note "答案與逐項解析"
    **D。** 問題是資料契約抹掉了未知狀態。A 不改變輸入資訊；B 把有效空結果也當故障；C 無法恢復被程式隱藏的錯誤。回讀[錯誤契約](04-tool-contracts.md)。

## 情境二：票券程式重構

團隊用 Claude Code 維護多套服務，測試檔分散在各 package。

### Q04｜單選；3.1

資深工程師的 Claude 都會使用共用 fixture，新成員卻常自建資料。規範目前放在資深工程師的 `~/.claude/CLAUDE.md`。先做什麼？

- A. 把團隊規範移到版控中的專案 CLAUDE.md。
- B. 要新成員延續資深工程師的聊天 session。
- C. 把規範放到 Git commit message 就好。
- D. 增加每輪輸出 token 上限。

??? note "答案與逐項解析"
    **A。** 規範應在團隊可取得的作用域。B 把共享知識綁到偶然的聊天歷史；C 不是每輪相關的專案指引；D 不處理缺少規範。回讀[設定位置](06-claude-code.md)。

### Q05｜單選；3.3

所有 `*.test.ts` 都需使用相同 fixture，但它們散在不同目錄。最合適的配置？

- A. 只在 `tests/CLAUDE.md` 寫規範。
- B. 讓每次 prompt 都列出全部測試路徑。
- C. 在 `.claude/rules/` 以 `paths: ["**/*.test.ts"]` 套用。
- D. 把規範加進每個工具描述。

??? note "答案與逐項解析"
    **C。** 規則依檔案模式匹配，跨目錄仍可適用。A 漏掉其他目錄；B 需要反覆手動維護；D 把程式規範混進不相關工具。回讀[path 規則](06-claude-code.md)。

### Q06｜單選；3.4、3.5

需求是把所有服務改成新的日期契約，有三種相容方案，還沒決定時區策略。下一步？

- A. 直接批量取代字串，測試失敗再說。
- B. 先探索使用範圍並澄清時區、相容性，建立遷移計畫。
- C. 把每個檔案交不同 agent 直接修改，最後拼接。
- D. 不管任務內容，只要超過一個檔案就拒絕執行。

??? note "答案與逐項解析"
    **B。** 未決的架構問題會影響整體正確性。A、C 提早固定尚未決定的語意；D 是武斷門檻，不能衡量實際歧義。回讀[規劃與迭代](06-claude-code.md)。

## 情境三：活動市場研究

協調者分派來源調查與統計分析，再交由整合者產出有引用的報告。

### Q07｜複選，選兩項；1.2、1.3

使用標準非 fork 子代理時，哪兩項可避免整合者缺乏必要資料？

- A. 在委派 prompt 明確放入前面取得的發現與來源位置。
- B. 只說「把上面的內容整理一下」。
- C. 假設共享工具清單代表共享完整對話。
- D. 定義交付 schema，要求保留 claim 與來源關係。

??? note "答案與逐項解析"
    **A、D。** A 傳遞必要上下文，D 保護交接後的證據關係。B 對看不到父對話者無效；C 混淆工具能力與對話內容。回讀[任務交接](02-orchestration.md)。

### Q08｜單選；5.6

兩份可信報告，一份統計去年的所有入場人次，一份統計今年第一季付費票券。數字不同，應如何整合？

- A. 選較大的數字，避免低估。
- B. 取平均得到比較穩定的估計。
- C. 保留來源與期間、口徑，確認可比性後才判斷是否矛盾。
- D. 因有差異，將兩份來源全部刪除。

??? note "答案與逐項解析"
    **C。** 期間和母體都不相同，不能直接當成同一量。A 任意挑值；B 平均沒有可解釋意義；D 丟掉可用資訊。回讀[來源與時間](09-context-reliability.md)。

### Q09｜單選；1.2、1.6

三個 worker 都查一般活動需求，無人查企業活動；報告卻聲稱涵蓋全市場。應如何修正？

- A. 增加一個只負責潤稿的 agent。
- B. 讓既有摘要更短。
- C. 要所有 worker 再查一次同樣問題。
- D. 由協調者重新劃分範圍，針對漏掉的族羣委派調查。

??? note "答案與逐項解析"
    **D。** 缺口源於拆工範圍。A 不能創造證據，B 可能再丟資訊，C 重複相同盲區。回讀[協調者責任](02-orchestration.md)。

## 情境四：開發者探索工具

助理需要理解陌生 repo，內建工具和 MCP 工具皆可用。

### Q10｜單選；2.5

你要找到所有呼叫 `reserve_seat` 的位置，應先用什麼？

- A. Grep 搜尋內容，再 Read 相關結果與 wrapper。
- B. Glob 搜尋 `reserve_seat`，即可找到所有呼叫。
- C. Write 產生一份可能的呼叫清單。
- D. 不篩選地把所有檔案一次載入。

??? note "答案與逐項解析"
    **A。** 函式使用是內容問題；若有別名還要繼續追蹤。B 只匹配路徑；C 是猜測；D 消耗大量上下文且不改善定位。回讀[內建工具](04-tool-contracts.md)。

### Q11｜單選；2.1、2.4

MCP 可以搜尋未簽出 repo 的文件，但 agent 一直用本地 Grep。工具描述只有「搜尋」。優先改什麼？

- A. 移除所有本地工具。
- B. 清楚描述遠端範圍、輸入與回傳資料，以及和 Grep 的差異。
- C. 每輪強制 MCP，不論任務需要。
- D. 先重寫 MCP server 的容器部署。

??? note "答案與逐項解析"
    **B。** 現象可由能力邊界不清解釋，應先驗證這個原因。A 丟掉合理能力；C 不適用本地需求；D 無證據顯示部署有問題。回讀[MCP 可發現性](05-mcp.md)。

### Q12｜複選，選兩項；1.7、5.4

昨天調查中斷，今天部分程式已修改。哪兩項有助於可靠恢復？

- A. 把昨天所有結論直接標成現在仍正確。
- B. 只靠「請繼續」，不提供任何檔案資訊。
- C. 用 manifest 找回已完成、部分完成與待做工作的結果位置。
- D. 注入修改資訊，對受影響的舊結論重新分析。

??? note "答案與逐項解析"
    **C、D。** 恢復既需要知道工作進度，也需要檢查資料是否過期。A、B 都無法處理今日變更。回讀[可恢復狀態](09-context-reliability.md)。

## 情境五：CI 的程式審查

每次 PR 更新會呼叫 Claude Code，開發者只希望看到具體、未解決的問題。

### Q13｜單選；3.6

CI 一直等待互動輸入。應先使用哪個有文件記載的執行方式？

- A. 隨意設定 `CLAUDE_NO_QUESTIONS=1`。
- B. 把 prompt 重複送三次。
- C. 用 `claude -p` 執行非互動請求。
- D. 把所有程式碼放入 CLAUDE.md。

??? note "答案與逐項解析"
    **C。** `-p`／`--print` 是考綱指定的非互動方式。A 在本情境沒有文件依據；B 不改互動模式；D 混淆專案指引與輸入資料。回讀[CI 執行](07-ci-review.md)。

### Q14｜單選；4.1、4.2

模型反覆報告被程式前置檢查擋掉的空值錯誤。如何優先降低這類誤報？

- A. 明定「必須有可到達的失敗路徑」，加上有／無前置檢查的對照例。
- B. 只寫「請更有信心」。
- C. 刪除所有邊界情況的測試。
- D. 每條 finding 都自動接受。

??? note "答案與逐項解析"
    **A。** 判準與相近正反例直接界定決策邊界。B 不可操作；C 使驗證變弱；D 使誤報進入工作流程。回讀[few-shot 判準](07-ci-review.md)。

### Q15｜單選；3.6、4.6

生成者的自審漏掉跨檔介面不一致。哪種組合最貼近問題？

- A. 只增加同一 session 的自我鼓勵。
- B. 只跑逐檔審查，不看檔案關係。
- C. 讓每次 review 都重新發布全部舊留言。
- D. 獨立審查上下文，加局部 pass 與跨檔整合 pass。

??? note "答案與逐項解析"
    **D。** 同時處理生成偏差與跨檔依賴。A 不增加獨立視角；B 漏掉整合缺陷；C 製造重複噪音。回讀[多 pass 架構](07-ci-review.md)。

## 情境六：大量活動文件抽取

服務抽取不同格式的活動報價，部分缺稅號，部分總額與明細不一致。

### Q16｜複選，選兩項；4.3、4.4

哪些設計能同時容納來源缺失與來源矛盾？

- A. 稅號缺失時填入隨機但格式正確的字串。
- B. 稅號欄位允許 null，並定義缺失的後續流程。
- C. 保存原文總額與計算總額，額外做語意驗證。
- D. 只要 strict schema 通過就覆蓋所有資料品質狀態。

??? note "答案與逐項解析"
    **B、C。** B 表達未知，C 保留矛盾。A 虛構資訊；D 混淆格式與正確性。回讀[輸出驗證](08-structured-output.md)。

### Q17｜單選；4.5

一項任務阻塞使用者當下的報價確認；另一項做每週歷史文件分析且可等待一天。批次怎麼分配？

- A. 兩項都批次，因較便宜必然最好。
- B. 每週分析可評估批次；互動確認保留符合即時需求的流程。
- C. 兩項永遠不能批次，因結果可能不同順序。
- D. 使用批次後用回傳位置對應文件，不需要 ID。

??? note "答案與逐項解析"
    **B。** 選擇依延遲容忍度。A 忽略阻塞需求；C 可用 custom_id 對應；D 在順序不同時會錯配。仍須核對實際期限與失敗預算。回讀[批次窗口](10-batch-human-review.md)。

### Q18｜單選；5.5

總準確率很高，但特殊格式樣本少、錯誤多。如何決定是否減少人工？

- A. 只看總平均，超過內定數值就全自動。
- B. 只抽低信心項，永遠不看高信心項。
- C. 按文件與欄位評估、用標註集校準，高信心項仍分層抽查。
- D. 讓模型自行宣佈已達生產品質。

??? note "答案與逐項解析"
    **C。** 可看到被平均掩蓋的弱項，也可偵測高信心錯誤。A 掩蓋分佈差異；B 形成抽樣盲區；D 不是外部驗證。回讀[人工與校準](10-batch-human-review.md)。

## 訂正方法

每題記錄選項、漏看的情境限制、錯誤假設、應回讀章節與一個可驗證實驗。例如 Q03 答錯，應寫「我把成功的空結果與取不到資料視為相同」，再去[Lab 1](11-labs.md)分別測兩者。不要只背正確字母。

回到[考綱地圖](00-exam-map.md)標記仍無法解釋的任務；下一輪先修補依賴觀念，再重做改寫後的情境。
