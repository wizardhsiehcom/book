# 09｜上下文可靠性：摘要後仍能追到事實

**考綱：5.1–5.4、5.6。** 本章延續[分工](02-orchestration.md)與[結構化輸出](08-structured-output.md)，目標是讓長任務在摘要、交接與失敗後仍可恢復。

## 先分出不可模糊化的資訊

「客戶買了幾張票，想近期改期」是順暢的摘要，卻丟失票券 ID、張數、指定日期和承諾。這些交易事實應存於獨立 case facts，必要時每輪加入上下文；敘事摘要負責來龍去脈，不能取代精確值。[官方考綱 §6，5.1](appendix-sources.md)

```json
{
  "case_id": "CASE-18",
  "ticket_ids": ["T-041", "T-042"],
  "requested_date": "2026-10-08",
  "customer_expectation": "兩張票必須在同一場次",
  "confirmed_actions": [],
  "pending": ["查目標場次容量", "確認跨城市政策"],
  "source_revision": "fixture-v1"
}
```

上述欄位是本書的狀態設計範例。case facts 本身也要更新：若使用者改了日期，不能同時保留兩個不標時間的「最終要求」。可以記錄舊值與被取代時間，但當前有效值必須清楚。

## 修剪工具輸出，保留判斷依據

一次票券查詢也許含付款、促銷、場館、通知與分析欄位，改期只需要其中幾項。前置 adapter 可保留必要欄位、來源和錯誤狀態，減少上下文負擔。不要把 `policy_version` 或 `isError` 當噪音刪掉，否則後續可能用錯政策或把失敗當成功。

長輸入可把關鍵發現與未決問題放前面，再用明確分節整理詳細證據，減少中段資訊被忽略的風險。這不保證「放最前面就一定記得」，仍需要具體檢查重要資訊是否在最終決策中被正確使用。[官方考綱 §6，5.1](appendix-sources.md)

## Scratchpad 與 manifest 的分工

Scratchpad 存工作發現；manifest 存「有哪些工作狀態、在哪裡、是否完成」。恢復時協調者先讀 manifest，再載入必要結果。

```json
{
  "revision": "fixture-v1",
  "tasks": [
    {"id": "capacity", "state": "done", "result_path": "state/capacity.json"},
    {"id": "policy", "state": "partial", "result_path": "state/policy.json"}
  ],
  "next_step": "補查跨城市改期條文"
}
```

這不是自動化魔法：程序重啟後仍要驗證路徑、來源版本與狀態新鮮度。若 repo 已變更，只能把舊發現當成重查線索。`/compact` 可以縮減長對話，但關鍵結論仍應有可追溯的位置。[官方考綱 §6，5.4](appendix-sources.md)

## 不要把失敗隱藏在漂亮報告裡

worker 查活動政策時逾時，已完成的場地資料仍可交付。回傳應包含 failure type、嘗試的查詢、重試紀錄、部分成果及可行替代來源。coordinator 才能決定重試、換來源或在報告中標記缺口。

`findings: []` 若沒有狀態，無法分辨「成功但沒有發現」與「根本沒查到」。兩者的結論強度完全不同。對單一失敗立刻丟棄所有成果也不合理；可以保留可用成果，但要標明不足以支持哪些結論。[官方考綱 §6，5.3](appendix-sources.md)

## 升級處理依條件，不能只看情緒

| 情況 | 合理行動 |
|---|---|
| 使用者明確要求人工 | 立即走人工接手流程 |
| 政策未涵蓋請求 | 不自行補造政策，升級判斷 |
| 多個身分符合查詢 | 詢問額外識別資料 |
| 無法取得進展 | 帶著嘗試與缺口交接 |
| 使用者不滿但未要求人工，且問題可處理 | 承認問題，提供具體解法 |

模型說自己有 99% 信心，不能取代身分核實；使用者生氣也不等於一定超出能力。明確要求人工時，不應先強迫完成一輪自助調查。[官方考綱 §6，5.2](appendix-sources.md)

## 每項主張帶著自己的來源

來源鏈不只是報告末尾列幾個網址。每個 claim 需對到來源、位置、資料涵蓋期間與必要片段。若一份資料是去年全年、另一份是今年第一季，數字不同未必矛盾；若同期間與同定義仍不同，就保留兩值與方法差異，不能隨意取平均。

本書原創練習：A 報告說「年度入場人次 12 萬」，B 說「付費票券 8 萬」。兩者一個可能含免費入場、一個只計付費；在定義未確認前，不可寫成「來源不一致，估計 10 萬」。整合者應先對齊單位、期間與母體，再決定是否可以比較。[官方考綱 §6，5.6](appendix-sources.md)

**自測：** 報告附了十個來源但無法知道哪個支持「已符合政策」。這算可追溯嗎？不算；需補 claim-source mapping，不能用參考文獻數量代替證據關係。
