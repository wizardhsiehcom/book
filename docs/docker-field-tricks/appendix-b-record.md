## 怎樣保留足夠的證據

看輸出之前先寫預期。例如第 06 章要測的是第一筆日誌出現的時刻，就不能只在退出後數行數；第 13 章要測清理，就不能只量 stop 花多久。當你換了觀察量，可能已經換了問題。

對預期失敗，記錄具體錯誤。缺檔、daemon 不可用與語法錯誤都可能非零退出，但只會有其中一種符合你的假設。需要重複的效能與競態實驗，保留每輪值及順序，讓中位數也能回到原始資料核對。

若用 pipe 把輸出送進 `tee`，記得管線尾端成功不一定代表前面的命令成功；Bash 可用 `set -o pipefail` 或立即保存 `PIPESTATUS`。不要為了留下 log，反而吃掉最重要的失敗訊號。（此為 Bash 管線行為；使用本機 Bash 可自行對照 `false | cat` 的退出碼。）
