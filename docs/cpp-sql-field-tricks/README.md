# C++ 接上 SQL 之後

## 那些有點土，卻能解決問題的工程技巧

你已經能看懂 C++、build、下 breakpoint。接手一套真正會讀寫 SQL 的程式，卻發現難的不是語法：入口要等設備，重跑會動資料，只有一個 `false`，工具查詢很快，程式就是卡住。旁邊的老手改兩行就知道往哪裡查，你卻不知道他為什麼先動那裡。

這本書把那些省略的推理補回來。從確認正在跑的 exe，到固定一筆輸入、手動 `test_mode`、保存中間值、分開看 API 回傳與真正寫入，再走到鎖等待和失敗後能不能重跑。不是要把每個小招都做成平台，而是知道它省下什麼、把成本移到哪裡。

## 先拿到第一個小成果

先讀[開場：今天接手的是哪一支程式？](00-workday.md)。跟著工作 1 走過「取得輸入 → 計算 → 保存結果」，先分清 C++ 記憶體裡的值和資料庫裡的值。

再到[實驗準備第一層](appendix-lab.md#first-run)編譯，依序讀第 01–04 章。不啟動資料庫，先核對執行檔；接著在一支約 30 行的小程式裡，親手把手動輸入換成固定值、加入 `test_mode`，最後才使用整理好的重播工具。這四章不用先懂 ODBC。

每章把「現在看到什麼」和「為什麼下一步這樣做」接起來。程式片段會說明是範例原碼、需要你實際替換的區塊，還是只用來說明既有專案的示意；不要把三者混著貼進同一支程式。

## 書的範圍與誠實界線

實驗載體是自造的工作清單：`JobRow → process_job → Result → 寫回／通知意圖`。不依賴任何私有 repo、設備或 GPU。原始碼與小腳本可直接下載，不需要讀者先搭起完整服務。

本版以 Windows x64、C++17、ODBC Driver 17 和 Docker SQL Server 2017 實測。選擇既有映像是為了把環境固定下來，不是新的產品選型建議。資料庫只在專用容器放合成資料，與讀者正式庫無關。實際版本與限制見[驗證紀錄](appendix-validation.md)。

有些章節提供實測小案例；第 09、14、17 章也包含需要你帶回自己專案的判讀流程，不冒稱所有引擎、driver、工具與部署都已驗過。交易提交回應遺失只做應用層故障模型，沒有假裝重現真實網路斷線。

第一次閱讀沿[全書地圖](00-map.md)走；已經卡住時，直接查症狀。每章結尾有一個變化題，答案分開折疊：能說出下一個觀察位置，比背下命令更重要。
