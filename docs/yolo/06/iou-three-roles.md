# 把 IoU、信心門檻與 NMS 拆成三套規則

IoU（Intersection over Union）只描述兩個框重疊多少，不描述分數高低。公式是交集面積除以聯集面積：分子是重疊區，分母是兩個框蓋住的全部面積。聯集可用「兩框面積相加再減掉交集」得到，避免把重疊區算兩次。confidence 不進入分子，也不進入分母；把它乘進 IoU 會把幾何重疊和分類分數混成一個無法對照的數。

用一組人造框把每一步算完。預測框 \(A=[0,0,10,10]\)，寬 10、高 10，面積 100。標註框 \(B=[5,5,15,15]\)，面積同樣 100。交集是 \([5,5,10,10]\)，寬 5、高 5，面積 25。聯集 \(=100+100-25=175\)，因此 \(\mathrm{IoU}=25/175=1/7\approx 0.1429\)。若把 \(B\) 改成 \([2,2,8,8]\)（面積 36），交集就是這個較小框本身，面積 36，聯集 \(=100+36-36=100\)，IoU 變成 0.36。同一個預測框對兩個標註得到兩個完全不同的 IoU；計算過程沒有任何一步用到分數。這個例子只用來固定公式，不是某次真實推論的輸出。

實務上常把三道不同的門檻都叫成「IoU」或「過濾」，必須分開說。

第一道是信心門檻，它根本不是 IoU。它只看分類或物件分數，低於下限的候選直接丟掉，框重不重疊都不會被這一步救回來。細節見 [confidence-cutoff.md](confidence-cutoff.md)。公開的 Ultralytics Predict / Val 文件把 `conf` 寫成候選的分數地板；這一步與幾何重疊無關。

第二道是 NMS 的 IoU。它用在同一類裡：高分框壓制與自己重疊過高的低分框，目的是減少同一物體被報多次。同一套文件裡的 `iou` 參數指的就是這道 NMS 重疊門檻，不是評估時把預測配到標註的那個門檻。推論常見流程是先用 `conf` 預過濾，再跑 NMS；不要寫成「一定先 NMS、再濾分數」。順序反過來會改變留下哪些框，因為 NMS 的勝者取決於當下還在的候選集合：先丟掉一個中等分數但位置更好的框，後面的抑制結果就會不同。

第三道是評估匹配 IoU。它把留下的預測配到標註，用來定義 TP、FP、FN。COCO bbox 常用一組門檻 0.50:0.05:0.95：從 0.50 到 0.95、步長 0.05，每個門檻各算一次再平均。匹配規則變嚴，報表數字通常變差，但權重沒變。這與偵測頭有沒有學好是兩件事，見 [tp-fp-fn.md](tp-fp-fn.md)。

訓練時的正負樣本指派，更不一定是「IoU 大於某固定值就算正」。有的流程用分類分數與 IoU 的聯合度量，或對每個標註只取 top-k 個預測，把正樣本名額分給少數候選。不要假設訓練指派、NMS、評估匹配共用同一個門檻，也不要假設一定存在一條全庫通用的 IoU 切分線。看到訓練程式裡出現重疊項，先問它是在指派、在抑制，還是在算指標。

還有 NMS-free 例外。Ultralytics YOLO26 的公開文件寫明可選 `nms=False`：一對一頭、不做 NMS。此時沒有「NMS IoU」這道閘，但仍可能先濾分數，評估匹配 IoU 也還在。看到重複框時，先確認是不是關了 NMS，而不是先怪 `iou` 設錯。

失敗模式裡有兩條特別容易誤判。第一，提高 `conf` 並不保證 precision 單調上升。兩個高分框都對準同一個物體時，若 NMS 沒壓掉其中一個，評估會把一個算 TP、另一個算 FP；濾掉較低但仍過線的那一個，precision 可能升，但若濾掉的是唯一對得上的框，recall 掉、precision 也不一定更好。第二，把評估 IoU 從 0.50 改成 0.75，或把 NMS `iou` 調寬調窄，報表會動，這是規則在變，不是模型變好。改匹配規則不能寫進「這次訓練比較成功」。

除錯時可用下表當檢查順序。每一格都是優先假設，要用實際框座標與分數核對，不能當成因果證明。

| 觀察 | 優先核對 | 不要直接當成 |
|------|----------|--------------|
| 分數高、IoU 低 | 框偏了，或評估匹配門檻過嚴 | 分類頭壞掉 |
| 分數低、IoU 高 | 被 `conf` 預過濾 | NMS 刪了正確框 |
| 同一物體兩個框 | NMS `iou` 過寬，或 `nms=False` | 標註一定重複 |
| 只改 `iou` 分數大變 | 改到的是 NMS 或評估匹配 | 訓練比較成功 |

驗收標準如下。能手算一組框的交集、聯集與 IoU，且不把 confidence 乘進公式。能分開說：`conf` 是分數地板；predict / val 的 `iou` 是 NMS；COCO 的 0.50:0.05:0.95 是評估匹配。能指出推論常先濾分數再 NMS，以及 YOLO26 可關 NMS。不把改匹配規則說成模型改進。能說明訓練指派可能是聯合度量或 top-k，不是全庫共用的單一 IoU 閾值。

來源（文件會改，本文於 2026-09-08 核對公開頁，不寫死預設數值）：[Predict](https://docs.ultralytics.com/modes/predict/) 與 [Val](https://docs.ultralytics.com/modes/val/) 將 `iou` 作為 NMS、`conf` 作為候選下限；[YOLO26](https://docs.ultralytics.com/models/yolo26/) 可選 `nms=False` 一對一；COCO bbox 評估 IoU 為 0.50:0.05:0.95。
