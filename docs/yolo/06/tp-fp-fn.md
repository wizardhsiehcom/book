# 單頁 TP／FP／FN 框匹配：分數排序貪婪最高未配對 IoU

目標偵測的對錯，不能只看框有沒有畫出來，必須把同一張圖、同一類別的預測框與標註框配對之後，才分得出真正例（TP）、假正例（FP）與假反例（FN）。標準框度量幾乎沒有可自然計數的真反例（TN）：背景不是一顆顆可以列舉的框，精確率與召回率才是主軸。這並不表示偵測準確度無法定義，只表示那種把 TN 放進分母的準確度公式，在這裡沒有自然對應物。本頁用一條可手算的玩具規則，說明分數排序如何把重複偵測打成 FP；它不是完整 COCO 評估器，也不是所有推論引擎的匹配實作。

先固定四條假設：無 crowd、無 ignore、同一張影像且同一類別、maxDets 未截斷。流程是預測依分數由高到低排序；每個預測只能配一個尚未被佔用的標註；在仍超過 IoU 門檻（本頁用 0.50）的候選中，取最高 IoU。分數較高者先佔坑，後面即使對同一標註的 IoU 更大也不能再當 TP，重複框因此變成 FP。IoU 的門檻、重疊幾何與排序角色見 [iou-three-roles.md](iou-three-roles.md)；這份 TP／FP 序列如何走進精確率—召回率曲線見 [precision-recall.md](precision-recall.md)。

合成例如下。門檻為 IoU ≥ 0.50。標註兩個：G1、G2。四個預測已按分數排序：

| 預測 | 分數 | 對 G1 的 IoU | 對 G2 的 IoU | 決策 |
|------|------|--------------|--------------|------|
| P1 | 0.95 | 0.82 | 0.10 | 配 G1 → TP |
| P2 | 0.88 | 0.71 | 0.08 | G1 已配 → FP（重複偵測） |
| P3 | 0.70 | 0.12 | 0.61 | 配 G2 → TP |
| P4 | 0.40 | 0.20 | 0.15 | 皆低於門檻 → FP |

計數為 TP = 2、FP = 2、FN = 0，精確率 2/4 = 0.50，召回率 2/2 = 1.00。P2 對 G1 的 IoU 並不低，但 G1 已被更高分的 P1 佔用，故記 FP。這不是模型沒看見物體，而是同一物體被報了兩次。若把 P3 對 G2 的 IoU 改成 0.40，P3 也變 FP，G2 無人認領，FN = 1。漏檢與定位偏差在計數上都是「沒配上的標註」，單看 FN 分不出來。若先看低分框再看高分框，同一張表會得到完全不同的 TP 集合，這正是必須先排序再貪婪的原因。

失效首先來自排序：校準差或同類競爭會讓高分錯框先佔走標註，真框變成 FP。門檻過嚴會把略偏的定位打成 FP 並製造 FN；過寬則把鄰近同類誤配成 TP。若評估時截斷 maxDets，低分但本可匹配的框進不了表，召回率被人為壓低。面積區間會先過濾標註與偵測，連分母都變。推論引擎可能用匈牙利算法、NMS 後再配、或允許一對多，匹配結果不必與本頁玩具規則相同，不可把這條規則普遍化成所有評估器或部署時的對錯判定。

COCO 的 crowd／ignore 也不是「框落在某區域內就整筆忽略」。公開評估器 `evaluateImg`（見 [cocoeval.py](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py)）會對偵測依分數排序，再貪婪匹配，並套 crowd／ignore 規則；有效匹配優先，面積範圍、maxDets 與 IoU 門檻都會改變一筆預測是 TP 還是 FP、一筆標註是否進入 FN。

驗收標準是：給定同分組（圖＋類）的分數排序與 IoU 矩陣，能手工複核每個預測的 TP／FP 與未配標註的 FN；重複偵測不得雙計 TP；能指出本規則與完整 COCO 在 crowd／ignore／maxDets 上的差異，且不把 TN 硬塞進框度量。
