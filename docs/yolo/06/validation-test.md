# Validation 選閾值，Test 只准看最後一次

閾值是用資料做的決策。誰用來 **挑選** cutoff，誰就不能再自稱無偏的最終成績。很多人只切模型權重，卻把閾值留到 test 上掃，等於在考卷上練習後再交卷。作業點怎麼掃見 [confidence-cutoff.md](confidence-cutoff.md)；AP 為什麼不能代替那個點見 [ap-map.md](ap-map.md)。

## 時間隔離、來源隔離

**時間**：週一到週四訓練，週五當 val 選 cutoff，下週一當 test。不要把同一支攝影機連續十秒切成三份——相鄰幀幾乎是複本，val 上的「最好閾值」會偷到 test 的資訊。看起來三份互斥，統計上卻高度相依。

**來源**：廠區 A 的燈、鏡頭、物料不能代表廠區 B。把多來源混在一起再隨機 shuffle，看起來有 val／test，其實是同一分布抽兩次。要讓 test 模擬「明天才會看到的資料」，而不是「同一小時裡沒抽到的那幾張」。

合成：同一隻貓 30 幀，分數都在 0.48–0.52。10 幀進 val、10 幀進 test，val 選 0.50 在 test 上會漂亮得不合理。改成上午／下午或鏡頭 1／鏡頭 2，cutoff 可能從 0.50 變成 0.72。你要提前看到的是後面這種不穩，不是前面那種假穩。稀有類在 val 上的 max-F1 同樣會因兩三張圖跳動，這正是不能讓 test 再參與選點的原因。

## 允許的流程

1. 只在 **validation** 上掃 cutoff、算事件級成本、按類別／場景挑點。
2. 把選定 cutoff **凍結**。
3. **test 只跑一次** 該點（以及事先登記的 AP），確認有沒有崩。
4. 若你因 test 把 0.45 改成 0.60，這次 test 作廢，必須換從未看過的 hold-out，或等下一週新資料。

YOLO 驗證摘要的 max-F1 同樣只能當 val 參考，不能在 test 上重新取 max-F1 再寫進報告。公開摘要見 [confidence-cutoff.md](confidence-cutoff.md)。框級計數仍須先聚成事件，否則 test 上的「每小時誤報」是假的。

## 資料漂移就要重驗

燈管換了、季節變了、新產品上線，絕對分數會平移。舊 cutoff 的事件級誤報可能從每小時兩次變成二十次，而 AP 幾乎不動——排序仍對，校準卻漂了。這正是 AP 取代不了作業點的原因。重驗時：只在新 val 上重掃，再用時間上更新、且仍隔離的 test 確認一次。舊 test 數字不得繼續當合格證明。

## 失敗模式與驗收

失敗：在 test 上掃閾值並把最好點寫進報告；用隨機切分代替時間／來源切分；漂移後只看 mAP 沒掉就繼續用舊 cutoff；把 ignore／crowd 協定當成 test 上可臨時改的開關。

驗收：書面記錄哪一份 split 選 cutoff、哪一份只確認一次；test 指標在凍結前登記（作業點成本 + AP），不得事後加指標；漂移觸發重驗時，新 test 與選點用的 val 仍然隔離。
