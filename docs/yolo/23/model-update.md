# C04 配套：模型更新的閱讀與驗收路線

這條路線把本書既有資料、訓練與部署內容接成「收到新資料 → 候選模型 → 評估 → 發布 → 恢復」的工作台。它是 C04 的原理閱讀入口與驗收設計；C04 的程式、固定環境及真模型執行證據須由課程另行提供。

## 一條合成時間線

1. 目前 `r1` 已通過載入與健康檢查；保存其完整套件。
2. 新資料 `ds2` 經切分與健檢，建立 `job2`，以 `attempt1` 訓練 `run2`。
3. 模型完成目錄已發布，任務狀態尚未更新，程序中斷。
4. 新程序確認舊執行者停止，查核完成清冊，補記成功並進入評估；不重複訓練。
5. 第一次候選被評估拒絕，發布入口拒絕它，r1 持續服務。
6. 另一次依規則產生的合格候選建立 r2；切換後若模型載入失敗，停止候選並恢復完整 r1，取得新的 ready。

這是紙上演練。第 5、6 步可以用受控評估／載入替身分別製造故障；課程的完整成功路徑仍須使用真模型。若因測試集結果改模型，依既有評估紀律另備未用過的 hold-out，不能拿故障演練當成反覆調 test 的理由。

## 實作時要完成的故障矩陣

先約定每個案例的啟動、工作與清理期限。用明確的階段確認訊號停在指定邊界；不能只睡幾秒就猜測已抵達。測試只操作自己的暫存目錄與程序，結束時核對殘留。

| 案例 | 注入點／輸入 | 通過條件 |
|---|---|---|
| 正常鏈 | 固定真資料與真模型 | 可從發布版本追到原始輸入與執行，實際推論成功 |
| 重送 | 相同 job ID、相同完整意圖 | 回傳已有工作／結果；沒有多開執行 |
| 衝突 | 相同 ID、不同資料或設定 | 明確拒絕，原工作不變 |
| 半產物 | 寫暫存模型時停止程序 | 下游不讀殘檔；恢復策略與新嘗試可查 |
| 產物先完成 | 正式完成目錄建立後、狀態提交前停止 | 新程序查核後補記，沒有重跑訓練 |
| 品質拒絕 | 已凍結門檻下的劣化結果 | 評估成功但候選拒絕；直接呼叫發布入口亦不能繞過 |
| 證據錯配 | 報告來自另一模型，或必要指標缺失 | 拒絕發布，不能只信 passed 欄位 |
| 載入失敗 | 候選檔完整但載入器回報錯誤 | 無 activated；完整回滾並取得前版的新 ready |
| 舊 ready | 保留已退出 session 的 ready 檔 | 不能當成目前服務健康；重新探測 |
| 成功回應遺失 | activated 已保存但呼叫端未收到 | 同 activation 查核結果，不重複切換 |
| 回滾也失敗 | 前版完整性檢查失敗 | 明示 recovery_failed，不宣稱恢復服務 |

每列保存：輸入與版本、注入邊界、故障前後持久紀錄、實際程序身分、輸出摘要、預期與實際結果、清理結果。標明是真模型、合成資料或替身；替身測試不能替代真模型的載入與數值驗收。

## 本書現有可執行檢查的邊界

[manifest_check.py](manifest_check.py) 驗完整／篡改／缺檔；[compare_detections.py](../20/compare_detections.py) 驗匯出結果比對。它們可沿用，但沒有涵蓋本頁的任務恢復、發布狀態或真服務回滾。

E02 本輪交付的是閱讀內容與故障判準；上表是課程待實作的驗收要求，沒有把紙上時間線或文件建置成功算成整條鏈通過。

## 無提示遷移題

把偵測任務換成小型影像分類，新增「每個必要類別召回皆達標」的發布條件。自行列出必須改動與可以沿用的紀錄，並設計一次拒絕發布與一次載入失敗。

判準：模型輸出與評估指標確實改成分類契約；資料／模型／評估／發布關係可追溯；重送及恢復身分規則仍成立；發布入口真正執行新條件。只換頁面標題或沿用偵測 AP 當分類驗收不通過。
