## 工程交付建議

建議負責人在交付前整理 **Release inventory**（清冊），依資產與使用情境記錄：

| 欄位 | 要求 |
| --- | --- |
| 資產 | 程式 commit、wheel、權重檔、資料集快照、容器映像 |
| 識別 | 版本字串、檔名、**SHA-256**、上游公開 URL（含憑證或簽章的 URL 須遮罩） |
| 授權標示 | 該資產附帶的 SPDX／LICENSE 原文路徑 |
| 網路／散布 | 是否對外 HTTP 推論、是否散布二進位、是否改 GPL／AGPL 涵蓋碼 |
| 決策 | 走 AGPL 合規（含源碼提供流程）**或**已採購的企業授權編號 **或**停用該資產 |
| 資料 | 訓練／標註資料來源、同意紀錄、留存與刪除政策（依管轄地，**不虛構期限**） |

依清冊找出尚未確認的條款與負責人，再決定交付條件。

## 憑證、日誌與資料處理

- 金鑰、權杖、簽署 URL **只放環境變數或密鑰庫**，禁止寫進 repo、命令列歷史可複製的明文參數、以及**任何 log**（請求 URL 中的憑證、權杖與簽章須遮罩）。
- 最小權限：推論行程只讀權重與輸入目錄；輸出目錄可寫；禁止雲端管理員憑證進容器。
- 傳輸與靜態加密、存取稽核依資安基線；**留存與刪除政策依資料管轄地與合約**，本書不發明截止日期。
- 採購／標註資料：保存來源、授權範圍、可否再訓練、可否出境；處理紀錄與刪除證明由清冊指定的負責人追蹤。

**合規動作（工程，非法務結論）：** 對外網路服務若可能觸發 AGPL 源碼提供，應依**該次**程式、權重、資料集、依賴版本與實際條款判斷；必要時取得法律專業意見，再選擇符合條款的開源或企業授權方案。
