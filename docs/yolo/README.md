# YOLO 工程：從任務到上線

這本書帶你把 YOLO 物件偵測模型接成可驗收的系統：先確定要找什麼、結果怎麼用，再準備資料、訓練、評估，最後部署與維護。適合已能執行簡單程式、準備做第一個視覺專案的讀者。

全書使用「契約」一詞，指的是**各階段事先約定的輸入、輸出與通過條件**。例如，模型回傳一個框時，下游必須知道座標是相對於原圖，還是縮放後的圖。把條件寫清楚，才知道錯誤出在哪一段。

第一次閱讀先完成工程主線。神經網路架構、框的位置如何學得與解碼，以及如何移除重複框，放在第 08–12 章選讀；DFL、NMS 等名稱會在對應頁面說明，不必先背。

文中出現的 CLI、GPU 型號與模型檔名**未在作者本機對你的硬體驗證**；請在目標設備上自行跑通並驗收延遲、精度與記憶體。

## 三條契約（全書共用）

**比較模型時，各類別如何平均要一致。** AP（平均精度）摘要一個類別在多個分數門檻下的表現；mAP 是各類別 AP 的**等權平均**，不直接依類別頻次加權。稀有類別和大宗類別的 AP 若下降相同幅度，對 mAP 的影響也相同。計算條件見[平均精度與 mAP](06/ap-map.md)。

**訓練與推論不必使用相同輸入尺寸**，但圖片如何縮放與補邊（letterbox）、尺寸如何配合模型的步幅（stride）、像素值如何正規化，以及框如何還原，都必須有一致、明確的約定。否則評估時的結果無法直接拿來判斷上線表現。細節見[影像與座標](03/index.md)。

**排錯時，先分清漏標與漏檢。** GT（ground truth）是評估使用的標註答案。漏標是圖上有物體，答案卻沒標框；模型即使找對，也可能被算成誤報（FP）。漏檢則是答案有框，預測卻沒配對成功。例如兩個框的重疊程度（IoU）不足，或預測框在去除重複框的步驟（NMS）中被移除。先查是哪一種，再修改資料或門檻。見[對錯三種計數](06/tp-fp-fn.md)。
