# YOLO 工程：從任務到上線

這本書把 YOLO 當工程系統寫，不把「下載權重、跑一張圖」當成終點。主線是：**任務契約 → 推論與座標 → 資料與標註 → 評估 → 訓練 → 錯誤與改善 → 延伸任務與選型 → 基準、匯出、即時與維運**。神經網路內部（架構、DFL、解碼／NMS、演進）放在選讀，需要時再進。

文中出現的 CLI、GPU 型號與模型檔名**未在作者本機對你的硬體驗證**；請在目標設備上自行跑通並驗收延遲、精度與記憶體。

## 三條契約（全書共用）

**mAP** 是各類別 AP 的**等權平均**；類別頻次不直接加權。稀有類別掉分會和大宗類別一樣拉低 mAP。

**訓練與推論不必同輸入尺寸**，但 letterbox、stride、正規化與框座標還原必須同一套契約，否則評估與上線各說各話。

**漏標 ≠ 漏檢**。漏標：圖上有物體但 GT 沒框，模型框對了會被算成 FP。漏檢：GT 有框但預測沒對上（TP matching IoU 不夠或被 NMS 吃掉）。排錯先分這兩種，再動資料或閾值。
