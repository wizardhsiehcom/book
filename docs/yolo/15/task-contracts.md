# Ultralytics 標註契約：分類、實例遮罩、姿態與旋轉框

回到 [index.md](index.md)。本頁只談**可直接寫進磁碟、用欄位數驗收**的標註契約，不談訓練執行或推論。影像與標籤如何配對、座標如何正規化，四種任務共用同一套幾何語言；差別只在「一列寫什麼、幾個欄位算合法」。

## 共用配對與正規化

除分類以外，偵測家族都採「一張圖對一個同名 `.txt`」：`images/train/a.jpg` 對 `labels/train/a.txt`。空檔表示該圖沒有任何實例，不是壞檔。座標一律把像素 \(x\) 除以影像寬、\(y\) 除以影像高，落到閉區間 \([0,1]\)。**幾何對錯要以像素平面判斷**，不要用被壓扁的正規化圖去讀角度或邊是否垂直。類別索引從 0 起，必須對得上資料 YAML 的 `names`。

標註校驗應先標出非法座標與欄位數，並核對影像、來源與匯出流程，再決定要不要修。不要為了通過語法就盲目夾緊或刪點、把真實框硬塞進檢測框、任意放大框或改類別。須確認實際標到的物體與該版本的類別對應；框應遵循已文件化的標註政策，而非解析器的任意強制。機器格式可被接受，並不代表語意標註正確。

## 影像分類

分類**沒有**逐框 YAML，也沒有每圖一個標籤檔。資料根目錄下用資料夾當類別名，`data` 指向這個根，而不是指向帶 `nc`/`names` 的偵測 YAML。官方結構是 `root/train/class_name/*.jpg`、`root/val/class_name/*.jpg`，可選 `test` 必須使用**同一組**類別名。來源：[Ultralytics Classify datasets](https://docs.ultralytics.com/datasets/classify/)（核對於 2026-09-08）。

兩類完整樹：

```text
root/
  train/
    cat/
      a.jpg
      b.jpg
    dog/
      c.jpg
  val/
    cat/
      d.jpg
    dog/
      e.jpg
```

失敗與修補：train 有 `cat` 而 val 只有 `kitten`，等於兩個任務；把資料夾改成同一組名字。圖放在 `root/*.jpg` 沒有類別層，讀不到標籤。分類契約的「欄位數」是 0：標籤就是路徑上的資料夾名。

## 實例分割（多邊形遮罩）

一張圖一個 `.txt`，**每個實例一列**：`class x1 y1 x2 y2 ... xn yn`，全部正規化到 0..1。至少三個 \((x,y)\) 點；不同列可以有不同長度。列前**沒有** `xc yc w h`，不要把偵測框欄塞進多邊形。來源：[Ultralytics Segment datasets](https://docs.ultralytics.com/datasets/segment/)（核對於 2026-09-08）。

非退化三角形，**7 欄**（1 個 class + 3 對座標）：

```text
0 0.20 0.20 0.80 0.25 0.50 0.85
```

對應像素直覺：寬 100、高 100 時三點約為 \((20,20)\)、\((80,25)\)、\((50,85)\)，面積不為零、邊不共線。

失敗與修補：少於 6 個座標欄（不足三點）刪列或補點；出現 5 個偵測欄再接多邊形，刪掉中間的 `xc yc w h`；點重複成一線改成真正圍成面積的多邊形；值 \(>1\) 或 \(<0\) 先確認是否忘了除以寬高。

## 姿態（框 + 關鍵點）

一列順序是 `class xc yc w h`，再接 \(K\) 組關鍵點。維度 \(D=2\) 時每點 \((x,y)\)；\(D=3\) 時每點 \((x,y,v)\)。總欄位數固定為 \(5+K\cdot D\)。YAML 必須寫 `kpt_shape: [K, D]`（\(D\) 只能 2 或 3）。`flip_idx` 依**你自訂的點順序**把左右對調，不是依骨架名稱自動猜。來源：[Ultralytics Pose datasets](https://docs.ultralytics.com/datasets/pose/)（核對於 2026-09-08）。

可見度 \(v\)：\(0\) 未標、\(1\) 已標但遮擋、\(2\) 已標且可見。這是標註真值旗標，**不是**模型預測的關鍵點置信度。來源：[Ultralytics annotation](https://docs.ultralytics.com/platform/data/annotation)（核對於 2026-09-08）。未標點在本例採用 \((x,y)=(0,0)\) 且 \(v=0\)：這是選定的一致匯出慣例，不是全宇宙唯一不可改的規則。

自訂三點順序：左、右、中心。`kpt_shape: [3, 3]`，`flip_idx: [1, 0, 2]`（左右對調、中心不動）。總欄位 \(5+3\cdot3=14\)。框中心 \((0.50,0.50)\)、寬高 \(0.40\times0.40\)，故像素意義上框覆蓋正規化 \([0.30,0.70]\times[0.30,0.70]\)。已標兩點都落在框內；未標占位用 \((0,0)\)。

完整 14 欄列：

```text
0 0.50 0.50 0.40 0.40 0.00 0.00 0 0.62 0.48 1 0.50 0.58 2
```

意義：class 0；框；左點未標 \((0,0),v=0\)；右點已標遮擋 \((0.62,0.48),v=1\)；中心已標可見 \((0.50,0.58),v=2\)。

完整小型 data YAML：

```yaml
path: datasets/toy_pose
train: images/train
val: images/val
names:
  0: person
kpt_shape: [3, 3]
flip_idx: [1, 0, 2]
```

失敗與修補：欄位不是 14（例如漏掉某個 \(v\)）整列作廢重寫；把 \(v\) 當成置信度寫成 0.87 屬契約錯誤，只能是 0/1/2；左右點順序與 `flip_idx` 不一致時，水平翻轉增強會把左右標反，應改順序或改 `flip_idx`，不要只改圖。

## 旋轉框（OBB）

標籤列是 `class` 加四個正規化角點，**恰好 9 欄**：`class x1 y1 x2 y2 x3 y3 x4 y4`。訓練內部可能用 `xywhr`，但**那不是標籤列**。來源：[Ultralytics OBB datasets](https://docs.ultralytics.com/datasets/obb/)（核對於 2026-09-08）。公開文件沒有把「必須順時針且必須從某一固定角起算」訂成強制規則，本頁不宣稱起始角索引強制。以 x/W、y/H 正規化時，寬高縮放通常不均勻，旋轉形狀的角與長寬比可能改變，但軸對齊矩形在此變換下仍保持軸對齊；幾何判斷需回到原始像素座標。四個角點須不自交，且確實對應預期的有向矩形；僅「不自交四邊形」並不能保證是矩形。接近正方形會有方向歧義，但不必然是退化形。

像素平面上的真矩形（寬 200、高 100）四角 \((40,20)\)、\((120,20)\)、\((120,60)\)、\((40,60)\)，正規化後 9 欄：

```text
0 0.2000 0.2000 0.6000 0.2000 0.6000 0.6000 0.2000 0.6000
```



失敗與修補：不是 9 欄（少角、多了角度欄、或寫成 `xywhr`）一律改回四角；邊交叉成蝴蝶結，重排成凸四邊形；近正方形時微小角抖動會讓角度不穩，class 與 `names` 對不上是映射錯誤，改索引而非改四角。

## 實務疊加與欄位數驗收

先配對檔名，再數欄位：分類 0 欄（資料夾即類別）；分割每列 \(\ge 7\) 且為奇數個數字（1+偶數座標）；姿態恰好 \(5+K\cdot D\)；OBB 恰好 9。通過欄位關再查 \([0,1]\)、多邊形／四邊形是否非退化。來源契約見上文四個資料集頁與 annotation 頁（核對於 2026-09-08）。通過這份清單的檔，才算可用標註，而不是「看起來像 YOLO」。
