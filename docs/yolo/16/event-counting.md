# 從軌跡到穿越事件：影格數不能當每小時事件

把偵測數、軌跡長度或可見影格數當成「每小時穿越人次」，會把同一通過的連續觀測重複加總。Ultralytics 追蹤模式會輸出 track ID，把跨影格的框連成軌跡（公開說明，見文末）。**ID 是否連續、何時算一次穿越，都不是官方指標。** 下列事件規則是本頁自設工程示例：示範如何把點列變成有方向的穿越；不保證真實追蹤器給出相同 ID，也不是產品 metric。

## 影格數不是事件數

行人由左至右可能連續出現數十影格。每個影格是觀測，不是穿越。正確單位是：在指定觀測窗內，相對一條全高垂直線，每個 track ID 的每一次穩定側轉換至多一筆，且 L→R 與 R→L 分開計。有限時長只報該窗內事件。在清楚回報次數、觀測窗與速率時，觀察次數除以曝光小時數就是從十分鐘資料得到的有效經驗速率；例如十分鐘內七件事對應每小時四十二次的速率。這並非斷言下一小時實際會發生四十二次，短時窗的不確定性必須一併記錄。不應禁止這種標準的速率正規化。

## 全高垂直線、方向、滯後、上次穩定側

全高度垂直計數線 x=line_x 依設計忽略 y，因為它要涵蓋整幅影像的走廊通道。有限長度的門口線段則刻意不把端點向外延長，這對該 ROI 是正確的幾何。請依需求選擇對應幾何，不要把「有限線段外的穿越沒被算到」本身當成錯誤。

方向：穩定左到穩定右記 `L→R`，反向記 `R→L`。兩向各一個計數器，不可合成淨流量，否則來回各一次會顯示成零。

滯後帶寬為 \(b\)：\(x\le x_{\mathrm{line}}-b\) 為穩定左，\(x\ge x_{\mathrm{line}}+b\) 為穩定右；帶內不更新側別、不產生事件，用來吸收框中心在線附近的抖動。

每個 ID 只記上次穩定側。第一次形成穩定側只初始化、不計事件，避免在線一側出現就被當成穿越。之後唯有穩定側真正改變才加一。同一 ID 折返必須再計：**禁止用「此 ID 已計過」永久壓制**，否則反向事件會漏。

## 合成軌跡（驗規則，非追蹤精度測試）

取 \(x_{\mathrm{line}}=100\)、\(b=5\)，故穩定左為 \(x\le 95\)、穩定右為 \(x\ge 105\)。下列點列為手寫合成，用來固定規則；不是追蹤精度測試，也不使用 GPU 或真實影片。

穿越：ID=1 的 \(x\) 依序 80、90、94、98、102、110、120。94 仍在穩定左；98 與 102 在帶內；110 才進入穩定右。七個影格只有一次 `L→R`。

抖動：ID=2 在 90 初始化為左，其後 96、100、104、100、92 均未到達穩定右，事件為零。

折返：ID=3 由 80 到 120（`L→R`），回到 80（`R→L`），再到 120（第二次 `L→R`）。三次穩定側轉換、兩向都計；若永久壓制，後兩筆會消失。

## 新身分、時間缺口、有限觀測時長

追丟後若分到新 ID，舊的上次穩定側不繼承。新 ID 已在右側出現時只初始化為右，不自動補一筆穿越；之後走向左才單獨產生 `R→L`。事件狀態機跟隨 ID，不是物理人。連續性取決於追蹤器，本頁不宣稱。

這個簡單的逐 ID、穩定側玩具假設單一串流內時間戳連續單調、且 ID 不重用。長間隔後真實穿越無法得知，實務部署應在更新狀態前預設拒絕或重置。目前玩具沒有間隔過期機制，這是已知上限而非可上線成品；合成斷言只驗證玩具邏輯，仍需真實軌跡與事件的留出集。

事件只存在你實際看到的時間軸。窗長十分鐘且 `L→R` 為七，應寫「十分鐘內七次」。缺口越大，越不能把窗內次數線性放大成每小時。

## 操作步驟

1. 準備 `(t, track_id, x, y)`；y 保留但不參與判定，以強制全高線。
2. 選定線位置與帶寬（可先取畫面寬約百分之一到二，再依線邊抖動加大）。
3. 用字典記錄每個 ID 的上次穩定側；點在帶內則跳過。
4. 穩定側改變則對應方向加一，並記下時間、編號與方向。
5. 輸出雙向計數、事件表與觀測窗起迄；ID 消失後何時清除須預先規定。
6. 報表必帶觀測窗與計數。

## 程式（標準庫、合成點列）

```python
def stable_side(x, line_x, band):
    if x <= line_x - band:
        return "L"
    if x >= line_x + band:
        return "R"
    return None  # hysteresis band; not a stable side


def count_line_events(samples, line_x=100.0, band=5.0):
    """Full-height vertical line x=line_x. samples: (t, track_id, x, y); y ignored."""
    last_stable = {}
    n_lr = 0
    n_rl = 0
    events = []
    for t, tid, x, _y in samples:
        side = stable_side(x, line_x, band)
        if side is None:
            continue
        prev = last_stable.get(tid)
        if prev is None:
            last_stable[tid] = side
            continue
        if side == prev:
            continue
        if prev == "L" and side == "R":
            n_lr += 1
            events.append((t, tid, "L->R"))
        elif prev == "R" and side == "L":
            n_rl += 1
            events.append((t, tid, "R->L"))
        last_stable[tid] = side
    return n_lr, n_rl, events


def test_cross_jitter_reverse():
    line_x, band = 100.0, 5.0

    cross = [
        (0, 1, 80.0, 10.0),
        (1, 1, 90.0, 50.0),
        (2, 1, 94.0, 200.0),
        (3, 1, 98.0, 0.0),
        (4, 1, 102.0, 999.0),
        (5, 1, 110.0, 40.0),
        (6, 1, 120.0, 40.0),
    ]
    n_lr, n_rl, ev = count_line_events(cross, line_x, band)
    assert n_lr == 1 and n_rl == 0
    assert ev == [(5, 1, "L->R")]
    assert len(cross) > n_lr + n_rl

    jitter = [
        (0, 2, 90.0, 1.0),
        (1, 2, 96.0, 1.0),
        (2, 2, 100.0, 1.0),
        (3, 2, 104.0, 1.0),
        (4, 2, 100.0, 1.0),
        (5, 2, 92.0, 1.0),
    ]
    n_lr, n_rl, ev = count_line_events(jitter, line_x, band)
    assert n_lr == 0 and n_rl == 0 and ev == []

    reverse = [
        (0, 3, 80.0, 0.0),
        (1, 3, 120.0, 0.0),
        (2, 3, 120.0, 0.0),
        (3, 3, 80.0, 0.0),
        (4, 3, 80.0, 0.0),
        (5, 3, 120.0, 0.0),
    ]
    n_lr, n_rl, ev = count_line_events(reverse, line_x, band)
    assert n_lr == 2 and n_rl == 1
    assert [e[2] for e in ev] == ["L->R", "R->L", "L->R"]

    reset = [
        (0, 10, 80.0, 0.0),
        (1, 10, 120.0, 0.0),
        (2, 11, 120.0, 0.0),
        (3, 11, 80.0, 0.0),
    ]
    n_lr, n_rl, ev = count_line_events(reset, line_x, band)
    assert n_lr == 1 and n_rl == 1


if __name__ == "__main__":
    test_cross_jitter_reverse()
```

## 失效模式

把偵測數或影格數當事件；無滯後導致連發；永久壓制折返；兩向抵成淨流量；新 ID 誤接或重複計；把本規則說成官方指標。

## 驗收條件

穿越路徑的事件數等於穩定側轉換次數，且小於影格數。抖動路徑零事件。折返路徑兩向分開計、同一 ID 可多次觸發。判定函數不使用 y。新 ID 不繼承舊側。輸出含觀測時長；每小時率需同列實際觀測時長與事件數。僅用標準庫，無網路、無模型推論。
