# 開詞彙工程：閉集、文字、視覺與無提示

[語意分割與單目深度](semantic-depth.md)

開詞彙不是把檢測框外包給另一個產品線。YOLOE 本身輸出框與分割；選 YOLO-World 是因為權重／匯出契約，不是因為「只有 World 才有框」。閉集、文字提示、視覺提示、無提示是四種部署狀態，必須與檢查點、詞表、嵌入一起版本化，不能在現場臨時改詞。

YOLOE 的 prompted 權重：推論時可用 set_classes 或 API 動態指定文字／視覺 prompts。把已部署的 prompt 策略凍結，屬於發版治理（固定類別集合、避免線上任意改 prompt），不是技術上做不到。[官方 YOLOE 文件](https://docs.ultralytics.com/models/yoloe/) 說明提示介面。

## 四種狀態與檢查點

| 狀態 | 檢查點形態（公開文件，2026-09-08） | 標籤從哪裡來 | 本頁部署政策允許現場改詞？ |
| --- | --- | --- | --- |
| 閉集 | 一般檢測／分割權重 | 訓練時固定類別 | 否 |
| 文字提示 | `yoloe-26s-seg.pt` 等 prompted `-seg` | `set_classes([...])` 後的文字嵌入 | 僅離線重算嵌入後換檔 |
| 視覺提示 | 同上 prompted 權重 | 參考圖；目前文件以 `object0`、`object1`… 當 generic 標籤 | 否；只對齊參考圖與後處理對照表 |
| 無提示 | `-seg-pf` prompt-free | 權重內建詞表 | 否；`set_classes` 會被拒絕 |

文字路徑第一次跑會安裝 tokenizer、下載文字編碼器；文件寫明工作目錄會出現 `mobileclip2_b.ts`。離線準備必須核對**實際 cwd 產物與套件依賴**，不能假設「一定在某個通用快取」。視覺路徑不要發明穩定通用 API：以當次 `results.names`／class ID 與你存檔的提示定義做對照。無提示權重不是「忘了設類別的文字模式」。

YOLO-World 原版權重不支援匯出；World v2 才宣告可匯出。這影響 [匯出](../20/index.md) 與 [模型選擇](../18/index.md)，與「要不要框」無關。任務切面見 [任務](../15/index.md)；開詞彙總覽見 [開詞彙](../17/index.md)。

## 最小 YOLOE 文字路徑（介面煙測）

以下只證明套件狀態與檔案落點，**不能**當放行證據。

```python
from ultralytics import YOLOE

model = YOLOE("yoloe-26s-seg.pt")
model.set_classes(["person", "bus"])
results = model.predict("bus.jpg")
print(results[0].names)  # 對齊你存檔的提示定義，不要假設跨版本 API
```

部署包必須同時凍結：檢查點檔名、提示字串列表、產生的嵌入、cwd 內 `mobileclip2_b.ts`（或當次實際檔名）、Python 套件鎖定檔。缺任一項，現場「同一句英文」也不是同一模型。

自有標籤映射：訓練／MES 用廠內代碼，推論用提示詞。對照表綁 **(checkpoint, prompt list, names/class ID)**，不是綁模型家族暱稱。視覺模式把 `object0` 映射到工單代碼；文字模式把 `person` 映射到同一代碼。換提示或換權重就作廢舊表。

## 失敗模式

1. **把 `-seg-pf` 當可改詞。** `set_classes` 被拒或行為未定義；現場看起來「沒偵測到新缺陷」。
2. **只複製 `.pt`。** 缺文字編碼器／tokenizer，第一張圖在產線才下載或失敗。
3. **用合成圖當放行。** 合成圖只測介面與 `names` 長度；不能證明新詞能抓真實缺陷。
4. **用一句話認證未見缺陷。** 開詞彙不能從用詞推出缺陷物理已覆蓋。
5. **視覺標籤當語義。** `object0` 是當前文件的 generic 標籤，不是穩定類名 API。
6. **追蹤 ID 跨提示重用。** 詞表一變，[追蹤](../16/index.md) 必須重開會話。

## 放行：先鎖提示，再測資料

合成資料：僅介面／狀態煙測（載入、`set_classes` 成敗、檔案是否在 cwd、`names` 與提示長度一致）。

真實放行（固定提示與檢查點之後才進測試集）：

- 代表性實景 hold-out，含光照、遮擋、尺度。
- 硬負例（外觀相近、用詞易混）。
- 稀有目標的最低件數，不足則標「未覆蓋」而非「模型會泛化」。
- 同一目標的用詞變體（同義、大小寫、領域黑話）只允許在**驗證提示**階段掃描；一經凍結，測試集不得再改詞。
- 指標：允許科學上定義清楚的 **novel／known 合計值**，但必須同時給分組表，並在報告寫明加權方式。禁止只報一個漂亮總分；也不禁止合計本身。細節與門檻寫在 [評估](../06/index.md)、[基準](../19/index.md)。

詞表、嵌入、檢查點三者聯合版本號。現場只准載入已簽署的三元組。新缺陷要進詞表，就走新的驗證→凍結→測試，而不是在線上改一個英文字。
