# 05　篩掉早夭品，值得嗎？

## 開場問題：測都測過了，為什麼還要烤幾個小時？

一顆晶片通過了 CP 和 FT，所有規格項都在範圍內。它為什麼還要被放進烤箱，加溫加壓連續運作幾小時，然後再測一次？

因為**有一類缺陷在出廠當下量不到**。它是一個比較薄的金屬連線、一處比較弱的介電層、一個接觸不太完美的界面——現在功能完全正常，但它的壽命遠短於正常品。這類產品裝到客戶的系統裡，可能幾天、幾週後才失效。

burn-in 的邏輯是：**與其讓它在客戶手上壞，不如在我手上先壞掉。** 本章談這個邏輯的物理前提、它的代價，以及它在什麼條件下不划算。成本算法見 [02](02-test-cost-model.md)。

## 先看結構：浴缸曲線與加速老化

產品的失效率隨時間的典型形狀是一條浴缸曲線：

```mermaid
flowchart LR
    A["早夭期<br/>失效率高且遞減<br/>製造缺陷造成"] --> B["穩定期<br/>失效率低且平坦<br/>隨機失效"]
    B --> C["磨耗期<br/>失效率上升<br/>材料老化"]
```

| 階段 | 失效原因 | 測試能做什麼 |
|---|---|---|
| 早夭期 | 製造缺陷：微裂、薄化、污染、弱接合 | **burn-in 的目標**：用加速條件讓它提早發生 |
| 穩定期 | 隨機事件 | 篩不掉，只能靠設計裕度與可靠度規格 |
| 磨耗期 | 電遷移、介電崩潰等長期機制 | 不是篩選問題，是壽命設計問題 |

**burn-in 只對第一段有效。** 它的前提是：加溫加壓能讓潛在缺陷的失效**加速**，而不改變正常品的行為。這個加速關係通常用溫度的指數關係建模——溫度每提高一定幅度，等效老化時間放大數倍。所以幾小時的 burn-in 可以代表正常使用下的一段較長時間。

**這個前提有邊界**：加速模型只涵蓋它所描述的失效機制。若某種缺陷對溫度不敏感，提高溫度對它沒有加速效果，burn-in 篩不到它。

## 輸入／操作／輸出：burn-in 不產生判定

| 步驟 | 輸入 | 操作 | 輸出 |
|---|---|---|---|
| 上板 | 成品、burn-in board | 逐顆插入 socket | 一整板待烤產品 |
| 施加應力 | 目標溫度、電壓、激勵 | 持續運作設定時數 | 潛在缺陷被加速到失效 |
| 下板 | 已烤產品 | 取出 | 外觀上無法分辨誰壞了 |
| **後測** | 已烤產品 | 重新跑測試程式 | **這一步才產生判定** |

**關鍵推導**：burn-in 本身不篩掉任何東西——它只是讓該壞的先壞。**真正把它抓出來的是後測。** 這代表 burn-in 的成本是「烤的時間 ＋ 多一次測試插入」，兩者都要算進去。只算烤箱時間會低估。

另一個容易漏掉的成本是 **burn-in board**：它要在高溫下長時間承載，socket 要耐得住反覆熱循環，一片板上有多少顆決定了單顆分攤的治具成本。板的設計與壽命是 burn-in 成本的重要部分。

## 失敗會長什麼樣子：烤過頭和烤不夠一樣糟

| 現象 | 機制 | 需要的證據 |
|---|---|---|
| burn-in 後失效率沒有下降 | 條件不足，或該產品的失效機制對此應力不敏感 | 烤前烤後的失效率比對；失效分析確認機制 |
| burn-in 後良率掉太多 | 應力過強，正常品也被損傷（過殺） | 烤後不良品的失效分析：是潛在缺陷還是新造成的傷害 |
| 客戶端仍有早夭 | 篩選涵蓋不到該機制，或 burn-in 條件與實際使用條件不匹配 | 客戶端失效分析與失效時間分布 |
| 高功率產品烤不動 | 自身發熱疊加環境溫度，超出板與 socket 的承受範圍 | 實測晶片接面溫度，不是烤箱設定溫度 |
| 同板不同位置結果不同 | 板上溫度或供電不均 | 板上各位置的實測溫度與電壓 |

**「高功率產品烤不動」是現在最實際的難題**。AI 與高效能運算晶片自身功耗極高，在高溫環境下持續全速運作時，晶片接面溫度會遠高於環境設定值。這對 burn-in board 的供電能力、散熱設計與 socket 的熱阻都是新要求——**這不是把烤箱調高就能解決的問題，是治具與供電的工程問題。**

供電需求可以具體到什麼程度？ITRS 2009 在談晶圓級 burn-in 時估計，設備需要對**每片晶圓供應超過 1,000 安培**的電流。[T4](appendix-sources.md#T4) handler 端的熱控制也已經是千瓦等級——Cohu 在 Eclipse 平台標示的熱控制能力為 4–6 kW，溫度範圍 −40 至 130°C（選配 −55 至 155°C）。[T7](appendix-sources.md#T7) **這些是設備商對自家產品的標示，不是產業通用規格**；引用它們只為了說明高功率篩選的瓶頸在供電與散熱，不在烤箱溫度。

加速模型本身有標準可依。JEDEC 的公開詞典收錄浴缸曲線與可靠度用的 Arrhenius 加速式 AT = exp[(−Eaa/k)(1/T1 − 1/T2)]，分別引用 JESD74A／85／91A。[T10](appendix-sources.md#T10) TI 的應用文件則示範了依 JESD85 計算 FIT 的完整流程：AEC-Q100 的範例為 231 顆樣本、1,000 小時、125°C；同一顆產品的 FIT 由 55°C 的 2.26 降到 0°C 的 0.015。[T11](appendix-sources.md#T11) **後面這組數字說明溫度對失效率的影響有多陡——這正是加速老化能成立的物理基礎，也是它只對溫度敏感機制有效的原因。**


## 如何檢查與控制：每個條件都要能說出它在加速什麼

| 控制項 | 怎麼量 | 失控的後果 |
|---|---|---|
| 實際接面溫度 | 晶片端量測，不是烤箱設定值 | 加速倍率算錯，篩選強度不如預期 |
| 板上溫度均勻性 | 各位置實測 | 部分位置烤不足、部分過殺 |
| 供電能力 | 滿載下的實際電壓 | 電壓塌陷使應力不足 |
| burn-in 時數 | 依加速模型推算並驗證 | 憑慣例設定，無工程依據 |
| 烤前烤後失效率 | 兩次測試結果的比對 | 無法證明 burn-in 有效 |
| 過殺率 | 烤後不良品的失效分析 | 良率損失被誤當成產品品質問題 |
| 治具壽命 | 板與 socket 的熱循環次數 | 治具老化造成的假不良 |

一份能判定的 burn-in 方案，至少要回答：**針對哪種失效機制、用什麼加速模型、實際接面溫度是多少、等效老化多久、烤前烤後的失效率差多少、過殺率多少、這個條件適用哪些產品**。

**最後一項最常被忽略**：burn-in 條件是針對特定產品與失效機制訂的。換一顆功耗不同、材料堆疊不同的晶片，同一套條件可能既篩不到該篩的，又傷到不該傷的。

## 理解檢查

??? question "為什麼說 burn-in 本身不篩掉任何東西？"
    burn-in 只施加應力，讓潛在缺陷加速失效；它不做量測、不產生判定。烤完之後產品外觀與烤前一樣，必須再跑一次測試才能知道誰壞了。所以 burn-in 的成本要算「烤的時間」加「多一次測試插入」，兩者缺一不可。

??? question "把 burn-in 溫度再調高，是不是就能篩得更乾淨？"
    不一定。加速模型只對它描述的失效機制有效——對溫度不敏感的缺陷，調高溫度沒有幫助。而且溫度過高會開始損傷正常品，把過殺率推上去。篩選強度要由「篩到的真不良」與「傷掉的良品」共同決定，不是單調遞增。

??? question "為什麼高功率晶片的 burn-in 特別難？"
    晶片自身功耗在高溫環境下持續全速運作，接面溫度遠高於烤箱設定值，而且熱必須被帶走。這對 burn-in board 的供電能力、散熱路徑與 socket 熱阻都是新要求。關鍵是實際接面溫度，不是烤箱設定溫度——兩者可能差很多。

??? question "客戶要求「取消 burn-in 以降低成本」，工程上該提出什麼問題？"
    至少三個：這個產品的早夭失效率有多高、目前 burn-in 攔到的是哪一類機制、取消後漏到客戶端的預估成本是多少。如果沒有烤前烤後的失效率數據，就沒有依據判斷 burn-in 值不值得，也沒有依據取消它。
