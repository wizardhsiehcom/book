# 資料庫與資料正確性：從一筆紀錄到可靠恢復

你能把 AOI 結果寫進資料庫，但如果寫到一半斷線、兩個匯入器同時工作、或隔天需要重判，還能說明哪些資料可信嗎？這本書從三筆缺陷開始，逐步建立「憑什麼相信資料」的判斷能力。

不需要先學 ORM，也不要求先熟悉 ODBC。前七章從身分、表格、SELECT 與約束開始；中段用兩條時間線理解交易與競爭；後段討論重送、未知提交、通知、升版與恢復。

!!! info "本版的實驗證據"
    教材以 SQL Server 2022、compatibility 160 為基線。官方支援環境與本機 Docker 模擬測試分開記錄；哪些步驟已跑過、哪些仍是演練設計，請先看 [驗證紀錄](verification.md)。閱讀完或網站建置成功，不等於資料庫實驗通過。

## 如何讀

| 你目前的問題 | 入口 | 讀完應能做的事 |
|---|---|---|
| 我不知道表該怎麼切 | [資料身分](01-identity.md)、[正規化](02-normalization.md) | 找出鍵、基數與重複事實 |
| SQL 跑了，但數字不對 | [查詢](03-query.md) 至 [聚合](06-aggregation.md) | 手算列集合與統計粒度 |
| 單次能跑，多人就壞 | [約束](07-constraints.md) 至 [鎖與死鎖](12-locks-deadlocks.md) | 畫出交錯順序並維持不變條件 |
| 加索引前不知道該看什麼 | [索引](13-indexes.md)、[查詢計畫](14-query-plans.md) | 比較結果、讀取量與寫入成本 |

| 資料要活很多年 | [Outbox](17-outbox.md) 至 [保留期](21-retention.md) | 解釋通知、變更與恢復的邊界 |

第一次閱讀請依 [全書地圖](00-map.md) 順序進行。每章先寫預測，再看解釋；遇到 SQL 時先列出你認為會得到的列，而不是只看執行有沒有錯。章末題的 [答案](answers.md) 獨立放置，最後用 [設備校正遷移題](exercises.md) 檢查能否換場景使用。

圖解以 Mermaid 原始碼維護，直接對應本書的資料與交易契約。循序圖由上往下讀；先遮住最後的結果，預測下一步，再與 SQL 實驗對照。圖是機制示意，實際執行結果以驗證紀錄為準。

## 同一組資料，逐步增加責任

合成工廠有兩個批次、三筆缺陷。批次 A 的缺陷 1 有兩次判定，缺陷 2 尚未判；批次 B 也有一筆編號 1。它們足夠讓你看見身分碰撞、JOIN 膨脹、NULL 與重判的差別，不代表任何公司的實際 schema。

後面才加入操作紀錄與目前指標。每增加一張表，都要問：它保存什麼不能從其他資料可靠推回的事實？它與其他表必須一起成功嗎？

[實驗入口](labs.md) 提供 schema、手算對照、交易斷言與重送檢查。程式碼以教學可查核為目的；權限、故障注入與還原測試的覆蓋範圍都在同頁說明。
