# 獨立練習：把判斷帶到另一個系統

章末題測單一概念；這一頁要求把概念接起來。不要先看答案，也不要直接替 AOI 表改名就宣布完成。

## 關卡一：先說對三個數字

使用本書 seed，分別查批次 A 的缺陷數、判定事件數、未判缺陷數。交出 SQL、手算列集合，以及把 LEFT JOIN 的條件從 ON 搬到 WHERE 後會改變什麼。不能只交 COUNT 結果。

## 關卡二：替修改寫一個反例

寫出「版本、判定、目前指標、操作結果」必須維持的關係。選其中一條，刻意在第二次寫入後發生錯誤，證明它沒有留下半套結果。由另一個 session 讀回，記錄受限帳號與管理員執行的差異。

## 關卡三：提交結果未知

給定：操作 X 的提交回覆遺失，讀取副本暫時查不到；另一個操作 Y 已經合法重判同一缺陷。設計查核與 UI 狀態，不允許靠目前分數等不等於 X 的分數推斷 X 是否成功。

需要交出原意圖、查核目標、超時預算、如何維持 unknown，以及 X 最終查到時應回哪一份結果。

## 期末：設備校正紀錄匯入

工廠有兩間廠區，同一設備代號可能在不同廠區重複。每台設備會多次校正；每次記錄量測值、單位、校正方法版本、操作者與來源檔。新校正不能刪除舊校正。

兩位操作者可能同時匯入。匯入器會離線保存待送資料，網路中斷後重送；若第一次成功回覆遺失，不能產生兩份校正。操作者確認新資料後，可以再次校正同一設備。舊操作重送時，仍應找回當次結果。

第一版沒有來源系統欄位；第二版開始要求保存它。升版期間舊客戶端仍在線。三個月後需要清理部分操作紀錄，但最長離線時間與外部重送窗口尚未決定。每週要演練把備份還原到另一個資料庫。

### 你要交付

1. ER 圖與 DDL：鍵、基數、單位契約、可空欄位與不可變歷史。
2. 三條查詢：每台目前校正、指定期間校正事件、尚未校正的設備。
3. 寫入交易：穩定操作身分、同 ID 異意圖、expected version 與結果查核。
4. 兩 session 時間線：同操作競爭、兩個新操作競爭、提交回覆遺失。
5. 升版步驟：expand、可重入 backfill、舊客戶端退出證據、contract。
6. 備份與還原報告：實際還原位置、資料對帳、耗時與未涵蓋的故障。
7. 保留政策提案：哪些需求未決定，為何此時不能直接刪操作表。

沒有規定使用 ORM、訊息佇列或 Web 介面。只有在需求使某個元件必要時才加入，並說明它新增的失敗窗口。

### 通過判準

| 能力 | 足夠證據 | 不足證據 |
|---|---|---|
| 身分 | 跨廠同代號不碰撞；重判有新事件 | 所有資料只有一個流水號 |
| 查詢 | 列集合與粒度對帳 | 執行沒有錯 |
| 原子性 | 故意中途失敗，新連線確認全回滾 | TRY/CATCH 有印訊息 |
| 並行 | 真正雙連線、同步點與結果 | 同一連線跑兩次 |
| 恢復 | 原 ID 查核、舊結果不漂移 | 看到目前值相同就當成功 |
| 演進 | 舊資料、舊客戶端、重入都有證據 | 空庫 migration 成功 |
| 還原 | 新庫可讀且不變條件通過 | 備份檔存在 |

[評閱提示](answers.md#transfer) 只提供判準與取捨，不給唯一 schema。
