# 03｜從工程材料長出題目

好的題目可以追溯到一段可查看的材料：影像、測試結果、公開文章、流程圖或自己的問題紀錄。先有材料，再決定標題，能讓文章的承諾停在證據支撐得到的地方。

## 一張材料卡就能開始

以下為**合成的練習設計，尚未執行**：

| 欄位 | 寫法 |
|---|---|
| 讀者與問題 | 視覺工程師：亮度變化可能影響哪些判定？ |
| 材料來源 | 自行繪製的幾何影像，含固定形狀與亮度變體 |
| 準備方法 | 保存原圖、變換方式、模型或規則版本與逐張輸出 |
| 要觀察什麼 | 哪些變體改變判定；原圖與變體必須可配對 |
| 尚未知道 | 真實成像噪聲與缺陷分布是否有相同行為 |
| 可以寫的內容 | 測試設計與限制；執行後才補觀察結果 |

此時標題可以是「我準備怎麼檢查亮度變化下的判定」，還不能寫「我解決了光源造成的誤報」。合成亮度變換與實際改變光源的物理效果也不同，題目應保留這個範圍。

## 把工作紀錄變成讀者問題

原始紀錄常是「今天改了超時設定」。讀者更需要知道的是：超時發生在哪個步驟？呼叫端是否知道工作已完成？下一次重試會不會產生第二筆結果？

用三步轉換材料：

1. **找出判斷點。** 當時有哪些選項，為什麼需要選？
2. **找出可展示的差異。** 哪張圖、哪筆紀錄或哪個測試能讓別人看懂？
3. **縮小結論。** 哪個條件尚未測到，必須留在限制中？

若公司材料不能公開，可以另做獨立的合成案例，說明同類問題。重新製作的案例必須標明用途；只遮掉名稱的截圖仍可能留下識別資訊，改寫後也不應冒稱保留了原案結果。

## 十二個起始題目

下表全是候選題，不代表已完成作品。先挑一項有材料的題，再挑一項願意動手驗證的題。

| 題目 | 最小準備 | 適合的主張與模式 |
|---|---|---|
| 離線分數之外，設備判定還要看什麼？ | 公開例子，分開誤檢、漏檢與使用條件 | 觀點論證；交代取捨，避免代填現場效益 |
| 影像亮度變化後，哪些樣本改判？ | 合成影像、配對輸出與固定設定 | 教學；限定合成測試範圍 |
| 補資料還是重訓，先看哪類錯誤？ | 公開資料上的錯誤分類 | 決策復盤；先執行再寫結果 |
| 模型回退時，需要保存哪些資訊？ | 自製版本紀錄與一次回退練習 | 教學；展示如何確認使用的版本 |
| 推論超時，日誌能回答哪個問題？ | 模擬服務、請求 ID、時間紀錄 | 案例；說明在哪一步失去資訊 |
| 多個影像來源，如何對回正確結果？ | 合成資料流、來源 ID 與亂序測試 | 設計分析；不照抄內部網路 |
| AI 產生程式後，哪個測試抓到錯誤？ | 可公開程式、失敗案例與修正 | 復盤；呈現驗證，不以產碼量代替品質 |
| 狀態與錯誤處理如何幫助閱讀？ | 小型前後對照與相同行為檢查 | 學習敘事；清楚交代學習範圍 |
| 手冊問答的引用真的支持答案嗎？ | 可引用文件、問題與評分規則 | 資料解讀；分開引用正確與回答有用 |
| 固定流程足夠時，是否需要 Agent？ | 同一任務與可比較的完成條件 | 觀點／比較；未實測先寫設計 |
| 工具失敗後重試，會不會重複動作？ | 沙盒工具與失敗紀錄 | 教學；明確觀察最終狀態 |
| 半導體文章裡，藏著什麼軟體問題？ | 原文與自己的推論分欄 | 閱讀筆記；不借用原作者資歷 |

## 看領域作者時，學他如何選問題

設備文章可以從一項明確任務開始。Wagno Alves Bragança Júnior 的晶圓檢查文章沿著影像處理、幾何量測與校正描述工作。這種任務順序適合拆出自己的材料卡；文中的案例不能替代你自己的誤差分析。[原文，2023-10-18](https://www.linkedin.com/pulse/wafer-inspection-computer-vision-brief-introduction-wagno-cxy0f)

LLM 作品也能從可查看的中間結果取材。Simon Willison 的影像框選工具紀錄描述了影像方向資訊導致框錯位的除錯過程。可借鏡的是「看見異常 → 找條件 → 展示修正」的敘述；原文使用的 2024 年模型與 API 不作為現在的實作指令。[原文，2024-08-26](https://simonwillison.net/2024/Aug/26/gemini-bounding-box-visualization/)

Agent 題材可以先問：工具呼叫成功，是否等於任務完成？把預期結果、實際執行紀錄與最後狀態分開，往往就有可討論的具體問題。這裡提出的是練習方向，實際原型仍需自己的測例；[Anthropic 的評測文章，2026-01-09](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)可作進一步閱讀。

以上來源查核日為 2026-09-30；未在本書重現作者專案。技術長文提供取材方法，下一章另用 LinkedIn 原始短貼文分析發文結構。

## 用材料成熟度決定下一步

如果只有疑問，寫問題與預備方法；已有測試，寫條件、結果與限制；多次修正後有完整紀錄，才適合寫決策復盤。同一題可以逐步成長，不必一次寫成完整成功故事。

本章練習：從十二題挑一題，填好材料卡，標註「已做」「待實作」或「閱讀推論」。接著寫一句你目前能支持的結論，以及一句現在仍不能支持的結論。帶著這張卡進入[第四章](04-post-patterns.md)，選擇合適的文章結構。
