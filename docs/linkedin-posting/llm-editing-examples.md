# 短文編修示例：選材、輕修與英文重寫

本頁使用**匿名合成材料**示範編輯取捨，不是實際人物經歷、已獲作者採用的成稿，或高成效貼文。範例的用途是比較修改範圍；自然度與是否像本人，仍需由作者判斷。真實貼文比較見[貼文剖析](post-anatomy.md)。

## 同一份材料，三個不同候選

練習材料：第一次參加開源協作日（本合成情境設定為 open-source sprint，未設定官方英文名）；在文件工具專案提出一個修正範例的 PR，尚未確認合併；受邀帶領該專案的主持人，是報名原因之一；現場另有數個感興趣的專案；午餐有飯糰；有團體照。以下候選均只使用這批材料，不加入後來才得知的談話或結果。

### A｜把本人行動放前面

> 第一次參加開源協作日，在文件工具專案提了一個修正範例的 PR。
>
> 現場還有幾個專案想試。

主角是自己的參與。省略主持人、餐飲與照片描述；提出 PR 的狀態保持不變。

### B｜把報名動機放前面

> 這次報名開源協作日，一個原因是想參加那位受邀主持人帶的文件工具專案。
>
> 最後提了一個修正範例的 PR。謝謝主持人，也謝謝主辦團隊。

主角是參加的原因及感謝。省略其他專案、餐飲；人物名稱可在真實起稿時依已確認材料填入。帶領單一專案沒有被寫成主辦整場活動或創辦專案。

### C｜把現場參與放前面

> 第一次參加開源協作日，現場有好幾個想試的專案，這次先選了文件工具。
>
> 中午有飯糰。謝謝主辦團隊，留張團體照紀念。

主角是現場與共同參與，適合搭配練習材料裡的團體照。省略主持人與 PR，不要求每版都展示貢獻。這版保留餐飲是選材決定，並不表示餐飲是活動文必備元素。

三版改變的是重點與留下的材料，不只是首句。若當次目的是呈現具體工作，A 較直接；若只是活動紀錄，C 也完成自己的任務。這是依題目作的編輯判讀，不能據此預測哪版會收到更多反應。

## 刪掉沒有增加意思的感想

假設草稿已有「第一次參加開源協作日，在文件工具專案提了一個修正範例的 PR」，後面又接：

> 這是一次充滿啟發、收穫滿滿的旅程，也讓我深刻體會到開源社群的無限可能。

這個練習沒有提供足以支持上述感受的材料，而且作者想要簡短紀錄，因此可以整句刪除，不用換成另一句感想。若真實作者明確說這是自己的感受，就應保留意思或請他選擇，而不是因為某些詞常見就一律禁用。

簡短感謝則可能有不同功能。「謝謝主持人和主辦團隊」在交代感謝對象，並不因為缺少技術資訊就必須刪除。先分辨每句在做什麼，再決定留不留。

## 本人草稿已成形時，只做輕修

**輸入草稿（合成）：**

> 第一次參加開源協作日，這次我是在文件工具那邊，提一個修正範例的 PR。
>
> 還有幾個專案想試。謝謝主辦和主持人。

**要求：**「幫我順一下，其他不用加。」

**輕修：**

> 第一次參加開源協作日，這次選了文件工具專案，提了一個修正範例的 PR。
>
> 還有幾個專案想試。謝謝主辦和主持人。

只整理第一句的語序與時態，保留後段節奏；沒有增加收穫、CTA、hashtag 或角色說明。若「文件工具」實際是場次而非專案，需依已知名稱修正，不能靠潤稿猜測。

## 英文重寫保留同一組事實

以上輕修版可重寫為：

> Joined my first open-source sprint and opened a PR to fix an example in a documentation tool.
>
> There were a few other projects I wanted to try too. Thanks to the organizers and project leads.

英文調整了順序與措辭，仍只表示第一次參加這種活動、提出一個 PR、對其他專案有興趣和致謝。沒有增加「第一次參加年會」「首次貢獻大型專案」、合併結果、CI 經歷或自豪感。實際活動若有官方英文名，應改用已確認的名稱。

這不是唯一自然的寫法，也不需要刻意添加縮寫或語病。作者若本來說得更正式或更口語，應以其原稿為依據。後續若才補充「問過主持人某個技術問題」，可新增問過這件事；在沒有回答內容時，不代寫對方立場。

## 怎麼判斷這輪編修是否完成

先核對材料與輸出：事實、角色、數量和狀態有沒有改變？再核對任務：候選是否有實質差異、輕修是否保持範圍、英文是否保留態度？最後由作者選擇是否願意用這樣的口吻發布。

若作者只問「適合 LinkedIn 嗎」，可以回答本文呈現了什麼、讀者能看出哪些參與，以及哪些效果還不知道。評估不必自動變成另一輪改稿。
