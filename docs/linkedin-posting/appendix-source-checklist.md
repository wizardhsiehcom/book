# 附錄 A01｜來源卡、貼文拆解與公開檢查表

你可以用本附錄檢查來源、拆解公開貼文，並回顧自己的貼文和作品。引用時連到原作者或官方原頁；日期不明就寫「未知」，不要拿查核日期填成發布日期。同一 URL 只算一個獨立來源。

## 一、來源卡

每次引用報告、官方文件、教程或作者案例時，複製一張卡。若來源含數據，樣本、期間、帳號類型、指標分子／分母都要填；缺資料就直寫缺口。

```markdown
### [ID]｜[來源標題]
- 原始 URL：
- 作者／發布者：
- 發布日期／更新日期：未知（若來源未標示）
- 查核日期：YYYY-MM-DD
- 來源類型：官方功能／工程說明／觀察研究／教學／原作者貼文
- 已讀範圍：具體頁面或段落；若只讀摘要，明講摘要
- 存取限制：登入、付費牆、部分文字、圖片未讀等；沒有則寫無
- 樣本／期間／帳號類型：不適用時寫不適用；未知時寫未知
- 指標定義：分子、分母、重複計數與觀察窗；未公布就寫未公布
- 方法限制：選樣、非隨機、作者自述、資料不完整等
- 可以支持的主張：
- 不能支持的主張：
- 可用章節／預計引用句：
```

**來源卡原則：**連結要指向能支持這句話的原始發布者，不指向搜尋結果或轉述。平台公告支持「平台公開說了什麼」，不自動支持它造成多少觸及；工具商報告可記錄樣本內關聯，不能寫成普遍因果。若同一篇文章出現在官方指南和研究筆記中，仍只列一次。

## 二、公開貼文拆解卡

拆解目的是學習資訊安排，不複製別人的文字、圖片、個人故事或職涯資歷。只看得到搜尋摘要就保留為待補，不當作已讀樣本。

```markdown
### [ID]｜[原貼文標題或自訂短名]
- Permalink：
- 作者／日期：日期未知時照實標示
- 查核日期／可讀範圍／存取限制：
- 帳號類型：個人／Page／未知
- 預期讀者：原文直接說明／依正文推測（標出哪一種）
- 開頭交代了什麼問題或承諾？
- 結構：情境 → 主張 → 證據／步驟 → 限制 → 結尾
- 證據是第一手經驗、可重現測試、引用資料，還是作者自述？
- 媒介與段落：文字／圖片／文件／影片；段落如何支持論點？
- 讀者可帶走的內容：
- 我可借鏡的組織方式（不用原句）：
- 我不能借用的經驗、數字或資歷：
- 可見反應數：僅作頁面當下的互動線索，不能推論觸及
```

每張卡回答「作者怎麼讓論點可檢查」，而不是「這篇為什麼爆」。公開的按讚、留言和轉貼數不揭露完整 impressions 或 members reached。

## 三、發布前公開檢查

- [ ] **來源**：每個數字、平台規則和借用案例都能點到原始 URL；已標日期、查核日、讀取範圍和存取限制。
- [ ] **工作狀態**：已完成、正在做、計畫、閱讀推論分清楚；合成資料、模擬環境和未驗證結果明確標示。
- [ ] **量測**：數字附樣本、期間、帳號類型、分母與觀察窗；公開互動不寫成曝光、觸及或商業轉換。
- [ ] **隱私**：沒有未獲公開授權的影像、設備畫面、序號、客戶／同事資訊、內部文件、帳號或網址。刪除圖片 metadata 與螢幕截圖中的敏感欄位。
- [ ] **權利**：圖片、程式、文件和引用具備可公開使用的依據；必要時改畫示意圖或自行製作合成資料。
- [ ] **表述**：區分來源明示的事實與自己的推論；不把作者自述當作獨立驗證，不宣稱自己具備未完成作品的技能或成果。
- [ ] **平台**：會變動的介面、格式限制和 Analytics 定義已重開官方頁面查核，記下查核日；不能確認當前資格時不保證所有帳號都看得到。
- [ ] **可讀性**：一篇有一個主問題；圖片有替代文字，影片有字幕；程式片段與圖表有足夠上下文。
- [ ] **互動**：標記他人與提問都與內容相關；不要求互讚、不用自動留言或誘餌句式換互動。
- [ ] **結尾**：讀者知道可帶走什麼；CTA 只在符合貼文目的時使用。

LinkedIn 的創作者分析是發文者私有資料，且頁面明示多項數字為估值。發布前不要用別人貼文的公開互動數填入自己的曝光或觸及。[LinkedIn Help：單篇貼文分析](https://www.linkedin.com/help/linkedin/answer/a523040)；[LinkedIn Help：發布貼文與可用選項](https://www.linkedin.com/help/linkedin/answer/a527227)

## 四、發布後回顧卡

```markdown
### [貼文 ID]｜七日回顧
- Permalink／發布時間（含時區）：
- 目標讀者／貼文目標：
- 觀察窗：發布後 24 小時／168 小時／其他（列出精確時數）
- 讀取時間與資料來源：單篇分析／彙總分析／其他
- 發布情境：主題、模式、媒介、外連、標籤、粉絲數或受眾規模（可取得時）
- Impressions：數值／未取得；查核時點：
- Members reached：數值／未取得；注意是估值且不重複計數：
- Reactions／comments／reposts／saves／sends：分項記錄
- 自訂每曝光互動率：(以上明列的互動合計) ÷ impressions =
- 外連訪問：次數／未取得；是否可能重複：
- 檔案瀏覽／新增追蹤／可確認的後續對話：分開記錄，不自動歸因
- 留言主題：只記可觀察內容，不猜測匿名讀者職稱或動機
- 混雜因素／資料缺口：
- 下一輪決策：保持／改一項／暫停；下一個假說：
- 技術 eval 結果（若貼文展示作品）：另開技術紀錄，不併入內容互動率
```

把「內容成效」和「技術 eval」分開保存。前者比較貼文與讀者行為，後者比較軟體版本、任務和成功條件；兩套分母不同。正式定義請參考 C09 的[成效與 eval 範例](09-measure-and-learn.md)。

## 六、簡短術語表

- **AOI**：自動光學檢查（Automated Optical Inspection），用相機與影像處理／模型檢查物件。
- **RD**：Research and Development，研發；職稱本身不代表特定技術能力。
- **LLM**：大型語言模型，依上下文產生或理解文字等輸出。
- **Agent**：能按任務狀態選工具並執行多步流程的模型系統，需明確權限和停止條件。
- **eval**：用固定任務、成功條件與評分方式檢查系統行為的評測。
- **trace**：一次執行的時間序紀錄，包含模型、工具呼叫、輸入輸出及交接等步驟。
- **CTA**：Call to Action，行動邀請；例如請讀者回覆一個與主題相關的實務問題。
- **ROI**：Region of Interest，感興趣區域；本書影像範例中指指定的檢查區域。
