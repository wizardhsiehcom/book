# 如何讀案例、讚數與作者歷程

本書要回答的是：**某位作者在某段職涯，如何向某群讀者發言；哪些做法適合自己的位置？** 因此每篇案例都需要同時看內容、作者、日期與互動，不能只看一個讚數。

## 把四種材料分清楚

| 材料 | 能學到什麼 | 尚需補什麼 |
|---|---|---|
| LinkedIn 原始貼文 | 開頭、結構、公開反應與留言 | 發布時的角色、受眾規模、同作者其他貼文 |
| 作者自己的職涯或寫作回顧 | 作者如何描述動機、轉折與成果 | 獨立核實、普通貼文及未成功嘗試 |
| 作者原站的技術文章 | 推理方式、實作材料、題材變化 | 對應的 LinkedIn 貼文與平台反應 |
| 大型平台研究 | 該樣本的格式、頻率與互動差異 | 工程角色、抽樣偏差與個人適用條件 |

以下是本書的研究與編輯規則，不是 LinkedIn 官方標準。

## 一篇貼文至少讀四欄

1. **當時的位置。** 作者是工程師、主管、顧問還是專職創作者？職位須有帶日期的資料；今天頁首顯示的職稱不能填回幾年前。
2. **主要任務。** 教一種方法、解釋一次決策、展示作品，還是邀請同行回答？文末有問句，不代表整篇主要模式就是提問。
3. **發表與觀察時間。** 原文只有「一年前」就保留相對日期。今天讀到的快取內容，未必是今天的數字。
4. **實際可見的反應。** Like 類反應、全部 reactions、留言與轉發分開記；看不到就是未取得。

題材、模式、媒介、目的也要分開。例如「Agent」是題材，「失敗復盤」是模式，「文字加流程圖」是媒介，「找同行檢查設計」是目的。若把四者混成一類，就無法知道讀者究竟對哪一部分有反應。

## 讚數能比較到哪裡

先比較同一作者、相近發布期間、相同數值定義與觀察條件的貼文。固定期間後才收樣本，保留普通與低互動案例；另挑的熱門教學案例不混入成效統計。

| 情況 | 合理的處理 |
|---|---|
| 介面只有全部 reactions | 寫「總反應」，不改稱純 Like 數 |
| 一篇有數字，另一篇看不到 | 留缺值，不把後者當成零互動 |
| 舊文是今日累積數，新文是七日數 | 分開展示，不作同窗高低排名 |
| 沒有曝光數 | 不計每曝光互動率 |
| 只有今日追蹤數 | 不計歷史追蹤者互動率 |
| 留言包括作者自己的回覆 | 不把留言數當獨立讀者人數 |
| 只有兩三篇目的取樣案例 | 拆解寫法，不推估模式勝率 |

資料足夠時，本書會先列樣本數、中位數與分布，再談差異。即使同作者比較也可能受到題材、事件、媒介與受眾成長影響；它描述關聯，不能單獨證明模式造成成效。

## 作者時間軸要有兩條線

一條是可驗證的職涯事件；另一條是帶日期的公開作品。兩者可以並排，不能自動接成因果。例如升任後較常寫架構，可能來自職責改變，也可能只是目前能讀到的文章選擇不同。

| 時段 | 角色及來源 | 可讀作品及平台 | 寫法觀察 | 未知 |
|---|---|---|---|---|
| 早期 | 有日期的本人履歷或當時文章 | 明列是部落格、團隊文章或 LinkedIn | 只描述已讀作品 | 職稱細節、其他文章、互動 |
| 中期 | 可驗證的轉職／升任事件 | 固定期間內可讀作品 | 與早期逐項比較 | 當時受眾規模 |
| 近期 | 最新可核對的角色 | 最近作品 | 區分個人與公司發言 | 是否能移植到讀者帳號 |

最早可讀的文章不一定是第一篇。作者今日的聲望也不能解釋早期貼文當時的反應。

實作案例見[同一作者的跨期寫法比較](longitudinal-comparison.md)。該輪按時間與題材目的取樣原站文章，適合教學分析，不適合估計模式頻率、互動排名或作者整體風格的變化。

## 建議的三種標記

- **案例支持：** 已讀案例確實呈現某種寫法，只支持此個案。
- **跨來源支持：** 多個獨立來源在可比範圍內支持同一觀察；同份報告的轉述只算一條來源鏈。
- **編輯推論：** 根據讀者工作與可提供的證據，提出值得嘗試的寫作選擇；尚未證明比較有效。

讀到角色適配表時，先找這些標記。你可以依編輯建議開始練習，同時用[自己的觀察紀錄](09-measure-and-learn.md)逐步修正。
