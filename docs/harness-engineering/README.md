# Coding Agent 的運作原理

## 從模型到可控的工作系統

這本書帶你看懂 coding agent 如何把一個要求變成檔案修改，以及你應憑什麼相信工作已完成。你會追蹤工具結果、理解記憶與權限，再為自己的任務選出足夠的設計。

本書寫給會讀簡單程式、但未設計過 agent 的讀者。例子使用 Python；不知道非同步程式或模型上下文也可以開始。必要術語會在首次出現時解釋，另附[術語表](glossary.md)供查閱。

## 全書只用一個容易驗證的錯誤起步

商店規定滿 1,000 元免運，程式卻用了 `>`，讓剛好 1,000 元仍被收費。這個自編案例會貫穿全書：先讀檔、再修改、檢查 999／1,000／1,001 元，最後交代結果。

錯誤很小，卻足以看見重要差別：模型提出修法不代表檔案已改；檔案已改不代表檢查通過；檢查通過也不代表執行環境足夠安全。每章處理其中一個問題。

## 從看懂流程，走到自行設計

全書分四個學習階段。第一次閱讀先走各章的基本案例，再讀進階段落；遇到陌生模式時，不必先背英文名稱。

| 階段 | 閱讀範圍 | 進入下一階段前，試著完成 |
|---|---|---|
| 入門：畫出責任 | 第 1–4 章 | 說明模型要求、工具結果與完成證據有何不同 |
| 核心：接好資料與動作 | 第 5–10 章 | 解釋編輯為何被拒，以及摘要丟掉什麼會影響下一步 |
| 進階：管理跨層邊界 | 第 11–13 章、[架構模式組合](advanced-patterns.md) | 說明權限、分工、記憶與擴充如何互相影響 |
| 綜合：用證據做選擇 | 第 14–16 章 | 提出兩種方案，設計反例，寫下採用與撤回條件 |

進階內容沿用免運案例，再加入中斷恢復、多人修改與擴充更新等條件。新增條件是本書的教學推導，不是論文已完成的產品測試。每次增加機制，都要回答：它解決哪個失敗，又帶來什麼新責任？

## 這本書如何使用論文

主要來源為 Paul Barbaste、Tristan Darrigol、Germain Vu、Tom Wiltberger 的 [*Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents — A Source-Code Study of Eleven Systems*，arXiv v1](https://arxiv.org/html/2609.00006v1)。原文以原始碼研究比較執行架構，本書依學習順序重新解釋，新增案例、練習與實驗。

產品名稱用來呈現設計差異。所有產品行為均以論文快照為界，不是今日功能保證，也不是效能排行榜。本書未獨立重做所有原始碼稽核；來源日期、授權及限制詳見[來源說明](sources.md)。

想回查原文，可用[論文對照索引](paper-map.md)。想看各研究案例的角色與版本，可用[系統查閱卡](system-cards.md)。

## 如何判斷自己真的讀懂

試著完成三件事：找出「批准」與「隔離」的差別；用自己的話講完一次工具呼叫；解釋為什麼一次成功的修改不能證明所有任務都可靠。這比記住產品有幾個工具，更接近本書的學習目標。

本文依 ISO 24495-1 的淺白語言原則編寫：內容貼近讀者任務、答案找得到、機制看得懂、方法用得上。這是編輯方法，不宣稱 ISO 認證。實際讀者試讀與自動檢查分開記錄於[驗證紀錄](verification.md)。
