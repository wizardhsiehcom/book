# 工業工程師（IE）

晶圓廠的工業工程師（Industrial Engineer, IE）從工廠系統層次回答三個問題：需要多少產能、瓶頸在哪裡、如何用最少資源穩定達成交期與成本目標。IE 不擁有單一製程 recipe，也不等於每天管理產線的 Manufacturing Engineer。

## IE 的核心模型

```mermaid
flowchart LR
    DEM["需求、產品組合與交期"] --> CAP["Capacity Model<br/>tool、chamber、dedication、uptime"]
    CAP --> BOT["Bottleneck／Constraint"]
    BOT --> WIP["WIP、Cycle Time、Queue"]
    WIP --> SCN["擴產、改善與情境模擬"]
    SCN --> DEC["人力、設備、產品組合與投資決策"]
    DEC --> CAP
```

半導體流程具有 re-entrant flow：同一 lot 會多次回到同類設備，還有 qualification、hold、rework、batch tool、dedication 與 product mix。只看單台設備 utilization，容易把局部滿載誤認成整廠最優。

## 核心工作

- 建立 short/long-term capacity model，換算 wafer starts、tool/chamber capacity、uptime 與產品組合。
- 分析 bottleneck、queue、WIP、cycle time、move 與 on-time delivery。
- 評估新機、擴產、設備改善、dedication 解除或產品組合變更的效益。
- 進行 discrete-event simulation、scenario/sensitivity analysis 與 constraint management。
- 規劃 headcount、shift、training/cross-skill 與 direct-labor productivity。
- 和 MFG、PE/PIE/EE、planning、finance、supply chain 與建廠團隊對齊假設。

## IE 與相鄰角色

| 角色 | 主要焦點 |
|---|---|
| IE／Capacity Planning | 模型、瓶頸、情境、資源與長短期產能 |
| Intelligent Manufacturing／MFG | 日常 fab control、dispatch、WIP、交期與人員運作 |
| CIM／MES | 生產執行系統、資料、流程規則與應用可靠度 |
| AMHS／Robotics | 晶圓載具實體搬運、自動化設備與控制系統 |

IE 會和 MES/dispatch 合作，但不應把 CIM、production control、MFG 與 AMHS 全部塞進 IE 一頁；相關職務另見[智慧製造、MFG、CIM 與 AMHS](18-smart-manufacturing.md)。

## 適合誰／工作型態

適合喜歡把複雜現場抽象成模型，又願意回現場檢查假設的人。工業工程、作業研究、統計、數學、管理科學、資工與製造背景常見。

多數 IE 以日班分析、規劃與專案為主；月／季 planning、產能 ramp 或重大 bottleneck 可能有高峰。是否輪班依職缺，不能因在 fab 工作就一概推定。

## 核心技能

- operations research、queueing、optimization、simulation 與 constraint theory。
- capacity、utilization、availability、WIP、cycle time 與 variability 的正確關係。
- SQL、Python、BI/visualization 與資料品質檢查。
- 能把模型假設、信賴範圍與 sensitivity 清楚呈現給營運決策者。
- 半導體 re-entrant flow、batching、qualification、dedication 與 dispatch 基礎。

## 職涯與轉換

可往 capacity/planning lead、manufacturing strategy、operations、supply chain、smart manufacturing、data/optimization、建廠規劃或管理職發展。轉 IME/MFG 要補 daily operation 與人員領導；轉 CIM 要補 software/system delivery。

## 面試準備

練習估算一組 tool 的 effective capacity，說明 uptime、PM、qualification、product mix、batch size 與 rework 如何改變答案。遇到 cycle time 上升，不要只回答「加機台」；先判斷 bottleneck、variability、WIP policy、dispatch 與非瓶頸資源的交互作用。
