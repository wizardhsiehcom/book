# 五台機台也用得上的 Linux 現場招式

**從 Windows 接 Linux 的小現場，學會資深工程師接手系統時的開發流與判斷。**

五台 client 裡只有一台不通，你不一定需要先懂完整的網路架構。你可能先需要一條確定好的線、一個固定的小檔，以及一個能說清楚「剛剛只換了什麼」的紀錄。

這本書收錄 11 個現場小動作：暫時只留一台、只改一次解析、用小檔替代整套服務、保存請求、故意讓路徑變慢、把 localhost 經隧道帶回來。每招都會帶你做到一個可觀察的差異，再解釋這個差異能把問題縮到哪裡。

你可能已經會讀 C++、build、下斷點，卻在接手機台系統時不知道先動哪裡：GUI 說連不上，到底先追程式、查設定，還是找網管？本書要補的是這段經驗。每次先說清楚眼前缺少哪個資訊，再選一個成本小、看得見結果的動作；拿到結果後，才決定下一步。

這些技巧也服務日常開發。固定輸入可以讓你少點十次畫面；小服務可以讓兩組人分開工作；經核准的隧道可以是固定的維護方式。用途不同，留下來的形式也不同，不必每招最後都變成正式平台。

## 先把網路現場接回你熟悉的程式

假設你接手一個 C++ 機台 client：使用者按下按鈕，程式組出要求、選目的地、送出，server 再驗證與處理。畫面的一句「失敗」把整串過程壓在一起。老手會先找能觀察或替換的交界，而不是同時修改整串。

| C++ 開發中可能做過的事 | 本書的現場動作 | 學到的判斷與限制 |
|---|---|---|
| 固定 argv、設定與同一個執行檔重跑 | 01 固定 client、線、孔與端點 | 建立可比較基線；換 client 仍可能連身份一起換 |
| 印出實際讀入的設定 | 02 看真正的 listener、03 看實際目的地 | 設定檔寫了什麼，與程序正在用什麼，要分開看 |
| 用固定回傳值暫代外部依賴 | 04 小檔服務 | 先解開開發阻塞；替身未涵蓋的功能仍要回原系統驗證 |
| 存下觸發 bug 的輸入，直接呼叫處理函式 | 06 保存 body 再送一次 | 縮短重跑；同一輸入仍需要可比較的初始狀態 |
| 暫加等待，觀察 timeout 與取消 | 09 延遲測試路徑 | 控制時序；網路延遲不等同某個 C++ 執行緒 sleep |

這些是工作方法的對照，不表示網路工具能直接驗證 C++ 記憶體、執行緒或業務邏輯。讀每章時，試著回答：「如果換成我的專案，我可以在哪個交界取得同樣的觀察？」

## 現在先拿到一個檔

第一次讀，直接到 [04｜把整個服務換成一個小檔案](04-tiny-server.md)。如果取檔失敗，回 [02｜敲埠與監聽](02-port-and-bind.md)；如果只有一台失敗，回 [01｜只留一台做對照](01-one-client.md)。

你不必照章序讀完才開始。遇到事故時按 [全書地圖](00-map.md) 的症狀查找；第一次學工作流，走 04→01→02→03→05→06，再選 07–11。先拿到小成果，再逐步理解它依靠哪些條件。

## 這本書預設你會什麼

你能開 Windows PowerShell，會用 SSH 登入 Linux，知道怎麼啟動與停止終端裡的程序。不要求熟悉封包分析，但你需要辨認哪個終端屬於哪台機器。本書每段命令都標出執行端；Linux 的 `sudo` 代表需要該機管理權限，Windows 的管理員 PowerShell 只在章節明示時使用。

教學基線是 Ubuntu 24.04 LTS 與 Windows 11，工具版本仍應以你的機器為準。這是寫作選用的環境，並非已重現的配套保證。沒有工具時先記下缺件，依組織既有方式安裝；本書不會把任意下載的二進位當成所有 Windows 都可用。

## 先辨認這幾個位置

- **server**：提供服務的 Linux，例用 `192.168.50.10`。
- **client**：呼叫服務的 Windows，C1–C5 例用 `.21`–`.25`。
- **埠（port）**：同一 IP 上用來區分網路服務的號碼；本書 HTTP 替身用 8080，重播接收器用 8081。
- **loopback**：`127.0.0.1`，永遠指「執行這個網路操作的那台電腦自己」。
- **監聽（listen／bind）**：server 程序在哪個位址與埠等待連線。

示例 IP 不是配址指令。先確認你現場的 LAN、VPN、Wi-Fi 沒有地址重疊，再把命令中的 IP 換成實際值；不要把正式機器直接改成書裡的位址。[01](01-one-client.md) 會教你記錄路徑，而不是靠猜。

## 怎麼判斷這招值得留下

每章都走同一個節奏：現場症狀 → 小招式 → 必要原理 → 親手實驗 → 結果解讀 → 失效反例 → 收尾與撤回。先保留基線 A，只改一項得到 B，再撤回看能否回到 A。結果沒有如預期發生，也是一個結果；不要為了讓書上的步驟成功而多改三個條件。

第一次讀到命令先停一下：預測哪個畫面或欄位會變，再執行一段並核對。每章末的判斷練習不是背旗標，而是練習拿結果決定下一個動作；展開參考思路前，先寫一句自己的理由。

成功敘述應像：「固定同一條線後，問題跟著 C2 走，所以先查 C2 及其設定。」它不應跳成：「C2 網卡壞了。」本書的捷徑用來縮小問題，最後仍要回原應用確認。

## 土招可以留下，但要知道留下的是什麼

手動開關 `test_mode` 的價值，在於先讓某條難進入的路徑可以反覆執行。真正要弄清楚的是：它繞過哪一段、是否仍走同一個處理核心、改完需不需要 rebuild、執行中的版本有沒有切回來。第 04 章的替身與第 06 章的重播，會從程式外部練習這種控制能力；本書不假定你的產品已經有測試入口。

小型 Python／uv script 也可以只是幫你保存、轉換與比對輸入的日常工具。第 06 章先用標準函式庫與 curl，讓資料流看得清楚；之後若要包成腳本，保留輸入檔、目標端點與回應的可追查性即可，不必為一次重跑先設計工具平台。

一次診斷留下結果與撤回紀錄；每天都用的命令留下參數與使用範圍；要交付給現場的做法則補上誰維護、怎麼停、失敗時怎麼辦。決定形式的依據是用途與成本，簡單做法本身不需要被淘汰。
