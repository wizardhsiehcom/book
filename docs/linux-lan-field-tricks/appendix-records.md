## 一次只改一項

```text
事件／日期：
操作者與 client：
server、服務、測試埠：

唯一改動：
```

示範寫法：「C1 換成 C2 後取檔失敗，換回 C1 成功；線、孔、server 未變。先查 C2 與其身份／路由，不足以判網卡故障。」這是**寫法示意，沒有宣稱真的測過**。

## 效能多加六個格子

第 07 章的每一組條件，各方向填三次 receiver 吞吐，記單位與接收端位置。把三次由小到大排序，中間值就是中位數；同時保留最小～最大，別只留下最好看的一次。

| 條件 | 方向 | 第 1 次 | 第 2 次 | 第 3 次 | 中位數／範圍 | CPU／link speed |
|---|---|---|---|---|---|---|
| C1 單台 | C1→Linux | 待填 | 待填 | 待填 | 待填 | 待填 |
| C1 單台 | Linux→C1 | 待填 | 待填 | 待填 | 待填 | 待填 |
| 五台同時，各台各列 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 |

兩端 CPU 觀察可用既有工作管理員與系統監視工具；記錄工具與採樣方式，不把某個瞬間百分比當整段平均。五台的總和也不是每台保證速率。

## 常見詞只記到夠用

| 詞 | 本書中的用途 |
|---|---|
| A/B/A | 基線、單項改動、撤回後再測 |
| prefix | 網路前綴長度，例如 /24；配合路由判斷目的地怎麼走 |
| bind | 程序選擇監聽位址；不是替網卡配 IP |
| payload | 這一層帶的資料；HTTP body 與 ICMP payload 不混稱 |
| pcap | 儲存封包的檔案；讀檔不會自動重送 |
| MTU／PMTU | 介面／路徑可承載的 IP 封包大小線索 |
| qdisc | Linux 流量排隊機制；第 09 章用 netem 改送出時序 |
| SMB dialect | 連線使用的 SMB 協定版本；有協商不等於讀檔授權 |
| fixture | 固定的測試輸入；第 06 章是去識別的 JSON |
