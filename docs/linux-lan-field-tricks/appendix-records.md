## 從現場招式接回 C++ 專案

不用先替整個專案設計測試框架。先選最耗時的一次重跑，記下它的入口、資料、狀態和結果，再判斷以下哪個小改動值得做：

| 現在的阻塞 | 可以先做的小動作 | 保留時要說清楚 |
|---|---|---|
| 每次都要人工點十個畫面 | 保存去識別輸入，增加直接呼叫測試入口 | 是否走同一處理核心、跳過哪些 GUI 前處理 |
| 外部服務還沒準備好 | 使用固定回應的替身 | 回應格式、支援範圍、如何切回原依賴 |
| 手動切 `test_mode` 才能開發 | 把目前模式顯示在啟動紀錄 | 是否需 rebuild、正在跑哪份 binary、交付前如何驗證 |
| 每次重跑都要轉資料和比結果 | 包成小型 Python／uv script | 輸入、輸出、依賴、端點，及會不會覆寫既有結果 |

這張表是遷移思路，不是本書已提供的產品功能。一次性程式可以保持小；要讓同事日常使用時，才補足參數檢查與使用說明。若要進入交付流程，驗證的對象應是實際交付的執行檔與設定，不能只看原始碼裡的開關已改回。

## 常見詞只記到夠用

| 詞 | 本書中的用途 |
|---|---|
| A/B/A | 基線、單項改動、撤回後再測 |
| prefix | 網路前綴長度，例如 /24；配合路由判斷目的地怎麼走 |
| bind | 程序選擇監聽位址；不是替網卡配 IP |
| payload | 這一層帶的資料；HTTP body 與 ICMP payload 不混稱 |
| pcap | 儲存封包的檔案；讀檔不會自動重送 |
| MTU／PMTU | 介面／路徑可承載的 IP 封包大小線索 |
| qdisc | Linux 流量排隊機制；第 09 章用 netem 改送出時序 |
| SMB dialect | 連線使用的 SMB 協定版本；有協商不等於讀檔授權 |
| fixture | 固定的測試輸入；第 06 章是去識別的 JSON |
